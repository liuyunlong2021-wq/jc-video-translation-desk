# 成片工作台

## 定位

成片工作台是视频翻译流程的第三页。它不负责重新判断角色参考音是否正确，也不反查配音工作台里的人工确认状态；它只消费第二页已经生成好的分组克隆配音成品，把目标语言人声按配音对白时间轴合成进无字幕成片母版，再烧录字幕和配音输出最终视频。

核心原则：

1. 第一页字幕工作台负责字幕、翻译、角色和配音分组。
2. 第二页配音工作台负责角色参考音、全局配音提示词、分组配音提示词和分组克隆配音。
3. 第三页成片工作台只负责成片处理：目标语言人声时间轴、原声分离、背景声混音、字幕配音烧录。
4. 成片工作台的可执行判断不再和参考音绑定强关联；只要有可用的完整分组克隆配音，就可以继续成片链路。

## 当前按钮链路

1. `更换视频`
2. `更换无字幕成片母版`
3. `生成成片`
4. `打开翻译成片`

推荐操作顺序仍然是：先准备无字幕成片母版，再点击 `生成成片`，最后打开或检查翻译成片。

但当前产品策略是：默认 UI 只保留一个主按钮。只要关键产物存在，就允许继续执行；如果某一步缺少可恢复产物，执行时再给出明确错误。

## 按钮后端逻辑

### 更换视频

入口：

- 前端按钮 key：`upload-video`
- 前端函数：`uploadTranslationVideo`
- 运行时状态：`VideoTranslationState.sourceVideoPath`

逻辑：

1. 用户选择或更换源视频。
2. 后端归档视频并写入源视频路径、音频存在状态和视频时长。
3. 如果更换的是源视频，会创建新的翻译状态，但保留源语言和目标语言设置。
4. 下游字幕、翻译、配音和成片产物按源视频变化重新开始。

### 更换无字幕成片母版

入口：

- 前端按钮 key：`upload-final-master`
- 前端函数：`uploadTranslationFinalMaster`
- Electron API：`selectVideoTranslationFinalMaster`
- 失效入口：`invalidateVideoTranslation(state, 'final-master-video')`

逻辑：

1. 用户上传或更换无字幕成片母版。
2. 后端将母版归档到当前 run 和 episode。
3. 写入：
   - `finalMasterVideoPath`
   - `finalMasterFingerprint`
4. 字幕和配音保持不变。
5. 只让成片音频处理下游失效：
   - `separationStatus`
   - `mixStatus`
   - `finalStatus`
   - `vocalPath`
   - `instrumentPath`
   - `mixedPath`
   - `finalVideoPath`
   - `originalVocalRemoved`

设计结论：

- 更换无字幕成片母版不应该影响第一页字幕结果。
- 更换无字幕成片母版不应该影响第二页已经生成好的分组克隆配音。

### 配音对白时间戳

入口：

- 前端按钮 key：`timestamp-target-dialogue`
- 前端函数：`timestampTranslationDialogue`
- 兜底函数：`ensureTranslationTargetVoice(state, true)`
- Electron API：`generateVideoTranslationDialogueTimestamps`
- 后端函数：`generateVideoTranslationDialogueTimestamps`

逻辑：

1. 读取当前完整分组克隆配音版本。
2. 校验分组克隆版本覆盖当前全部字幕 cue。
3. 对 grouped 配音版本，后端按每个配音块第一条字幕的起始时间放置音频。
4. 使用 FFmpeg 将所有分组音频按时间轴合成为一条目标语言人声轨。
5. 写入：
   - `dubDialogueTimestampPath`
   - `dubDialogueTimestampHash`
   - `targetVoicePath`
6. 对 grouped 版本，关键产物是：
   - `wiki/翻译/{episodeId}/成片/配音对白时间戳.json`
   - `episodes/{episodeId}/video-translate/{targetLanguage}/配音对白时间戳/{voiceVersionId}/目标语言人声.wav`

设计结论：

- 这一按钮不是重新生成配音，只是把第二页分组克隆音频按字幕时间轴摆好，形成目标语言人声轨。
- `targetVoicePath` 是后续合成目标语言音轨的直接输入。

### 生成成片

入口：

- 前端按钮 key：`generate-final-video`
- 前端函数：`generateTranslationFinalVideo`
- 内部复用函数：
  - `ensureTranslationTargetVoice`
  - `separateTranslationAudioCore`
  - `mixTranslationAudioCore`
  - `burnTranslationVideoCore`

逻辑：

1. 先检查当前是否已经有完整的目标语言人声轨；如果没有，就先补跑配音对白时间戳。
2. 再检查原人声和背景声是否已分离；没有就先分离。
3. 再检查目标语言音轨是否已混好；没有就先混音。
4. 再检查最终视频是否已生成；没有就执行烧录字幕和配音。
5. 每一步失败都停在当前步，并保留状态，方便下一次继续。

设计结论：

- 这是成片工作台默认的主按钮。
- 对普通用户来说，整个第三页只需要一次点击。
- 对排障来说，内部四步还都在，只是不再默认暴露。

### 分离原人声和背景声

入口：

- 前端按钮 key：`separate-source-audio`
- 前端函数：`separateTranslationAudio`
- Electron API：`separateSourceAudio`
- 后端 FFmpeg/音频处理函数：`separateSourceAudio`

逻辑：

1. 优先使用 `finalMasterVideoPath`，没有母版时使用 `sourceVideoPath`。
2. 后端分离原人声和背景声。
3. 写入：
   - `vocalPath`
   - `instrumentPath`
   - `separationStatus`
4. 清空旧的最终视频路径，避免旧成片继续被误认为可用。

设计结论：

- 这一步负责准备背景声、环境声和动作音。
- 它不负责判断目标语言配音是否正确。

### 合成目标语言音轨

入口：

- 前端按钮 key：`mix-background-audio`
- 按钮可用判断：`availableVideoTranslationActions`
- 前端函数：`mixTranslationAudio`
- 兜底函数：`ensureTranslationTargetVoice(state)`
- Electron API：`mixBackgroundAudio`
- 后端函数：`mixBackgroundAudio`

当前最终逻辑：

1. 只要 `separationStatus === 'ready'`，并且存在以下任意一项，就允许点击：
   - 已有 `targetVoicePath`
   - 或者已有覆盖当前全部字幕 cue 的完整 `grouped` 分组克隆配音版本
2. 点击后先执行 `ensureTranslationTargetVoice(state)`：
   - 如果 `targetVoicePath` 存在，直接使用。
   - 如果 `targetVoicePath` 不存在，但完整分组克隆版本存在，就自动补跑配音对白时间戳，重新生成目标语言人声轨。
3. 后端将：
   - 原人声轨 `vocalPath`
   - 背景轨 `instrumentPath`
   - 目标语言人声轨 `targetVoicePath`
   混合成目标语言成片音轨。
4. 写入：
   - `mixedPath`
   - `mixStatus`
5. 下游 `finalStatus` 标记为待重新生成。

设计结论：

- 这个按钮的职责非常单一：把已有分组克隆配音按时间轴合成进成片音轨。
- 它不再因为参考音换过、参考音确认状态变化、`voiceStatus` 变 stale 而被禁用。
- 它也不要求用户手动回到第二页重新证明“参考音绑定正确”。

### 烧录字幕和配音

入口：

- 前端按钮 key：`burn-subtitles-and-voice`
- 前端函数：`burnTranslationVideo`
- Electron API：`composeVideoTranslation`
- 后端函数：`composeVideoTranslation`

逻辑：

1. 读取：
   - `finalMasterVideoPath`，没有则使用 `sourceVideoPath`
   - `mixedPath`
   - `targetLanguage`
   - `finalScriptId`
   - `scriptHash`
   - `activeVoiceVersionId`
   - `dubDialogueTimestampHash`
2. 后端将目标语言混音轨和目标语言字幕烧录进视频。
3. 写入：
   - `finalVideoPath`
   - `finalStatus`
4. 生成后用户可以打开或导出成片。

设计结论：

- 烧录阶段只消费已经完成的混音和字幕结果。
- 参考音是否刚被重新选择，不应该反向阻断已生成成片音频的使用。

## 本次修复的问题

### 问题表现

用户在第二页配音工作台已经生成了完整分组克隆配音，也已经进入成片工作台；成片工作台左侧能看到已有配音结果和相关产物，但 `合成目标语言音轨` 仍然无法点击。

### 用户确认的产品诉求

成片工作台不应该关心参考音绑定、参考音是否重新点过、角色是否重新确认过。它只需要做一件事：把第二页生成好的分组克隆配音，按照配音对白时间轴合成进视频。

### 根因 1：按钮可用判断过度依赖 `voiceStatus`

旧逻辑：

- `合成目标语言音轨` 必须满足：
  - `separationStatus === 'ready'`
  - `dubDialogueTimestampHash` 存在
  - `voiceStatus === 'ready'`

问题：

- 用户更换或触碰参考音后，`voiceStatus` 可能变成 `stale`。
- 但真实的目标语言配音音频仍然存在。
- 于是按钮被错误禁用。

修复：

- 按钮可用条件改为看真实可用产物：
  - `separationStatus === 'ready'`
  - 并且 `targetVoicePath` 存在，或者存在完整 grouped 分组克隆版本。

### 根因 2：加载当前配音版本时误清成片路径

旧逻辑：

- `applyTranslationVoiceVersion` 每次加载当前配音版本时，都会先清空：
  - `targetVoicePath`
  - `dubDialogueTimestampPath`
  - `dubDialogueTimestampHash`
- 即使当前版本没有变化，也会清空。

问题：

- 用户重启 App、返回页面或刷新版本时，当前版本其实没变，但时间轴目标音轨路径被清掉。
- 这就是“明明配音都有了，重启后还是点不了”的直接原因。

修复：

- 只有用户真的切换到另一个配音版本时，才清空目标音轨路径和时间轴。
- 同一个当前版本重新加载时，保留现有 `targetVoicePath` 和 `dubDialogueTimestampHash`。

### 根因 3：旧状态已经丢路径时缺少自动恢复

问题：

- 如果旧逻辑已经把 `targetVoicePath` 清掉，新逻辑只是不再继续清，并不能凭空恢复被删的状态字段。

修复：

- `mixTranslationAudio` 点击后先调用 `ensureTranslationTargetVoice(state)`。
- 如果 `targetVoicePath` 缺失，但完整 grouped 分组克隆版本存在，就自动调用 `generateVideoTranslationDialogueTimestamps` 补回目标语言人声轨。
- 用户不需要回到第二页重新操作。

### 根因 4：普通成片页声音选择仍绑定输出语言

问题：

- 普通成片操作里曾按 `outputLanguage` 选择 `voicePath` 或 `englishVoicePath`。
- 如果当前输出语言状态和实际已有声音路径不一致，按钮可能被禁用。

修复：

- 成片页声音选择改为使用已有可用声音：
  - `voicePath || englishVoicePath`

### 本次简化：四步合一

问题：

- `配音对白时间戳`、`分离原人声和背景声`、`合成目标语言音轨`、`烧录字幕和配音` 在默认 UI 中过于碎。

修复：

- 默认入口收口为一个按钮：`生成成片`。
- 一键内部自动串联四步，保留步骤级错误和状态回写。

结果：

- 普通用户只需要点一次。
- 排障时仍然可以通过内部函数和状态查看每一步是否成功。

## 当前最终状态

- `生成成片` 是第三页默认主按钮。
- `配音对白时间戳`、`分离原人声和背景声`、`合成目标语言音轨`、`烧录字幕和配音` 都收进内部流水线，不再作为默认主按钮暴露。
- 当前 grouped 分组克隆版本完整覆盖全部字幕 cue 时，就可以一路生成成片。
- 如果 `targetVoicePath` 缺失，点击 `生成成片` 会自动补配音对白时间轴。
- 同一个分组克隆版本重新加载，不再清空已生成的目标语言人声轨和时间轴。
