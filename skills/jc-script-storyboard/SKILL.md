# 文稿 -> 大师导演式单镜头方案

继承项目总监已经锁定的导演、参考作品、国别、媒介和视觉总纲来拍。项目目标时长、已知配音时长、节奏档位和参考镜头数提供边界；叙事节拍与既定导演方法决定最终镜头数量、镜头语言和每镜时间预算。

每个输出镜头仍对应一张首帧和一条 Veo 3.1 单镜头视频。剪辑意义上的蒙太奇必须拆成多个独立输出镜头，不能藏在一条视频里切镜。

## 输入

- `script`：已确认文稿，保持原文；
- `targetDuration`：项目目标时长；没有本集配音时使用它规划无对白动作和整集时间轴；
- `actualDuration`：可选，已经生成的本集对白真实时长；存在时优先用于有对白镜头，不得覆盖无对白动作的时间预算；
- `ratio`：`9:16` 或 `16:9`；
- `shotPace`：`auto`、`slow`、`medium` 或 `fast`；
- `referenceShotCount`：可选的参考镜头数；
- `validationError`：上一次输出的合同错误，修正合同错误时仍保留导演对镜头数的决定权；
- `style`：已选视觉风格名称与固定提示词；
- `projectDirector`：已确认项目总监方案，导演、作品、国别、媒介、视觉总纲和资产 ID 都是只读事实；

## 1. 继承项目总监

不得重新推荐、选择或替换导演。读取 `projectDirector.direction` 和 `wiki/项目/项目总监.md`，原样继承具体导演、代表作和视觉总纲。

1. 判断当前文稿的戏型和节拍，但不得用判断结果改掉既定导演。
2. 从该导演的既定代表作中选择与当前节拍相似的具体场景或段落，提取 `rhythmArchive`：切镜密度、景别顺序、机位、运动、构图、动作衔接、光影和声音处理。
3. 把参考技法迁移到当前文稿，不复制原作人物、情节或标志性画面，也不声称原导演参与创作。
4. 导演总览的“导演身份”必须同时包含 `projectDirector.direction.director` 和 `projectDirector.direction.referenceWork`，不得使用新的创作者名称。

## 2. 让导演决定镜头数

1. 先按完整短句、信息点、动作变化、情绪转折和视觉对象变化划分 `storyBeats`。字数只是弱参考。
2. `shotPace` 表示剪辑倾向：慢节奏多留白和长镜；中节奏以清晰推进为主；快节奏允许短句一镜、反应特写、插入镜头和连续证据蒙太奇。
   - 输入为 `auto` 时，必须根据文稿信息密度、动作与情绪变化、目标时长，在 `slow`、`medium`、`fast` 中明确选择一个，并原样写入导演总览的 `- 最终节奏：`；禁止写 `auto`、中文别名或省略该字段。
   - 输入为固定档位时，最终节奏必须与输入完全一致。
3. 先标记每个节拍是 `onscreen`（画面内角色说话）、`voiceover`（旁白或画外音）还是 `none`（无对白动作/反应/环境）。有声节拍记录稳定 `speakerId` 和原文；动作节拍必须给出可观察的开始、发展、结束，不得因为没有台词而省略时间。
4. 参考镜头数只回答“大约多密”，不回答“必须多少”。没有输入参考值时，可用以下平均时长估出起点：`slow=7` 秒、`medium=4.5` 秒、`fast=2.5` 秒。
5. 导演为每个 `storyBeat` 选择处理方式：
   - `hold`：一个有表演、调度或揭示过程的长镜；
   - `progression`：一个标准推进镜头；
   - `montage`：为了压缩信息或制造爆发，拆成 2-5 个独立短镜头。
6. 汇总后得到 `finalShotCount`。它可以低于或高于参考值；如果明显偏离，先复查是否漏拍信息、把蒙太奇塞进单镜，或为了凑数制造空镜。确有导演理由时保留，并在 `shotCountRationale` 中说明。
7. 不得因为输入写了 10、16 或其他数字，就机械输出完全相同的数量；也不得在快节奏参考约 16 镜时无理由缩成 5 镜。

## 3. 设计开头、发展与结尾

1. 第一镜为 `hook`：第一秒直接呈现主体、结果、冲突、异常动作或强问题，不用无信息空镜和慢淡入。
2. 中段为 `development`：每镜只承担一个清楚的视觉任务。用景别变化、动作方向、视线、遮挡、焦点转移或运动完成镜间衔接。
3. 最后一镜为 `payoff`：回答开头的问题或落定核心收益，给出稳定可读的尾帧，不突然增加新信息。
4. 具体导演参考必须影响实际镜头：每个镜头的景别、机位、运动或时长至少有一项能追溯到 `rhythmArchive`，不能只把导演名字写在标题里。

## 4. 单镜头生成合同

1. `shots[].script` 顺序拼接后与输入文稿逐字一致，不重复、不遗漏、不润色；无对白动作镜头仍引用原稿中的动作/叙事内容，“无对白”只写在声音与时间轴字段，不得伪造台词。
2. 每镜 `playDuration` 大于 0 且不超过 8 秒；总和等于本次分镜时间轴总时长。已有 `actualDuration` 时，有对白镜头优先服从真实对白时长；没有时使用 `targetDuration` 做规划，并把估算标记为待配音确认。
3. `generationDuration` 取不短于 `playDuration` 的最小值 `4`、`6` 或 `8`；不足 4 秒的镜头生成 4 秒后在合成阶段裁剪。
4. 每镜只有一个主要场景、一个主要构图和一段连续动作。允许推、拉、摇、移、跟拍、环绕、手持和焦点转移；镜内不切镜、不转场、不分屏。
5. 每镜写清 `startState -> actionProgression -> endState`。蒙太奇中的每一个短镜也必须是独立可生成的连续镜头。
6. 相邻镜头通过主体位置、动作方向、视线、光线、色彩和参考资产特征保持连续；每镜独立重复必要特征。
7. 视频默认无旁白、无背景音乐；只保留必要的自然环境音和动作音效。只有输入文稿明确存在台词时，才写对白动作和口型配合，不得擅自添加对白。
8. 有声镜头必须记录：声音类型、稳定说话者 ID、显示名称、对应原文、声音情绪、情绪强度、语速、停顿/重音、对白时长（真实值或估算值）和口型/动作配合要求。画面内说话使用角色资产 `entityId`；旁白没有视觉资产时使用稳定 `narrator-*` ID。
9. 一个镜头只允许一个连续说话轮次和一个 `speakerId`。说话者切换必须拆镜；不得在同镜设计多人重叠对白。
10. 无对白动作镜头必须记录：动作节拍、目标时长和是否需要环境音/动作音；不得等待配音来决定该镜头是否存在。
11. 每镜用 `assetKeys` 引用本次 `assetPlan` 中确实出镜的资产；一个镜头最多引用一个主要场景。

## 5. 建立资产计划

App 已在输入中提供已确认的角色、场景和道具资产。先完成全部镜头，再把每镜绑定到确实出镜的现有资产。不得创建新资产、改写资产 ID 或输出资产文件。

- 镜头资产链接必须原样使用现有资产 Markdown 的 `entityId`；
- 同一实体在不同镜头、角度和动作下仍引用同一个 ID；
- 若文稿确实需要但现有资产中不存在关键角色、场景或道具，停止写入并说明缺失资产；
- 普通背景杂物不建立或绑定资产；
- 每镜最多绑定一个主要场景。

## 输出：直接写入项目 Wiki

不要输出 JSON。App 已在用户消息中附上确认文稿和已有资产，不要再逐文件调用 `list` 或 `read`。

先在内部完成整套方案，再使用一次 `write_batch` 工具提交全部分镜 Markdown。禁止一个镜头调用一次工具，禁止使用不存在的 `write` 或 `edit` 工具。批量写完后再简短说明完成数量：

1. `wiki/分镜/导演总览.md`；
2. 每镜一个 `wiki/分镜/镜头/shot-NNN.md`。

导演总览必须包含这些固定字段：

```markdown
# 导演分镜总览

## 创作依据

- 项目总监：[[../项目/项目总监]]
- 导演身份：原样写入项目总监确定的导演 + 具体代表作
- 参考场景：具体场景及适配理由
- 节奏档案：切镜、景别、机位、运动、构图与光影规律
- 分发意图：首秒钩子、信息推进与结尾回收

## 全局视觉锚点

完整视觉锚点正文

## 节奏方案

- 最终节奏：fast
- 参考镜头数：10
- 最终镜头数：14
- 数量理由：增减镜头的导演理由

## 资产清单

- [[资产/角色/character-host|主持人]]

## 镜头目录

- [[分镜/镜头/shot-001|镜头 01]]
```

单镜文件必须包含以下固定字段和标题：

```markdown
---
entityType: shot
entityId: shot-001
shotIndex: 1
status: draft
managedBy: short-video-factory
---

# 镜头 01

## 镜头参数

- 叙事作用：开场钩子
- 镜头职责：hook
- 剪辑处理：progression
- 播放时长：2.5 秒
- 生成时长：4 秒
- 景别：近景
- 机位：略低机位
- 运镜：快速推近后稳定
- 资产：[[资产/角色/character-host|主持人]]、[[资产/场景/scene-office|办公室]]

## 对应原文

本镜对应的原始剧本文字（对白或动作叙事，保持原文）

## 声音与时间轴

- 类型：画面内对白 / 旁白或画外音 / 无对白动作
- 说话者ID：character-host；无对白镜头填写“无”
- 对白角色：小红；无对白镜头填写“无”
- 对应台词：本镜对应对白；无对白镜头填写“无”
- 声音情绪：克制的惊讶
- 情绪强度：中
- 语速：中速，关键词略放慢
- 停顿/重音：说话前短停顿，重音落在“终于”
- 对白时长：2.1 秒（真实值；未配音时标记为估算值）
- 动作节拍：起始状态 → 连续动作 → 结束状态
- 环境音/动作音：门响、脚步或“无”
- 口型/动作配合：需要口型同步；无对白镜头填写“不适用”

## 起始状态

首帧可见状态

## 动作过程

连续动作过程

## 结束状态

结束时可读状态

## 画面提示词

可直接交给生图模型的单幅首帧提示词

## 视频提示词

可直接交给视频模型的提示词；必须写明单一连续镜头、无切镜、无转场、无背景音乐，并严格同步“声音与时间轴”：

- 画面内对白：逐字写入 `角色 <说话者ID> 自然说出：“<对应台词>”`，同时写明情绪、语速、动作和口型同步；不得只写“自然口型”。
- 旁白或画外音：逐字写入 `后期旁白：“<对应台词>”；本次视频模型不得生成人声`，只让视频模型生成画面、环境和动作。
- 无对白动作：明确写入 `无对白、无旁白`，不得补写台词。
```

输出前检查：文稿完整、总时长一致、每镜可单独生成、声音字段与视频提示词逐字一致、第一镜是钩子、最后一镜完成回收、资产引用完整、最终镜头数等于实际文件数。不得只在最终回复中粘贴 Markdown，必须在一次 `write_batch` 调用中写入全部真实文件。
