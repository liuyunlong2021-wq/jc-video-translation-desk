# 文稿 -> 大师导演式单镜头方案

把文稿交给一位有明确作品依据的导演来拍。风格、配音时长、节奏档位和参考镜头数提供边界；叙事节拍与导演方法决定最终镜头数量和镜头语言。

每个输出镜头仍对应一张首帧和一条 Veo 3.1 单镜头视频。剪辑意义上的蒙太奇必须拆成多个独立输出镜头，不能藏在一条视频里切镜。

## 输入

- `script`：已确认文稿，保持原文；
- `actualDuration`：真实配音时长；
- `ratio`：`9:16` 或 `16:9`；
- `shotPace`：`auto`、`slow`、`medium` 或 `fast`；
- `referenceShotCount`：可选的参考镜头数；
- `validationError`：上一次输出的合同错误，修正合同错误时仍保留导演对镜头数的决定权；
- `style`：已选视觉风格名称与固定提示词；

## 1. 锁定大师、作品与场景

这是本 Skill 的核心，不要只写“商业片导演”“动画导演”“电影感导演”等空身份。

1. 先判断媒介与戏型：真人、二维动画、三维动画、定格动画、水墨等；再判断当前文稿属于冲突钩子、功能揭示、流程讲解、证据蒙太奇、情绪转折或结果回收中的哪些节拍。
2. 选择一位与媒介和戏型真正匹配、拥有充分公开拉片与评论资料的世界知名导演、动画导演或核心主创。
3. 锁定该创作者的一部具体代表作，并找到其中与当前节拍相似的具体场景或段落。优先使用“某作品中某场戏如何处理某类信息”，而不是只借名字或表面美术。
4. 从训练数据中的影评、导演访谈、电影书籍和拉片资料，内部提取该场景的 `rhythmArchive`：切镜密度、长短镜组合、景别顺序、机位、运动、构图、动作衔接、光影和声音处理。
5. 把参考技法迁移到当前文稿，不复制原作人物、情节或标志性画面，也不声称原导演参与创作。

用以下作品作为检索锚点而不是封闭名单：真人可从大卫·芬奇《社交网络》、奉俊昊《寄生虫》、王家卫《花样年华》、韦斯·安德森《布达佩斯大饭店》等具体场景出发；定格动画可从亨利·塞利克《鬼妈妈》、韦斯·安德森《了不起的狐狸爸爸》、尼克·帕克《超级无敌掌门狗》等出发；二维动画可从宫崎骏《千与千寻》、今敏《红辣椒》、特伟《山水情》、万籁鸣《大闹天宫》等出发；写实 CG 可从安德鲁·斯坦顿《机器人总动员》、布拉德·伯德《超人总动员》等出发。最终选择必须服从当前媒介和戏型；若训练知识中有更准确的世界知名作品，就选择更准确者。

## 2. 让导演决定镜头数

1. 先按完整短句、信息点、动作变化、情绪转折和视觉对象变化划分 `storyBeats`。字数只是弱参考。
2. `shotPace` 表示剪辑倾向：慢节奏多留白和长镜；中节奏以清晰推进为主；快节奏允许短句一镜、反应特写、插入镜头和连续证据蒙太奇。
3. 参考镜头数只回答“大约多密”，不回答“必须多少”。没有输入参考值时，可用以下平均时长估出起点：`slow=7` 秒、`medium=4.5` 秒、`fast=2.5` 秒。
4. 导演为每个 `storyBeat` 选择处理方式：
   - `hold`：一个有表演、调度或揭示过程的长镜；
   - `progression`：一个标准推进镜头；
   - `montage`：为了压缩信息或制造爆发，拆成 2-5 个独立短镜头。
5. 汇总后得到 `finalShotCount`。它可以低于或高于参考值；如果明显偏离，先复查是否漏拍信息、把蒙太奇塞进单镜，或为了凑数制造空镜。确有导演理由时保留，并在 `shotCountRationale` 中说明。
6. 不得因为输入写了 10、16 或其他数字，就机械输出完全相同的数量；也不得在快节奏参考约 16 镜时无理由缩成 5 镜。

## 3. 设计开头、发展与结尾

1. 第一镜为 `hook`：第一秒直接呈现主体、结果、冲突、异常动作或强问题，不用无信息空镜和慢淡入。
2. 中段为 `development`：每镜只承担一个清楚的视觉任务。用景别变化、动作方向、视线、遮挡、焦点转移或运动完成镜间衔接。
3. 最后一镜为 `payoff`：回答开头的问题或落定核心收益，给出稳定可读的尾帧，不突然增加新信息。
4. 具体导演参考必须影响实际镜头：每个镜头的景别、机位、运动或时长至少有一项能追溯到 `rhythmArchive`，不能只把导演名字写在标题里。

## 4. 单镜头生成合同

1. `shots[].script` 顺序拼接后与输入文稿逐字一致，不重复、不遗漏、不润色。
2. 每镜 `playDuration` 大于 0 且不超过 8 秒；总和等于 `actualDuration`。快节奏短镜可以小于 4 秒。
3. `generationDuration` 取不短于 `playDuration` 的最小值 `4`、`6` 或 `8`；不足 4 秒的镜头生成 4 秒后在合成阶段裁剪。
4. 每镜只有一个主要场景、一个主要构图和一段连续动作。允许推、拉、摇、移、跟拍、环绕、手持和焦点转移；镜内不切镜、不转场、不分屏。
5. 每镜写清 `startState -> actionProgression -> endState`。蒙太奇中的每一个短镜也必须是独立可生成的连续镜头。
6. 相邻镜头通过主体位置、动作方向、视线、光线、色彩和参考资产特征保持连续；每镜独立重复必要特征。
7. 视频默认无旁白、无背景音乐；只保留必要的自然环境音和动作音效。不要擅自添加对白。
8. 每镜用 `assetKeys` 引用本次 `assetPlan` 中确实出镜的资产；一个镜头最多引用一个主要场景。

## 5. 建立资产计划

App 已在输入中提供已确认的角色、场景和道具资产。先完成全部镜头，再把每镜绑定到确实出镜的现有资产。不得创建新资产、改写资产 ID 或输出资产文件。

- 镜头资产链接必须原样使用现有资产 Markdown 的 `entityId`；
- 同一实体在不同镜头、角度和动作下仍引用同一个 ID；
- 若文稿确实需要但现有资产中不存在关键角色、场景或道具，停止写入并说明缺失资产；
- 普通背景杂物不建立或绑定资产；
- 每镜最多绑定一个主要场景。

## 输出：直接写入项目 Wiki

不要输出 JSON。App 已在用户消息中附上确认文稿和已有资产，不要再逐文件调用 `list` 或 `read`。

先在内部完成整套方案，再使用一次 `write_batch` 工具提交全部分镜 Markdown。禁止一个镜头调用一次工具，禁止使用不存在的 `write` 或 `edit` 工具。批量写完后再简短说明完成数量：

1. `wiki/分镜/导演总览.md`；
2. 每镜一个 `wiki/分镜/镜头/shot-NNN.md`。

导演总览必须包含这些固定字段：

```markdown
# 导演分镜总览

## 创作依据

- 导演身份：创作者 + 具体代表作
- 参考场景：具体场景及适配理由
- 节奏档案：切镜、景别、机位、运动、构图与光影规律
- 分发意图：首秒钩子、信息推进与结尾回收

## 全局视觉锚点

完整视觉锚点正文

## 节奏方案

- 最终节奏：fast
- 参考镜头数：10
- 最终镜头数：14
- 数量理由：增减镜头的导演理由

## 资产清单

- [[资产/角色/character-host|主持人]]

## 镜头目录

- [[分镜/镜头/shot-001|镜头 01]]
```

单镜文件必须包含以下固定字段和标题：

```markdown
---
entityType: shot
entityId: shot-001
shotIndex: 1
status: draft
managedBy: short-video-factory
---

# 镜头 01

## 镜头参数

- 叙事作用：开场钩子
- 镜头职责：hook
- 剪辑处理：progression
- 播放时长：2.5 秒
- 生成时长：4 秒
- 景别：近景
- 机位：略低机位
- 运镜：快速推近后稳定
- 资产：[[资产/角色/character-host|主持人]]、[[资产/场景/scene-office|办公室]]

## 对应台词

本镜对应原文

## 起始状态

首帧可见状态

## 动作过程

连续动作过程

## 结束状态

结束时可读状态

## 画面提示词

可直接交给生图模型的单幅首帧提示词

## 视频提示词

可直接交给视频模型的提示词；必须写明单一连续镜头、无切镜、无转场、无背景音乐。
```

输出前检查：文稿完整、总时长一致、每镜可单独生成、第一镜是钩子、最后一镜完成回收、资产引用完整、最终镜头数等于实际文件数。不得只在最终回复中粘贴 Markdown，必须在一次 `write_batch` 调用中写入全部真实文件。
