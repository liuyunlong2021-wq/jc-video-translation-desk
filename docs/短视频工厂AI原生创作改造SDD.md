# 单核心参考资产的单镜头媒体编排工作流 SDD

> 日期：2026-07-30
> 状态：MVP 已实施
> 目标版本：2.1 MVP
> 依据：当前短视频工厂代码、韭菜盒子原生媒体编排能力及 `jiucaihezi-app` 的 creation runtime、media task store、CreationPanel 和 media-generation 实现
> 实施证据：Phase 0 至 Phase 2 已在提交 `57c48b6` 中落地，并完成一次构建版最终视频合成人工验证；当前风险见 [项目 Wiki 当前状态](wiki/hot.md)
> 界面演进：本文第 5.1、5.4、5.5 节的中栏与右栏职责已由 `docs/三栏创作工作区与参考资产演进SDD.md` 取代；媒体 API、任务状态、持久化和合成合同继续有效。

## 1. 一句话目标

用户输入任意旁白型短视频诉求，可选上传一个需跨镜头稳定的核心参考资产，确认文稿和全局视觉风格后，逐阶段生成配音、单幅分镜图、单镜头视频和成片；每一步产物都进入可恢复的托管素材库。

## 2. 已确认产品决策

1. 底层按生成约束分类，不按产品营销、技术科普、历史讲解等用途分裂工作流。
2. MVP 主路线是“单核心参考资产”：每个 run 最多管理一个需跨镜头稳定的主体；无参考图是可选退路，不是产品主卖点。
3. 核心参考资产可以是产品、设备、Logo、食品、服装、建筑、界面或其他可视主体；不限定行业。
4. 角色、场景、多道具和多主体的跨镜头连续性不进入 MVP。
5. 文稿模型、图片模型、视频模型和声音模型由产品固定，用户只配置韭菜盒子 API Key。
6. 用户选择画面比例、目标成片时长和全局视觉风格；风格与文稿用途解耦，全片只确认一次。
7. `jc-script-storyboard` 按真实配音时长生成逐镜头方案；每段只有一张首帧图、一个连续镜头和一条 Veo 视频。
8. Veo 付费任务的生成时长只能是 `4 / 6 / 8` 秒；最终播放时长可按真实配音裁剪，两者必须分字段保存。
9. 声音设计应用只接收文稿和五项声音提示词，没有语言字段。
10. 最终合成使用统一 Qwen TTS 配音，MVP 不添加背景音乐、不保留 Veo 原音轨，不做多角色对白和口型同步。
11. 核心参考图、音频、分镜图、视频片段和成片全部保存到应用托管目录，并以紧凑素材库展示。
12. 不做一键全自动；每个付费阶段都必须由用户明确点击。

## 3. 固定能力表

| 能力 | 产品固定值 | 说明 |
| --- | --- | --- |
| API Origin | `https://api.jiucaihezi.studio` | 媒体接口内部根地址 |
| OpenAI Base URL | `https://api.jiucaihezi.studio/v1` | 文稿生成固定地址，只读显示 |
| 文稿模型 | `gemini-3.6-flash` | 内部常量，不在 UI 暴露 |
| 图片模型 | `gpt-image-2` | 无参考图走 `/v1/images/generations`，有参考图走 `/v1/images/edits` multipart |
| 视频模型 | `newapi/zx/veo-3.1-generate-preview` | 上游模型 `veo-3.1-generate-preview`，单张首帧图生单镜头视频，`4/6/8` 秒、`720p` |
| 声音模型 | `runninghub/aiapp/rh-aiapp-voice-design` | 上游模型 `rh-aiapp-voice-design`，Qwen TTS 声音设计应用 |
| 输出视频 | H.264/AAC、30 fps | 尺寸由用户选择的比例映射 |

不得把 OpenAI Base URL 直接用于媒体 endpoint 拼接。媒体请求必须使用 API Origin，否则会产生 `/v1/v1/...` 重复路径。

## 4. 第一版用户流程

```text
填写 API Key、选择画面比例和目标时长
  -> 选择全局视觉风格
  -> 可选上传一张核心参考图
  -> 输入视频诉求并生成可编辑文稿
  -> 用户确认文稿
  -> 点击“生成声音方案”并检查五项声音提示词
  -> 点击“生成配音”
  -> 配音进入素材库，应用读取真实时长
  -> 点击“转分镜”
  -> jc-script-storyboard 生成逐镜头视频方案
  -> jc-gpt-image 根据全局风格和核心参考资产生成每镜首帧提示词
  -> 用户在右栏逐镜检查并编辑分镜方案
  -> 点击“生成分镜图”
  -> 应用生成每镜独立分镜图，图片进入素材库
  -> 点击“生成视频”
  -> 每张分镜图生成一条 Veo 3.1 单镜头视频，视频进入素材库
  -> 点击“合成视频”
  -> FFmpeg 丢弃所有原视频音轨、顺序拼接并覆盖统一配音
  -> 成片进入素材库并可导出
```

每个阶段按钮都是该阶段的付费确认。当前阶段成功后才解锁下一阶段；用户可以先试听配音、查看全部单镜头分镜图、预览全部视频，再决定是否继续产生下一笔费用。

## 5. 界面改造

### 5.1 总体布局

保留当前三栏结构，但改变职责：

| 区域 | 新职责 |
| --- | --- |
| 左栏 | 用户诉求、文稿、比例、目标时长、全局风格和核心参考图 |
| 中栏 | 分类素材浏览器，紧凑展示参考图、配音、分镜图、视频和成片 |
| 右栏 | 上半区编辑声音方案并生成配音；下半区编辑分镜方案并执行图片、视频和合成阶段 |

### 5.2 API 配置弹窗

删除当前模型名输入框和可编辑 API URL 输入框。弹窗只保留：

- API 地址：只读文本 `https://api.jiucaihezi.studio/v1`；
- API Key：密码输入框，支持显示/隐藏；
- “前往获取”按钮：通过 Electron 打开 `https://api.jiucaihezi.studio/keys`；
- “测试连接”按钮：使用 Bearer Key 请求模型目录或执行最小文本请求；
- “保存”按钮。

外链 IPC 必须只允许 `https:`，并对“前往获取”使用固定 URL；不能继续接受渲染进程传入的任意地址后直接 `shell.openExternal()`。

### 5.3 左栏文稿状态

文稿存在四个状态：

```text
empty -> generating -> editable -> approved
```

- 用户可直接编辑模型输出。
- 点击“确认文稿”时冻结文稿快照和哈希。
- 生成开始后再次编辑文稿，不得偷偷改变在途任务；应提示重新开始一个生成任务。
- 画面比例第一版只保留 GPT Image 2 与 Veo 3.1 共同支持的 `9:16` 和 `16:9`。
- 目标成片时长提供“约 10 秒、约 15 秒、约 30 秒”；这是文稿与成片目标，不是单次 Veo 请求时长。
- 全局风格使用分段控件或菜单选择，不与产品营销、科普等用途绑定。
- 核心参考图使用上传按钮和缩略图；可移除、替换，不显示本地路径文本框。
- 不提供模型选择器。

### 5.4 中栏素材库

删除“选择素材文件夹”和“刷新素材”控件。中栏只保留一个纵向滚动容器，顶部用分段控件切换：

- `全部`
- `参考图`
- `配音`
- `分镜图`
- `视频`
- `成片`

紧凑展示规则：

- 图片和视频使用固定比例缩略图网格，不在列表里展开大预览；
- 配音显示为单行紧凑播放条，只常驻播放、时长和状态；
- 缩略项常驻素材类型、镜头编号、任务状态和视频时长；
- 点击缩略项打开模态弹窗，弹窗内才显示大图或视频、完整提示词、引用资产、错误信息和重试操作；
- 成片可在“全部”中置顶，仍使用缩略展示，点击后弹窗播放、定位或导出；
- 提示词是素材元数据，不作为独立素材。

弹窗必须支持点击关闭、`Esc` 关闭、焦点限定和键盘操作；不用只有鼠标悬停才能发现的操作。

### 5.5 右栏

删除语言、性别、声音、语速和试听文本控件。右栏使用上下两个独立区域，两区内部各自滚动，操作按钮不随长文本滚出可视区域：

- 上半区“声音方案”：可编辑五项声音提示词，并放置“生成声音方案”“生成配音”按钮；
- 下半区“分镜方案”：展示全局一致性和逐镜列表，每镜显示时间、对应文稿、分镜图提示词和视频提示词，两个提示词可编辑；
- 下半区操作栏放置“转分镜”“生成分镜图”“生成视频”“合成视频”；
- API Key 状态、阶段进度和错误提示保留在右栏，但不得挤占方案的独立滚动空间；
- 中栏只展示真实媒体结果，不承担分镜文档的主要审阅和编辑职责。

按钮规则：

| 按钮 | 解锁条件 | 成功结果 |
| --- | --- | --- |
| 生成声音方案 | 文稿已确认 | 右栏显示五项声音提示词 |
| 生成配音 | 声音方案已生成 | 音频进入中栏素材库 |
| 转分镜 | 配音已生成并测得时长 | 逐镜头计划进入右栏，等待用户检查和编辑 |
| 生成分镜图 | 分镜方案已生成 | 全部单镜头分镜图进入中栏 |
| 生成视频 | 所有单镜头分镜图生成成功 | 全部视频片段进入中栏 |
| 合成视频 | 所有视频片段和配音可用 | 最终成片进入中栏 |

按钮始终保留但未满足条件时禁用并说明原因。阶段完成后允许重新生成；重新生成引起的下游失效遵循第 8.3 节。

第一版删除 BGM 文件夹配置和自动批量生成开关。

## 6. 文稿与内置 Skill

项目内置四个只读 Skill：

- `skills/jc-media-script/SKILL.md`
- `skills/jc-script-storyboard/SKILL.md`
- `skills/jc-gpt-image/SKILL.md`
- `skills/jc-voice-design/SKILL.md`

`jc-storyboard-image` 的卷轴方案保留为未来 Seedance 2.0 路线，本版运行时白名单不调用它。

构建产物必须包含 `skills/`。运行时由应用读取 Skill 文本并作为固定系统指令调用文稿模型；Skill 不访问文件系统、不提交付费任务，也不持有 API Key。

### 6.1 通用文稿合同

`jc-media-script` 只负责把用户诉求收敛成可直接配音的旁白文稿，不固定行业模板，也不生成分镜。

```ts
interface MediaScriptBrief {
  request: string
  verifiedFacts?: string
  targetDuration: 10 | 15 | 30
  ratio: '9:16' | '16:9'
  styleId: string
  hasCoreReference: boolean
}

interface MediaScriptDraft {
  text: string
}
```

规则：

- `request` 必须非空；用户提供的数据、价格、功效、时间和事实只能来自 `verifiedFacts`。
- 目标时长只约束文稿长度，不能当作 Veo 的 `seconds`。
- 输出只接受 `{ "text": string }`；不接受标题、分析、镜头、Markdown 或模型补造的事实。
- 产品营销、科普、历史、企业介绍等只是 `request` 的内容差异，不切换底层媒体工作流。

### 6.2 核心参考资产合同

```ts
interface CoreReferenceAsset {
  id: string
  label: string
  relativePath: string
  mimeType: 'image/png' | 'image/jpeg' | 'image/webp'
  source: 'upload'
}
```

- 每个 run 只能有 `0..1` 个核心参考资产。
- 文稿、声音方案和配音可在无参考图时生成。
- 有参考图时，分镜计划对每镜输出 `coreReferenceVisible`；只有为 `true` 的镜头由应用强制绑定该资产。
- `id` 和 `relativePath` 只能由 Electron 主进程创建；Skill 不得输出真实文件路径。
- 删除或替换参考图时，文稿和配音保留，分镜图、视频和成片失效。
- 无参考图时允许继续，但 UI 必须标明“主体跨镜头一致性不保证”。

### 6.3 全局风格合同

MVP 不运行现有需要浏览器搜图和多轮选择的 `jc-film-style`。先使用少量经过验收的项目内置风格预设：

1. 真人写实
2. 2D 漫画/插画
3. 3D 渲染
4. 黏土定格

每个预设固定输出媒介、材质、光线、色彩、镜头语言和禁止项，合并到 `visualAnchor`。解说主题改变不自动改变风格；风格改变使分镜图、视频和成片失效，不使文稿和配音失效。

“信息图/PPT 风格”不进入上述生成预设。对可读文字、表格、图表和版式精度的需求，后续使用 HTML/Canvas/FFmpeg 确定性叠加，不让图片模型伪造文字。

### 6.4 声音设计输出合同

单旁白第一版只接受：

```ts
interface VoiceDesignDraft {
  text: string
  voicePrompt: string
}
```

`voicePrompt` 必须按固定顺序合并五项：人设、音色特征、基础风格、本篇情感、本篇节奏。应用验证 `text` 与冻结文稿一致，禁止 Skill 改写文稿。

声音设计媒体任务只向上游提交两个值：

```text
文稿       <- text
声音设定   <- voicePrompt
```

不生成、不提交语言参数。

### 6.5 分镜规划输出合同

```ts
interface StoryboardPlan {
  actualDuration: number
  visualAnchor: string
  segments: StoryboardSegment[]
}

interface StoryboardSegment {
  index: number
  playDuration: number
  generationDuration: 4 | 6 | 8
  script: string
  coreReferenceVisible: boolean
  storyboardImagePrompt: string
  videoPrompt: string
}
```

`visualAnchor` 由用户已确认的风格预设和必要的主体一致性描述构成。`jc-gpt-image` 将它展开到每个单幅首帧提示词，但不得在分镜阶段擅自更换风格或核心主体。

## 7. 时长与分段算法

### 7.1 预估

文稿生成以“约 10 秒、约 15 秒、约 30 秒”为目标。审核阶段使用 `中文字符数 / 200 * 60` 估算，只做提示，不截断文稿。

### 7.2 最终分段

最终分段必须以 Qwen TTS 音频真实时长为准：

1. 使用媒体探测读取 `voice.mp3` 实际时长。
2. 以 `ceil(actualDuration / 8)` 作为初始段数，按语义边界重新均衡，不在词语中硬切。
3. `playDuration` 是此镜头在最终时间线中的播放时长；正常处于 `4-8` 秒，所有段合计必须等于真实配音时长，误差不超过 `0.1` 秒。
4. `generationDuration` 是提交 Veo 的付费生成时长，只能为 `4`、`6` 或 `8`，并且必须大于或等于 `playDuration`。
5. 应用使用最小可覆盖的模型时长：`<=4 -> 4`、`<=6 -> 6`、`<=8 -> 8`，不允许 Skill 输出任意小数后再静默猜测。
6. FFmpeg 按 `playDuration` 裁剪已生成片段。例如约 15 秒配音可规划为两个 `7.5` 秒播放段，分别生成两条 `8` 秒视频后裁剪。

目标时长不要求是 4、6或 8 的倍数；只有每个 Veo 任务必须使用这三个离散值。成片仍以真实配音时长为准。

## 8. 媒体任务编排

### 8.1 状态机

```text
draft
  -> script-generated
  -> script-approved
  -> generating-voice-plan -> voice-plan-ready
  -> generating-voice -> voice-ready
  -> planning-storyboards -> generating-images -> storyboards-ready
  -> generating-videos -> videos-ready
  -> composing
  -> completed

任一阶段 -> failed / cancelled
```

每个图片和视频子任务独立维护：

```text
pending -> running -> success / failed / cancelled
```

### 8.2 执行顺序

1. 用户确认文稿，应用冻结文稿、比例、目标时长、风格和核心参考资产，并生成 `runId`。
2. 用户点击“生成声音方案”：使用声音 Skill 生成并展示 `VoiceDesignDraft`。
3. 用户点击“生成配音”：提交 Qwen TTS 声音设计任务，轮询、下载并把音频加入素材库。
4. 应用读取音频真实时长，但不自动提交下一阶段付费任务。
5. 用户点击“转分镜”：先使用 `jc-script-storyboard` 生成逐镜头方案，再使用 `jc-gpt-image` 根据风格和核心参考图生成 `StoryboardPlan`，结果进入右栏等待检查，不提交图片任务。
6. 用户编辑声音提示词时，当前配音及全部视觉下游失效；编辑全局一致性或某镜分镜图提示词时，该镜及其后的媒体依赖按第 8.3 节失效；编辑视频提示词时只使对应视频和成片失效。
7. 用户点击“生成分镜图”：无参考图时走文生图回退路径，并发上限固定为 2；所有成功图片立即进入素材库，失败图片可单独重试。
8. 用户点击“生成视频”：仅为已有成功单镜头分镜图提交 Veo 任务；视频并发上限固定为 2。
9. 所有成功视频立即进入素材库，失败视频可单独重试。
10. 用户点击“合成视频”：调用本地 FFmpeg 合成，保存成片并更新任务为 `completed`。

不得因一个视频失败重新生成已成功的图片、视频或配音。重试只针对失败子任务，并复用相同提示词、输入素材和模型参数。

### 8.3 重新生成与下游失效

| 用户动作 | 必须失效的下游结果 | 继续保留 |
| --- | --- | --- |
| 修改并重新确认文稿 | 声音方案、配音、分镜、视频、成片 | 历史 run 作为独立记录保留 |
| 编辑声音提示词 | 配音、分镜方案、分镜图、视频、成片 | 文稿、旧文件仍保留在磁盘 |
| 更换画面比例 | 分镜图、视频、成片 | 文稿、声音方案、配音 |
| 重新生成声音方案/配音 | 分镜图、视频、成片 | 文稿、旧音频作为历史素材保留但不再参与当前合成 |
| 重新生成某张分镜图 | 对应视频、成片 | 配音、其他分镜图和其他视频 |
| 编辑全局一致性或某镜分镜图提示词 | 对应分镜图、对应视频、成片 | 配音、未受影响镜头的媒体 |
| 编辑某镜视频提示词 | 对应视频、成片 | 配音、全部分镜图和其他视频 |
| 重新生成某条视频 | 成片 | 配音、所有分镜图和其他视频 |
| 重新合成 | 无 | 所有上游素材 |
| 修改目标时长 | 分镜方案、分镜图、视频、成片 | 文稿、声音方案、配音、核心参考图 |
| 修改全局风格 | 分镜方案、分镜图、视频、成片 | 文稿、配音、核心参考图 |
| 更换核心参考图 | 分镜方案、分镜图、视频、成片 | 文稿、配音、全局风格 |

失效表示不再参与当前工作流，不等于立即删除本地文件。删除历史素材必须由用户明确触发。

### 8.4 任务复用边界

从韭菜盒子实现移植并收敛以下行为：

- Bearer API Key 请求头；
- GPT Image 2 提交和结果 URL 提取；
- RunningHub adapter 提交；
- 原始 `rh_task_id` 轮询；
- AI App `nodeInfoList` 注入；
- 媒体任务状态、错误和结果落盘；
- 任务结果 URL 安全校验。

不得复制第二套上传器、轮询器或模型注册表。短视频工厂只保留三个固定媒体模型所需的最小合同。

## 9. 云端接口合同

### 9.1 文稿

使用 OpenAI 兼容客户端：

```text
baseURL: https://api.jiucaihezi.studio/v1
model: gemini-3.6-flash
Authorization: Bearer <API_KEY>
```

### 9.2 GPT Image 2

```text
POST https://api.jiucaihezi.studio/v1/images/generations
model: gpt-image-2
prompt: <当前镜头提示词 + 全局风格>
size: <按画面比例映射>
response_format: url
```

无核心参考图时使用该路径。可选比例取 GPT Image 2 与 Veo 3.1 的共同支持集合：`9:16`、`16:9`。同一 run 内所有图片必须使用同一比例。

有核心参考图时改用：

```text
POST https://api.jiucaihezi.studio/v1/images/edits
Content-Type: multipart/form-data
model: gpt-image-2
prompt: <当前镜头提示词 + 全局风格 + 主体一致性约束>
size: <按画面比例映射>
response_format: url
image: <托管目录中的一张核心参考图>
```

应用强制使用当前 run 的核心参考图，不把真实路径或 data URL 交给 Skill。

### 9.3 Veo 3.1

通过韭菜盒子现有 OpenAI 视频合同提交 multipart 表单：

```text
modelId: newapi/zx/veo-3.1-generate-preview
model: veo-3.1-generate-preview
input_reference: 单张单镜头首帧图
seconds: generationDuration（仅允许 4、6、8）
resolution: 720p
aspectRatio: <用户选择的画面比例>
```

`videoPrompt` 必须包含“单一连续镜头”“无切镜”“无背景音乐”。该提示仅用于改善生成结果，最终仍由本地合成强制丢弃原音轨。

### 9.4 Qwen TTS 声音设计

通过 `rh-aiapp-voice-design` 的现有 AI App 合同提交，只注入文稿和声音设定两个节点。适配层负责 `nodeInfoList` 编码、提交、轮询和音频 URL 提取。

## 10. 本地素材与持久化

用户不选择素材目录。Electron 主进程为每轮生成创建：

```text
<userData>/media-runs/<runId>/
  run.json
  inputs/core-reference.png       # 可选，每个 run 最多一张
  voice.mp3
  storyboards/001.png
  clips/001.mp4
  final.mp4
```

要求：

- 渲染进程不直接拼接任意本机绝对路径。
- 远程媒体结果由主进程下载到本轮目录后再交给 FFmpeg。
- 素材库只保存任务 ID、相对路径、状态、提示词和必要的远程结果 URL，不保存 base64 大对象。
- 第一版复用 Pinia persisted state 持久化任务元数据，不新增数据库表。
- 应用重启后可恢复成功素材；在途云任务如果保存了任务 ID 和轮询地址，应继续轮询。
- 清理动作只删除明确选中的 `runId` 目录，禁止递归操作宽泛目录。

## 11. FFmpeg 合成合同

现有 `renderVideo()` 从随机素材截片的逻辑改为接收已经按顺序生成的视频段：

```ts
interface ComposeGeneratedVideoParams {
  videoFiles: string[]
  playDurations: number[]
  voiceFile: string
  outputPath: string
  ratio: '9:16' | '16:9'
}
```

输出尺寸由比例映射：

| 比例 | 输出尺寸 |
| --- | --- |
| `9:16` | `1080x1920` |
| `16:9` | `1920x1080` |
合成规则：

1. 对每个视频只读取视频流，不映射原音轨。
2. 按 `playDurations` trim；片段不足时允许冻结最后一帧补足，禁止循环整段。
3. 统一缩放、补边、30 fps、yuv420p 后顺序 concat。
4. Qwen TTS 配音响度归一化至约 `-16 LUFS`。
5. 最终时长以配音为准；视频超出部分截断，短缺不超过单帧误差。
6. 第一版不混入 BGM、Veo 音轨或独立音效。
7. 输出 H.264 + AAC MP4。

当前 SRT 依赖 Edge TTS 的词边界，不能继续沿用。第一版不生成字幕；字幕时间轴另立阶段实现，不能用不准确的平均分配冒充真实同步。

## 12. API Key 与安全

- API Key 不写入日志、错误提示、统计事件或媒体任务 JSON。
- Electron 使用 `safeStorage` 加密后持久化；渲染进程只在发起请求所需的受控入口获取，不长期展示明文。
- 所有下载 URL 必须为允许的 `https:` 媒体地址；拒绝 `file:`、`javascript:`、未知本机路径和非预期重定向。
- “前往获取”只打开固定 keys URL。
- 任务提交前验证模型 ID、媒体类型、图片数量、比例、分辨率和 `generationDuration ∈ {4, 6, 8}`。
- 有核心参考图时验证它位于当前 run 目录内，且仅提交一个 `image` 文件。
- 取消任务只终止本地轮询和后续步骤；云端不支持取消时必须明确标记，不能声称已撤销计费。

## 13. 失败策略

| 场景 | 行为 |
| --- | --- |
| API Key 缺失/无效 | 阻止付费任务，打开配置并保留文稿 |
| 文稿 JSON 解析失败 | 自动重试一次；仍失败则保留原输出并提示重新生成 |
| 声音任务失败 | 停止后续付费任务，可单独重试 |
| 单张图片失败 | 其他图片继续，失败卡片可重试 |
| 单条视频失败 | 保留图片和其他视频，只重试失败视频 |
| 结果 URL 不安全 | 阻止下载并标记任务失败 |
| 下载中断 | 对同一结果 URL 重试，不重新提交付费生成 |
| FFmpeg 失败 | 保留全部云端素材，可重新合成 |
| 用户取消 | 停止新任务和本地进程，保留已成功素材 |

7. 分段覆盖全文、不重复、不遗漏；每段 `generationDuration` 只能是 `4 | 6 | 8`，`playDuration` 与配音实际时长一致。
8. 声音应用提交只有文稿和声音设定两个业务输入。

12. 单任务失败不重提已成功的付费任务。
13. 下载失败重试不重新生成媒体。
14. FFmpeg 输出不包含任何 Veo 原音轨。
15. 配音时长与最终视频时长误差不超过一帧，片段不因目标时长是否为 4、6、8 的倍数而失败。

## 17. 人工验收

1. 首次启动只要求 API Key，可跳转 keys 页面获取。
2. 输入一个产品、设备或界面诉求，选择一种全局风格并上传一张核心参考图，确认文稿。
3. 分别测试无参考图和有参考图：前者请求 `/v1/images/generations`，后者请求 `/v1/images/edits` 并且 multipart 包含唯一核心参考图。
4. 点击“生成声音方案”，右栏出现五项声音提示词，但尚未提交配音任务。
5. 点击“生成配音”，中栏出现可播放音频，并记录真实时长。
6. 点击“转分镜”，右栏出现完整逐镜方案；编辑任一镜头后刷新应用，修改仍然保留。
7. 点击“生成分镜图”，应用按已确认方案产生单镜头分镜图，中栏使用分类筛选和缩略图展示。
8. 点击“生成视频”，每张分镜图产生一条无切镜 Veo 视频；每段提交的 `generationDuration` 只是 4、6 或 8。
9. 任一视频失败时，其余任务继续；重试不重复扣已成功任务。
10. 点击“合成视频”，中栏出现成片；成片只有 Qwen TTS 配音，没有 Veo 人声或背景音乐。
11. 重新打开应用，仍能看到核心参考图、本轮成功素材和成片。
12. 用户点击缩略图，弹出预览弹窗，能在弹窗内查看提示词和执行单段重试。
13. 用户选择导出位置后得到可播放的 MP4。

## 18. 完成标准

只有同时满足以下条件才算 MVP 完成：

- 用户只输入诉求、API Key，并选择比例、目标时长、全局风格，可选上传一张核心参考图；不接触模型、URL、声音或素材文件夹；
- 右栏上半区可编辑声音方案，下半区可逐镜编辑分镜方案，两个区域可独立滚动且阶段按钮始终可见；
- 每一阶段完成后都可先检查素材，再决定是否继续；
- 配音、单镜头分镜图、视频片段和最终成片均进入中栏素材库；
- 有核心参考图时，所有标记为可见的镜头使用同一张核心参考图；
- 一张单镜头分镜图只驱动一条无切镜的 Veo 视频；
- 全片声音来自同一次 Qwen TTS 声音设计任务；
- Veo 原音轨被确定性移除；
- 成功媒体可恢复，失败任务可单独重试；
- 最终 MP4 可预览、定位和导出。
