> 日期：2026-07-31
> 状态：实施中
> 目标版本：2.5
> 依赖：`docs/三栏创作工作区与参考资产演进SDD.md`、`docs/短视频工厂AI原生创作改造SDD.md`、`docs/创作参数与品牌视觉升级SDD.md`
> 取代范围：`docs/三栏创作工作区与参考资产演进SDD.md` 第 4.1、4.4、8、10、12 节中的单项目选择、单核心参考与 Future 多资产方案
> 设计参考：`/Users/by3/Documents/jiucaihezi-app/public/skills/jc-everything-wiki` 的“一项目一 Wiki、Raw 保真、来源索引、双链/回链”原则；本应用使用固定骨架，不在运行时调用该 Skill

## 1. 一句话目标

让每个短视频项目成为一个可切换、可恢复、可由 Obsidian 等外部软件直接查看的固定 Wiki 包：用户原始输入进入 `.raw/`，确认文稿、声音设计、导演分镜、资产提示词、资产图、分镜图、视频和成片进入 Wiki 与受控媒体目录；导演分镜后建立资产计划，镜头通过稳定资产 ID 绑定资产，界面以 Markdown 双链展示正向引用和反向引用，全部必需资产确认后才允许生成分镜图。

## 2. 问题定义

当前实现同时存在项目管理和资产管理两个根本缺口：

1. “新建项目”当前只是归档旧 Store 并清空界面，没有可见项目目录和项目选择器；
2. 应用启动时按 `state.json` 修改时间猜最近任务，用户不能明确选择和切换项目；
3. 用户原始输入、确认文稿、提示词和媒体散落在 Store 与媒体目录中，外部软件无法完整理解项目；
4. 用户在导演分镜生成前并不知道全片究竟需要哪些人物、场景和道具；
5. 一个可选核心图不能表达多主体、多场景和多道具的镜头级绑定；
6. 用户上传的二维图片可能与全片三维、定格或真人风格不一致，直接作为镜头参考会造成风格漂移；
7. 分镜、资产提示词、资产图片和使用它们的镜头之间没有可浏览的引用关系，修改资产时难以解释影响范围。

根因不是少了一个按钮或上传框，而是系统把一次创作当成临时 `run`，没有把它建模为一个拥有 Raw、Wiki、媒体、状态和引用图谱的持久项目。

## 3. 已确认产品决策

1. 一个项目对应一个稳定 `projectId`、一个受控项目目录和一套固定 Wiki；
2. 点击“新建项目”立即创建项目目录和 Wiki 骨架，不等到确认文稿或上传图片才创建 ID；
3. 顶部同时提供“新建项目”和项目选择器，可保存当前项目后切换到任意历史项目；
4. 用户直接输入和导入的 Markdown 是 Raw；模型生成但未确认的内容必须标记为草稿，确认或成功产物才成为项目事实；
5. Wiki 使用普通 UTF-8 Markdown 和相对媒体链接，可由 Obsidian、VS Code 或文件浏览器直接查看；
6. `state.json` 继续负责执行状态，Markdown 负责持久可读文档；第一版不自动导入外部软件对 Markdown 的修改；
7. 左栏不再上传核心参考图，只保留用户诉求、比例、目标时长、视觉风格和镜头节奏；
8. 导演分镜负责识别资产需求，但不生成本地路径、不提交图片任务；
9. 分镜完成后，中栏自动进入独立“资产”工作区；
10. 用户可为任一资产选择“上传”“AI 生成”或“不需要”；
11. 未上传但被镜头引用的必需资产，由角色、场景和道具 Skill 生成资产提示词后补齐；
12. 用户上传的原图永久保留；与项目风格不一致时生成派生的风格统一版本，不覆盖原图；
13. 镜头只绑定资产 ID，不绑定资产名称、Markdown 文本、提示词或本地路径；
14. Markdown 双链是面向用户的文档投影和导航层，结构化 ID 是业务事实来源；
15. 正向引用由导演分镜产生，反向引用由应用根据正向引用实时计算，不双向重复存储；
16. 全部必需资产达到“已确认”后，才解锁分镜图生成；
17. 每镜只向图片任务发送实际绑定资产的当前采用版本，不发送全项目全部资产；
18. 保持现有三栏，不增加第四列，不创建第二套媒体状态机。

## 4. 新工作流

```text
新建项目，立即创建 projectId 和固定 Wiki 骨架
  -> 用户输入文字或导入 Markdown，保存为不可丢失的 Raw 提交
  -> 选择比例、目标时长、视觉风格、镜头节奏
  -> 生成并确认唯一文稿
  -> 生成声音方案与配音，读取真实时长
  -> 导演生成分镜、全局视觉锚点和资产计划
  -> 资产工作区展示人物、场景、道具清单及镜头反向引用
  -> 用户为重要资产上传原图
  -> 系统为缺失资产生成提示词
  -> 系统为缺失资产生成资产图
  -> 对风格不一致的上传图生成风格统一派生版本
  -> 用户逐项确认资产及当前采用版本
  -> 每镜绑定已确认资产 ID
  -> 生成分镜图
  -> 生成单镜头视频
  -> 合成成片
  -> Wiki 索引、来源索引和项目状态同步完成
```

任何页面切换、双链跳转、查看提示词或查看反向引用都不得自动产生付费任务。

## 5. 一项目一 Wiki

### 5.1 项目身份与物理目录

`projectId` 是项目、Wiki、媒体和云端任务的共同所有权边界。第一版直接复用现有安全目录，不为改名搬迁大文件：

```text
<Electron userData>/media-runs/<projectId>/
```

现有代码中的 `runId` 在迁移期等于 `projectId`。新增合同统一使用 `projectId`；媒体 API 可暂时保留参数名 `runId`，但值必须来自当前项目，不能再为同一个项目重复创建运行目录。

```ts
interface ProjectManifest {
  projectId: string
  name: string
  createdAt: string
  updatedAt: string
  stage: WorkflowStage
  coverRelativePath?: string
  wikiVersion: 1
}
```

- 新建项目使用本地安全随机 ID；
- 默认名称为“未命名项目 + 创建时间”，首次确认文稿后可建议用文稿主题重命名，但不得静默改名；
- 项目改名只修改 `project.json`、Wiki 标题和显示名称，不重命名物理目录；
- `project.json` 用于项目列表，`state.json` 用于完整执行恢复，两者职责不得混合；
- 所有相对媒体路径仍由 Electron 主进程解析并限制在当前 `projectId` 目录内。

### 5.2 固定项目骨架

新建项目时直接由应用创建以下最小骨架，不运行 `jc-everything-wiki`，也不让模型决定目录：

```text
<projectId>/
├── project.json
├── state.json
├── index.md
├── .raw/
│   ├── 提交记录/
│   └── 导入资料/
├── wiki/
│   ├── index.md
│   ├── 项目.md
│   ├── 来源索引.md
│   ├── hot.md
│   ├── log.md
│   ├── 文稿/
│   │   └── 确认文稿.md
│   ├── 声音/
│   │   └── 配音设计.md
│   ├── 分镜/
│   │   ├── 导演总览.md
│   │   └── 镜头/
│   ├── 资产/
│   │   ├── 产品/
│   │   ├── 角色/
│   │   ├── 场景/
│   │   └── 道具/
│   ├── 分镜图/
│   ├── 视频/
│   └── 成片/
├── inputs/
├── assets/
├── storyboards/
├── clips/
├── voice.mp3
└── final.mp4
```

文件只在有对应内容时创建；空目录可以在初始化时创建，空 Markdown 页面不得提前堆满占位文字。根 `index.md` 只负责把外部查看者引导到 `wiki/index.md`、`.raw/` 和主要媒体目录。

### 5.3 Raw 合同

Raw 保存用户实际提交给生成链路的原始信息，不保存模型总结，不保存完整聊天记录。

直接输入时，每次用户明确点击“生成文稿”都冻结一份提交：

```text
.raw/提交记录/0001-原始需求.md
.raw/提交记录/0002-修改后需求.md
```

导入 Markdown 时：

- 只支持 UTF-8 `.md`，必须执行文件大小和可读性校验；
- 原文件不移动、不删除；应用把本次使用的不可变快照复制到 `.raw/导入资料/`，以保证项目包可独立查看；
- `state.json` 记录原始绝对路径，`wiki/来源索引.md` 只记录原文件名、导入时间、快照相对路径和内容哈希，避免把机器目录写进可分享文档；
- 同名导入使用唯一文件名，不覆盖已有 Raw；
- 后续原文件变化不会静默改写项目快照，用户必须主动重新导入；
- API 只消费用户明确选择的 Raw 内容，不遍历 `.raw/` 猜测输入。

这个项目内 Raw 快照与 `jc-everything-wiki` 的“原始材料不动”原则不冲突：真实来源仍然保留在原位置，项目只保存一次明确提交的可移植证据快照。

### 5.4 Wiki 文档映射

| 项目产物 | Wiki 文档 | 写入时机 |
| --- | --- | --- |
| 用户原始输入 | `.raw/提交记录/*.md` 或 `.raw/导入资料/*.md` | 用户点击生成或主动导入时 |
| 确认文稿 | `wiki/文稿/确认文稿.md` | 用户确认文稿时 |
| 五项声音提示词 | `wiki/声音/配音设计.md` | 声音方案生成成功或用户应用修改时 |
| 导演全局方案 | `wiki/分镜/导演总览.md` | 分镜合同验证成功时 |
| 单镜分镜 | `wiki/分镜/镜头/<shotId>.md` | 分镜合同验证成功时 |
| 资产提示词与版本 | `wiki/资产/<类型>/<assetId>.md` | 提示词、版本或采用状态变化时 |
| 分镜图 | `wiki/分镜图/<shotId>.md` | 图片生成成功或采用新版本时 |
| 单镜视频 | `wiki/视频/<shotId>.md` | 视频生成成功或采用新版本时 |
| 成片 | `wiki/成片/成片.md` | 合成成功时 |
| 当前状态 | `wiki/hot.md` | 阶段或阻塞项变化时 |
| 已确认事件 | `wiki/log.md` | 确认、生成成功、采用版本或恢复迁移时追加 |

所有托管页面使用 YAML Frontmatter 标记稳定实体和生成状态：

```md
---
projectId: project-a91f
entityType: shot
entityId: shot-03
status: confirmed
managedBy: money-clips
updatedAt: 2026-07-31T12:00:00+08:00
---
```

- `status` 至少区分 `draft / confirmed / generated / failed`；
- 模型草稿可以显示，但不得伪装成确认事实；
- 媒体页面使用相对链接，例如 `![镜头 03](../../storyboards/003.png)`；
- 视频和成片页面使用普通相对链接并附带时长、比例、来源镜头和当前采用版本；
- Wiki 不复制媒体二进制，链接到同一项目目录内的受控文件。

### 5.5 来源索引

`wiki/来源索引.md` 维护“Wiki 文档 -> Raw 提交 -> 媒体/状态证据”的定位关系，不摘抄完整 Raw：

```md
| Wiki 文档 | Raw/来源 | 生成或确认依据 |
| --- | --- | --- |
| [[文稿/确认文稿]] | [0001-原始需求](../.raw/提交记录/0001-原始需求.md) | 用户确认文稿 |
| [[分镜/导演总览]] | [[文稿/确认文稿]]、voice.mp3 | 真实配音 23.6 秒 |
| [[资产/角色/asset-char-a91f]] | [[分镜/导演总览]] | jc-character-prompt |
```

来源索引由应用更新，不由各个 Skill 自行拼接路径。找不到来源时写“待补充”，不得猜测文件名或外部会话 ID。

### 5.6 Markdown 与执行状态同步

`state.json` 是恢复、校验、付费任务和精确失效的事实来源；`.raw/` 是用户提交证据；`wiki/*.md` 是可持续阅读的项目文档。三者不能互相替代。

每次已确认状态变化按以下顺序写入：

```text
验证结构化数据
  -> 写入 state.json.tmp 并原子替换 state.json
  -> 渲染受影响 Markdown 到临时文件并原子替换
  -> 更新 project.json.updatedAt 和 stage
```

- 同一项目继续使用串行写队列，防止防抖保存和阶段完成互相覆盖；
- Markdown 写入失败不得撤销已成功媒体，但必须把项目标记为“Wiki 待同步”并允许重建；
- 应用提供“重建 Wiki”命令，根据 `state.json` 和现有媒体重新生成托管页面，不触发模型或付费任务；
- `.raw/` 永不由“重建 Wiki”覆盖或删除；
- 第一版外部软件只读兼容：外部修改托管 Markdown 不自动回写 Store，下一次同步可能覆盖该修改；
- 页面 Frontmatter 必须明确 `managedBy: money-clips`，避免用户误以为外部编辑会自动进入生成链路。

### 5.7 新建项目与项目选择器

应用标题区使用稳定结构：

```text
[新建项目] [当前项目名称 v]                         [设置]
```

“新建项目”：

1. 当前有运行中任务时禁用，并显示原因；
2. 先立即保存当前项目的 `state.json`、Wiki 和 `project.json`；
3. 创建新的 `projectId`、默认名称和固定骨架；
4. 切换 Store 到空白项目，保留 API Key 和应用级配音引擎偏好；
5. 不删除、不归档隐藏、也不改写旧项目；
6. 新项目创建失败时继续停留在旧项目。

项目选择器：

- 数据来自扫描合法 `project.json` 后得到的项目目录，不使用 Pinia `history` 作为项目目录；
- 显示项目名、阶段、更新时间和可选封面缩略图；
- 支持搜索、切换、重命名和“在访达中显示”；
- 项目切换前保存当前项目，再显式加载选择项目的 `state.json`；
- 运行中任务时第一版禁止切换，后续若实现后台任务管理再放开；
- 项目损坏或 Wiki 待同步时显示状态，不从列表静默消失；
- 第一版不提供永久删除，避免项目与媒体不可恢复；
- 应用启动时恢复 `lastOpenedProjectId`；不存在时显示项目选择器，不再按文件修改时间猜当前项目。

### 5.8 外部查看与可移植边界

- “在访达中显示”打开整个 `<projectId>` 目录；
- 用户可把项目目录作为 Obsidian Vault 或在 VS Code 中打开；
- Wiki Link 和媒体链接必须使用项目内相对路径，不能写入 `file://` 或机器绝对路径；
- `project.json` 和 `state.json` 仍是应用私有执行文件，外部软件主要读取 `index.md`、`.raw/`、`wiki/` 和媒体；
- 第一版不承诺复制项目目录到另一台机器后可继续提交云端任务；可移植查看必须成立，完整导入/导出另立 SDD；
- API Key、用户目录路径、云端临时 URL、任务轮询密钥和本地模型路径不得写入 Wiki。

## 6. 信息架构

### 6.1 三栏职责

| 区域 | 新职责 |
| --- | --- |
| 顶部项目栏 | 新建项目、项目选择器、项目状态、设置 |
| 左栏：创作输入 | 用户诉求或 Markdown 导入、比例、目标时长、视觉风格、镜头节奏 |
| 中栏：作品工作区 | 文稿、分镜、资产、分镜图、视频、成片六个一级视图 |
| 右栏：上下文检查器 | 当前文档、镜头、资产或媒体的属性、提示词、引用关系和当前阶段操作 |

左栏删除核心参考上传、缩略图、替换和移除控件。旧任务的核心参考图迁移到“资产”工作区，不丢失原文件。

### 6.2 中栏一级视图

```text
文稿 | 分镜 | 资产 | 分镜图 | 视频 | 成片
```

| 视图 | 核心内容 |
| --- | --- |
| 文稿 | 唯一文稿、确认状态、统一配音播放器和真实时长 |
| 分镜 | 导演总览、全局视觉锚点、资产双链、节奏带、镜头文档 |
| 资产 | 资产计划、上传原图、AI 补齐、风格统一版本、确认状态、反向引用 |
| 分镜图 | 每镜首帧、生成状态、绑定资产、提示词和局部重做 |
| 视频 | 每镜视频、生成状态、来源分镜图和局部重做 |
| 成片 | 最终播放器、比例、时长、导出与重新合成 |

统一配音属于文稿的派生产物，常驻文稿视图顶部，不为音频单独增加一级视图。

### 6.3 阶段进度

右栏顶部阶段进度升级为：

```text
文稿 -> 配音 -> 分镜 -> 资产 -> 分镜图 -> 视频 -> 成片
```

| 当前状态 | 默认视图 | 主操作 |
| --- | --- | --- |
| 配音已生成 | 文稿 | 转分镜 |
| 分镜与资产计划已生成 | 资产 | 准备资产提示词 |
| 存在待生成资产 | 资产 | 生成 N 张资产图 |
| 资产图已生成但未确认 | 资产 | 确认资产 |
| 全部必需资产已确认 | 分镜图 | 生成 N 张分镜图 |
| 分镜图已完成 | 视频 | 生成 N 条视频 |
| 视频已完成 | 成片 | 合成视频 |

同一时刻仍然只允许一个绿色主按钮。上传是当前资产的工具，不冒充阶段主按钮。

## 7. 导演分镜与资产计划合同

### 7.1 分镜输出

`jc-script-storyboard` 在现有导演字段和镜头字段之外，新增 `assetPlan`。Skill 只输出本次计划内唯一的 `assetKey`；应用验证引用完整性后为每项资产分配稳定 ID。

```ts
type PlannedAssetRole = 'product' | 'character' | 'scene' | 'prop'

interface PlannedAsset {
  assetKey: string
  role: PlannedAssetRole
  label: string
  description: string
  identityTraits: string[]
  styleRequirements: string[]
  required: boolean
}

interface StoryboardDocument {
  // 保留现有导演字段
  assetPlan: PlannedAsset[]
  shots: StoryboardShot[]
}

interface StoryboardShot {
  // 保留现有镜头字段
  assetKeys: string[]
}
```

### 7.2 计划验证

- `assetKey` 在本次文档内必须唯一且不可为空；
- 每个 `shots[].assetKeys` 必须指向 `assetPlan` 中存在的项；
- 一个镜头只能有一个主要场景，但可引用多个人物和道具；
- 未在任何镜头出现的普通资产不得进入 `assetPlan`；
- 只影响气氛但不要求视觉一致的背景杂物不建独立资产；
- 同一实体不得因不同镜头、角度或动作被拆成多个资产；
- 角色服装或道具外观发生剧情性变化时才建立显式变体，不冒充新实体；
- Skill 不得输出 UUID、本地路径、图片 URL、付费任务 ID 或已生成状态。

### 7.3 稳定 ID 映射

应用解析成功后使用本地安全随机 ID 建立映射：

```text
character:xiaohong -> asset-char-a91f
scene:night-studio -> asset-scene-4c20
prop:core-device -> asset-prop-19d2
```

随后把镜头中的 `assetKeys` 一次性转换为 `referenceAssetIds`。持久化后不再依赖名称或 `assetKey` 解析关系。

## 8. 资产数据合同

```ts
type AssetRole = 'product' | 'character' | 'scene' | 'prop'
type AssetSource = 'upload' | 'generated'
type AssetStatus =
  | 'planned'
  | 'prompt-ready'
  | 'generating'
  | 'ready'
  | 'failed'
  | 'approved'

interface AssetVersion {
  id: string
  source: AssetSource
  relativePath: string
  prompt?: string
  derivedFromVersionId?: string
  createdAt: string
}

interface ReferenceAsset {
  id: string
  role: AssetRole
  label: string
  description: string
  identityTraits: string[]
  styleRequirements: string[]
  required: boolean
  status: AssetStatus
  prompt: string
  versions: AssetVersion[]
  activeVersionId?: string
}
```

规则：

1. `ReferenceAsset.id` 创建后不可因改名、改提示词或重生成而变化；
2. `activeVersionId` 决定下游实际使用哪张图；
3. 上传原图保存为独立版本，风格转换图通过 `derivedFromVersionId` 指向原图；
4. 提示词属于资产元数据，不是资产实体，也不作为镜头绑定目标；
5. 资产没有可用图片版本时不能进入 `approved`；
6. 必需资产未确认时不得提交分镜图任务；
7. 可选资产选择“不需要”后必须从所有镜头绑定中移除；必需资产不能直接选择“不需要”，必须先重新规划分镜或改为非必需；
8. Skill 只消费受控元数据，不读取和返回本机路径。

## 9. Markdown 双链创作图谱

### 9.1 定位

Markdown 是文稿、导演文档、资产文档和镜头文档的可读投影。它负责展示、导航、复制和未来导出；结构化 Store、资产 ID、版本 ID 和媒体状态负责校验、任务提交、恢复和失效计算。

不得从用户任意输入的 Markdown 文本中用正则反推付费任务绑定。引用关系必须先通过结构化编辑更新，再由应用重新渲染 Markdown。

### 9.2 链接语法

托管 Markdown 使用能被 Obsidian 直接解析的项目内文件路径 Wiki Link：

```md
[[资产/角色/asset-char-a91f|小红]]
[[资产/场景/asset-scene-4c20|夜间工作室]]
[[分镜/镜头/shot-03|镜头 03]]
[[项目|项目主视觉]]
```

- 文件名使用稳定实体 ID，目录表达实体类型，竖线后是可变显示名称；
- 页面 Frontmatter 中的 `entityType`、`entityId` 必须与文件路径一致；
- 应用解析链接后仍以 `entityId` 查询结构化状态，不以显示名称建立业务绑定；
- 改名只更新页面标题和链接显示名称，不改变 ID 或文件路径；
- 链接渲染为可聚焦、可点击的文本链接或紧凑标签；
- 无法解析的链接显示“引用已失效”，不得静默按名称匹配其他资产；
- Raw 和媒体不是 Wiki 实体，使用普通相对 Markdown 链接，不伪装成双链页面。

### 9.3 导演文档示例

```md
# 导演分镜

项目风格：[[项目|手工粘土定格]]

## 资产计划

- 角色：[[资产/角色/asset-char-a91f|小红]]
- 场景：[[资产/场景/asset-scene-4c20|夜间工作室]]
- 道具：[[资产/道具/asset-prop-19d2|核心设备]]
- 道具：[[资产/道具/asset-prop-62b8|笔记本电脑]]

## 镜头 03

资产：[[资产/角色/asset-char-a91f|小红]]、[[资产/场景/asset-scene-4c20|夜间工作室]]、[[资产/道具/asset-prop-19d2|核心设备]]
```

### 9.4 资产文档与反向引用

资产文档展示系统计算的反向引用：

```md
# 小红

类型：角色
当前版本：手工粘土定格版
来源：AI 生成

## 被引用

- [[分镜/镜头/shot-01|镜头 01]]
- [[分镜/镜头/shot-03|镜头 03]]
- [[分镜/镜头/shot-07|镜头 07]]
```

反向引用不写回资产记录。应用遍历 `shots[].referenceAssetIds` 生成索引；镜头绑定变化后立即重新计算。

### 9.5 跳转行为

- 点击资产链接：进入“资产”视图并选中对应资产；
- 点击镜头链接：进入“分镜”视图并滚动到对应镜头；
- 点击风格链接：在右栏展示项目主视觉和完整 `visualAnchor`；
- 跳转只改变当前视图和选择，不提交任务、不改变阶段、不清理提案；
- 浏览器式返回不是第一版要求，用户可通过现有一级视图返回。

## 10. 资产准备与 Skill 路由

### 10.1 路由表

| 资产角色 | 运行时 Skill | 资产图要求 |
| --- | --- | --- |
| `product` | `jc-prop-prompt` 的产品保持分支 | 严格保持产品轮廓、Logo、文字、颜色和结构；只转换媒介、材质与光影 |
| `character` | `jc-character-prompt` | 稳定身份特征、服装和比例；纯净背景；可复用角色设定图 |
| `scene` | `jc-scene-prompt` | 无人物空镜；明确空间布局、材质、光源和关键物件 |
| `prop` | `jc-prop-prompt` | 稳定轮廓、材质、尺寸和识别标记；纯净背景 |

### 10.2 应用运行时模式

现有三个 Skill 包含浏览器搜图、人工选图和文件约定，不能原样作为桌面应用单轮合同执行。实施时在现有 Skill 中增加明确的 `app-runtime` 输入分支：

```ts
interface AssetPromptRequest {
  mode: 'app-runtime'
  asset: {
    id: string
    role: AssetRole
    label: string
    description: string
    identityTraits: string[]
  }
  projectStyle: {
    id: string
    prompt: string
    visualAnchor: string
    ratio: '9:16' | '16:9'
  }
  hasUploadedSource: boolean
}

interface AssetPromptResult {
  assetId: string
  prompt: string
}
```

运行时模式规则：

- 不启动浏览器、不搜索 Pinterest、不要求用户在 Skill 内多轮选择；
- 只返回一个与 `assetId` 对应的结构化提示词；
- 不返回路径、图片、Markdown 文档或媒体任务状态；
- 上传图存在时，提示词描述“保持身份/轮廓/结构，只转换到项目媒介与视觉风格”；
- 上传图不存在时，提示词生成标准资产设定图；
- 输出通过解析器验证后，才允许应用提交图片任务。

### 10.3 上传与风格统一

每个资产只有一个统一的“参考图”列表。联网搜索结果与用户本地上传图进入同一列表，不区分用途，不要求用户填写说明，也不覆盖彼此。

- 资产卡展示参考图缩略图和一个“添加参考图”图标按钮；
- 每张参考图均可预览、单独删除；
- 用户可以为同一资产上传多张 PNG、JPEG 或 WebP；
- 生成时一次提交资产设计 JSON 与当前全部参考图；
- 固定说明仅为“请结合全部参考图生成，最终内容、画风和比例以资产设计 JSON 为准”；
- 新增或删除参考图后，已有 AI 资产图保留，但该资产重新进入待生成集合；
- 新 AI 版本生成成功后自动成为当前资产图，旧 AI 版本继续保留。

### 10.4 批量操作与费用

- “准备资产提示词”只提交文本任务；
- “生成 N 张资产图”才提交图片任务，并显示准确数量；
- 上传图需要风格转换时也计入 N；
- 资产图生成是可随时返回执行的增量操作，不受首轮角色、场景、道具 Skill 完成标记限制；
- 每次点击时现场扫描当前资产：已有与当前设计 JSON 匹配的 AI 版本则跳过，只有参考图、后来新增、上次失败或尚无 AI 版本的资产进入本轮任务；
- “匹配”同时要求该 AI 版本使用了当前参考图集合；参考图发生增删后只重做该资产；
- `assetPlanCompletedRoles` 只表示对应资产提示词 Skill 是否完成，不能用于禁用“搜索下载参考图”或“生成资产图”；
- 只要当前存在带有效设计 JSON 的资产，“生成资产图”就必须可用；没有参考图时仍允许文生图；
- 部分失败后主按钮显示“重试 N 个失败资产”；
- 已成功和已确认资产不得重复付费；
- 用户取消数量确认后不创建任何媒体任务；
- 资产生成失败时保留原上传版本和其他成功资产。

示例：角色已有 AI 图，导演分镜后又出现一个场景和一个道具。用户返回资产页并点击一次“生成资产图”时，只提交场景和道具两项；角色自动跳过，不要求重新运行三个资产提示词 Skill。

## 11. 分镜图生成合同

分镜图任务从单一 `referencePath` 升级为有序资产版本列表：

```ts
interface StoryboardImageRequest {
  runId: string
  shotId: string
  prompt: string
  ratio: '9:16' | '16:9'
  referenceAssetVersionIds: string[]
}
```

提交前应用必须验证：

1. 每个 ID 都属于该镜 `referenceAssetIds`；
2. 每个版本都是对应资产的 `activeVersionId`；
3. 每个必需资产状态为 `approved`；
4. 发送顺序固定为场景、角色、道具，组内按资产计划顺序；
5. 请求不包含未绑定资产和真实本机路径；
6. 媒体网关必须通过集成测试证明支持多图输入；若不支持，本阶段不得以“发送第一张图”静默降级。

图片提示词继续由 `jc-gpt-image` 根据导演镜头和资产绑定生成。它可以读取资产公开描述和当前版本元数据，但不得改变资产集合、生成新资产或删掉导演字段。

## 12. 编辑、版本与精确失效

| 修改 | 保留 | 失效 |
| --- | --- | --- |
| 资产改名或文档说明 | 全部媒体 | 无，仅重渲染链接名称 |
| 修改资产提示词但未生成 | 当前采用版本和下游 | 无 |
| 生成新资产版本但未采用 | 当前采用版本和下游 | 无 |
| 切换资产采用版本 | 文稿、配音、分镜、其他资产 | 引用该资产的镜头图、对应视频、成片 |
| 删除可选资产绑定 | 文稿、配音、其他镜头 | 原引用镜头图、对应视频、成片 |
| 新增镜头资产绑定 | 文稿、配音、其他镜头 | 当前镜头图、对应视频、成片 |
| 重新转分镜并改变资产计划 | 文稿、配音、可复用资产版本 | 受影响镜头图、视频、成片 |

- 资产新版本成功且被用户采用前，不得清空任何已生成媒体；
- 同一资产被 5 个镜头引用时，切换版本只让这 5 个镜头的视觉下游失效；
- 删除资产前必须展示反向引用；仍被引用的资产不能直接删除，只能先解除绑定或重新规划；
- 重新转分镜时优先按稳定语义匹配复用已有资产，不能仅按显示名称猜测；无法可靠匹配时创建新资产并让用户确认。

## 13. 旧任务迁移

现有 `<userData>/media-runs/<runId>/state.json` 目录直接接管为项目：

- `projectId = runId`，不移动或重命名目录；
- 根据旧状态中的文稿首句生成建议项目名，用户确认前可使用“历史项目 + 日期”；
- 补建 `project.json`、根 `index.md`、`.raw/` 和 `wiki/`；
- 根据旧 `state.json` 与现有媒体机械重建 Wiki，不调用模型、不产生费用；
- 无法还原最初用户输入时，`来源索引.md` 标记“旧任务未保存完整 Raw”，不得用确认文稿冒充 Raw；
- 原 Pinia `history` 只作为迁移线索，迁移完成后的项目列表以磁盘 `project.json` 为准。

旧任务的 `coreReference` 迁移为一个资产：

```text
role = 'prop'
source = 'upload'
status = 'approved'
activeVersionId = 原核心参考图版本
```

旧镜头迁移规则：

```text
coreReferenceVisible === true  -> referenceAssetIds = [迁移后的资产 ID]
coreReferenceVisible === false -> referenceAssetIds = []
```

- 迁移不复制图片文件；
- 旧任务已有分镜图、视频和成片时全部保留；
- 旧核心图角色无法可靠判断时默认 `prop`，界面允许用户改为产品、角色或场景；
- 缺少 `assetPlan` 的旧任务以兼容模式打开，不强迫用户补齐资产后才能查看或导出已有成片；
- 用户主动重新转分镜后才进入新资产计划流程。

## 14. 状态与恢复

业务阶段扩展为：

```text
draft
-> script-generated
-> script-approved
-> voice-plan-ready
-> voice-ready
-> shot-plan-ready
-> assets-ready
-> storyboards-ready
-> videos-ready
-> completed
```

`assets-ready` 表示全部必需资产存在已确认采用版本。该状态必须由持久化资产和镜头绑定重新计算，不能只信任历史字符串。

恢复任务时：

- 先读取应用级 `lastOpenedProjectId`，显式加载该项目；
- 若项目不存在或损坏，打开项目选择器，不自动选择修改时间最新的目录；
- 先恢复分镜、资产、版本和媒体相对路径；
- 重建正向引用索引和反向引用索引；
- 清理指向已不存在资产的 UI 选择；
- 缺失资产版本时回退到“资产”阶段并说明具体对象；
- 不自动重新生成提示词、资产图或分镜图。

## 15. 实施阶段

### Phase 1：项目与 Wiki 基础

1. 新建项目时立即创建 `projectId`、`project.json`、`state.json`、`.raw/` 和固定 Wiki 骨架；
2. 实现项目枚举、项目选择器、保存后切换、重命名和在访达中显示；
3. 保存并恢复 `lastOpenedProjectId`，删除按修改时间猜当前项目的主路径；
4. 实现直接输入和 Markdown 导入的不可变 Raw 提交与来源索引；
5. 实现结构化状态到 Markdown 的增量渲染与“重建 Wiki”；
6. 接管旧 `media-runs/<runId>` 为项目，不移动媒体。

### Phase 2：资产合同与迁移

1. 扩展导演分镜合同，输出 `assetPlan` 和镜头 `assetKeys`；
2. 增加资产、版本、映射和完整性解析器；
3. 把旧核心参考图迁移为单个资产；
4. 增加 `assets-ready` 阶段与精确失效测试；
5. 验证媒体网关多图输入能力。

### Phase 3：资产工作区

1. 左栏移除核心参考图；
2. 中栏升级为六个一级视图；
3. 实现资产清单、角色分组、状态、上传和版本选择；
4. 为三个现有资产 Skill 增加 `app-runtime` 合同；
5. 实现提示词准备、资产图生成、风格统一和逐项确认；
6. 资产未就绪时阻止分镜图提交。

### Phase 4：双链与镜头绑定

1. 渲染资产、镜头和风格 Wiki Link；
2. 实现链接跳转和系统计算的反向引用；
3. 实现镜头资产绑定编辑；
4. 分镜图任务只发送当前镜头采用的资产版本；
5. 实现资产版本切换后的镜头级精确失效；
6. 人工走通项目切换、Raw、Wiki、上传、补齐、风格转换、分镜图、视频和成片全链路。

四个 Phase 按顺序实施。Phase 1 独立交付后，项目管理和 Wiki 已可使用；多图网关验证失败时，Phase 3 可继续完成资产库，但不得宣称 Phase 4 的多资产分镜图链路完成。

## 16. 验收标准

1. 点击“新建项目”立即创建不同的 `projectId` 和固定 Wiki 骨架，不清空或覆盖旧项目。
2. 项目选择器能列出、搜索、切换、重命名和在访达中显示全部合法项目。
3. 应用重启恢复 `lastOpenedProjectId`；目标缺失时打开项目选择器，不猜最新目录。
4. 直接输入和导入 Markdown 都形成不可变 Raw 提交；外部原文件不被移动、覆盖或删除。
5. 确认文稿、声音设计、导演分镜、资产提示词、资产图、分镜图、视频和成片均有固定 Wiki 页面。
6. `来源索引.md` 能从确认文稿、分镜和资产回到实际 Raw、上游文档和媒体证据。
7. 项目目录可直接由 Obsidian 或 VS Code 查看，Wiki Link 和媒体相对链接不包含机器绝对路径。
8. “重建 Wiki”无需模型和费用即可根据状态恢复全部托管文档，且不覆盖 `.raw/`。
