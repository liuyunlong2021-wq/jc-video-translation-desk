# 并行创作分支与 Markdown 阅读导航优化 SDD

> 日期：2026-07-31
> 状态：已实施（正式签名发布验收待 Developer ID 证书）
> 目标版本：2.7
> 依赖：`docs/资产图工作区与Markdown双链创作图谱升级SDD.md`、`docs/Markdown主导Wiki创作与媒体执行升级SDD.md`
> 范围：分镜/资产生成编排、Markdown 阅读导航、右栏布局、API Key 持久化提示

## 1. 结论

当前“转分镜”过重的根因不是模型能力不足，而是导演在稳定资产 ID 建立前同时承担资产识别和资产提示词。创作参数和文稿确认后，角色、场景、道具三个专业 Skill 先并行生成正式资产提示词，App 分配稳定 ID；全部必需资产确认且真实配音时长可用后，导演再生成分镜并直接绑定现有资产 ID。

资产类型统一为 `character / scene / prop`。品牌设备、包装和应用载体都属于道具；需要保持 Logo、文字、品牌色和结构时，由道具的身份特征和用户参考图触发高一致性约束，不再建立第四种资产类型或专用分支。

## 2. 当前问题

1. 导演 Skill 同时承担镜头设计、资产识别和资产 Markdown 生成，输出规模过大，失败时整轮回滚。
2. 资产提示词前端按资产逐个串行调用，任一失败都会拖慢整个阶段，也无法展示每个分支的独立状态。
3. 历史流程保留 `product` 与单核心资产过渡概念，使资产类型、Skill 映射和镜头绑定出现不必要分叉。
4. 当前中栏镜头页仍渲染废弃的空状态，占据 Markdown 阅读区下半部分。
5. Markdown 双链可以正向进入镜头，但镜头页没有返回导演总览的父级导航。
6. 未签名开发包无法使用 Electron `safeStorage` 持久保存 API Key，当前会话成功不等于重启后仍可用。

## 3. 新编排模型

```text
确认文稿 + 比例 + 全局风格
        |
        +-- 配音分支：声音方案 -> 配音 -> 真实时长
        |
        +-- 资产分支（并行）：
              角色资产提示词（jc-character-prompt）
              场景资产提示词（jc-scene-prompt）
              道具资产提示词（jc-prop-prompt）
              -> App 去重并分配稳定资产 ID
              -> 用户上传/生成并确认资产版本
        |
        +-- 汇合：真实配音时长 + 全部必需资产已确认
        +-- 导演分镜与镜头提示词（jc-script-storyboard）
              -> 只能绑定已有资产 ID
        +-- 生成分镜图
```

### 3.1 三类资产并行

- 输入只来自确认文稿、比例、视觉风格和已有资产；资产规划不依赖真实配音时长。
- 角色分支扫描确认文稿，输出全部需要保持一致的角色资产档案与正式提示词。
- 场景分支扫描确认文稿，输出全部主要场景的空环境资产档案与正式提示词。
- 道具分支扫描确认文稿，输出全部重要道具的资产档案与正式提示词；品牌道具启用高一致性约束。
- 三个资产分支不写本地路径、不提交图片任务，不互相等待。
- 每个分支必须带 `generatedBySkill`、`sourceDocument` 和 `status: draft`，便于 UI 显示来源和失败重试。

### 3.2 本地汇合：唯一资产图谱

App 负责而不是模型负责：

- 按稳定语义合并同一实体，保留用户已有资产 ID 和版本；
- 先为三类资产分配稳定 ID；导演只允许引用这些 ID，并解析为 `referenceAssetIds`；
- 资产角色只允许 `character`、`scene`、`prop`；
- 品牌道具作为 `prop` 保存，并在身份特征中锁定 Logo、文字、品牌色、包装轮廓和关键结构；
- 资产在导演执行前已经确认，不因当前导演是否引用而删除；
- 冲突时标记为 `needs-review`，不得静默选一个版本；
- 生成 `wiki/资产/...` 与镜头反向引用，但不把反向引用重复存成第二份业务事实。

导演发现缺少关键资产时必须返回缺失资产错误并退回资产阶段，不得临时创造资产 ID。

### 3.3 Skill 与资产类型

| 资产角色 | 必用 Skill | 输出约束 |
| --- | --- | --- |
| character | `jc-character-prompt` | 身份、轮廓、服装、辨识特征与多角度一致 |
| scene | `jc-scene-prompt` | 空环境、空间布局、材质、光源，无人物 |
| prop | `jc-prop-prompt` | 轮廓、结构、材质、尺寸和识别标记；品牌道具额外锁定 Logo、文字与品牌色 |

三个资产 Skill 必须直接输出正式资产档案和“资产生成提示词”。输入包含确认文稿、项目视觉锚点、比例、已有资产和用户上传参考图元数据；输出不允许包含本地路径、任务 ID 或伪造媒体结果。

## 4. 状态与费用

```text
draft -> planning -> needs-review -> prompt-ready
      -> ready (用户上传或生成版本)
      -> approved
```

- 三类资产规划并行执行，都是文本任务，不提交生图费用；
- 用户点击“生成资产图”才提交图片任务；
- 一个资产失败不影响其他资产成功结果；
- 没有确认全部必需资产时，分镜图按钮保持禁用并显示缺失项；
- 重新生成导演方案时优先复用稳定资产 ID，不重复创建同名资产。

## 5. Markdown 阅读与返回导航

### 5.1 中栏布局

- 删除 `v-if="false"` 遗留分镜列表及其 `v-else` 占位区；
- `WikiDocument` 在当前视图中占满可用高度，只有文档自身滚动；
- 右栏操作栏保持固定底部，不侵占中栏文档空间。

### 5.2 父级返回

`WikiDocument` 增加可选父级路径：

- 导演总览：显示当前项目分镜总表；
- 单镜页面：显示 `返回分镜总表`，点击回到 `wiki/分镜/导演总览.md`；
- 资产页面：显示 `返回资产总表`；
- 正向 Wiki 双链继续进入目标页面；
- 返回只改变阅读路径，不触发模型、文本或媒体任务；
- 编辑模式保存后仍停留在当前页面，保存冲突保留草稿。

不引入浏览器式历史栈；当前产品只需要一层父级关系，避免返回路径不可预测。

## 6. API Key 持久化

### 6.1 正式发布

- 正式 macOS 包必须使用 Developer ID 签名和公证；
- 继续使用 Electron `safeStorage`，Key 只保存于系统安全存储；
- 重启后由 `hasApiKey()` 验证并恢复状态；
- 不把 Key 写入 `state.json`、Wiki、日志、统计事件或明文文件。

### 6.2 未签名开发包

- `safeStorage.isEncryptionAvailable()` 为 false 时只允许会话内存使用；
- UI 必须明确显示“仅本次运行有效，重启后需重新输入”，不能提示“已永久保存”；
- 开发包不通过自制加密文件绕过系统安全存储；
- 发布验收必须分别测试：未签名包的会话提示、签名包的重启恢复。

## 7. 验收标准

1. 参数和文稿确认后，角色、场景、道具三个 Skill 同时启动；任一分支失败可单独重试。
2. 资产只存在 `character`、`scene`、`prop` 三类；品牌对象作为带强身份约束的道具。
3. 角色、场景、道具提示词分别由对应 Skill 产生，并在 Markdown 中记录 `generatedBySkill`。
4. 资产提示词不再逐资产串行等待；一个分支失败不回滚其他成功分支。
5. 只有真实配音时长和全部必需资产同时就绪后才可转分镜；导演只能绑定已有资产 ID。
6. UI 顺序固定为 `文稿/配音 -> 资产 -> 分镜 -> 分镜图/视频 -> 成片`，后端状态与前端按钮同步。
7. 分镜 Markdown 阅读区不再出现下半屏空占位内容。
8. 从导演总览进入任一镜头后，可以一键返回导演总览；编辑、保存、双链跳转均不触发付费任务。
9. 未签名开发包明确提示会话 Key；签名发布包重启后仍能读取 Key。
10. 真实项目验证覆盖：至少 10 个镜头、5 个资产、一次失败重试、一次 Markdown 编辑返回和一次 App 重启。

## 8. 实施顺序

1. 先修中栏残留占位与 Markdown 父级返回，降低阅读阻力。
2. 删除 `product` 和单核心资产兼容分支，把历史产品资产迁移为 `prop`，保留原图和版本。
3. 实现角色、场景、道具三路并行，资产确认后再运行导演，并保留本地汇合校验与 `generatedBySkill` 字段。
4. 完成签名发布链路和 API Key 重启验收。
5. 最后再把并行状态、失败项重试和来源显示接入右栏，不提前扩展新的工作区。

## 9. 明确不做

- 不让四个分支各自创建互相冲突的稳定 ID；稳定 ID 只由 App 汇合时确定；
- 不让角色/场景/道具 Skill 直接提交生图或视频任务；
- 不保留 `product` 类型、产品专用分支或单核心资产过渡流程；
- 不复制 `jiucaihezi-app` 的业务代码，不新增数据库和第二套状态机；
- 不为返回功能引入通用浏览器历史栈。
