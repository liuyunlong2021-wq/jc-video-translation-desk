# 未注册旧项目阻塞新建与打开

## 现象

升级到用户自选项目目录后，界面仍显示 Pinia/localStorage 缓存的旧 `runId`。点击“新建项目”或“打开已有项目”时，在系统目录对话框出现前报“项目位置未注册”。

## 根因

新建和打开入口会先调用 `saveCurrentProject()`；自动保存监听也只检查 `runId` 是否为空。旧 ID 不在 `media-projects.json` 注册表中，主进程的 `resolveProjectRoot()` 正确拒绝写入，但渲染进程因此无法继续进入新建或打开流程。

## 修复

- 渲染进程以当前项目列表判断 `runId` 是否已注册。
- `saveCurrentProject()` 只保存已注册项目。
- 深度状态监听只为已注册项目安排自动保存。
- 不增加旧 `media-runs` 兼容或迁移；未注册缓存状态只作为无效 UI 状态清除。

## 验证

合同回归覆盖显式保存和自动保存门禁；全量测试 `149/149`、TypeScript 类型检查、差异检查和 macOS universal 打包通过。桌面点击仍需用户在新包中复验。
