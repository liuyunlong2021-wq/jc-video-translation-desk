# 本地构建与发布

## 环境

- Node.js：项目要求 `>=22.17.0`。
- pnpm：项目锁定 `10.12.4`。
- Electron：`22.3.27`。
- FFmpeg：使用项目已安装的 `ffmpeg-static`，构建版从 `app.asar.unpacked` 解析。

## 常用命令

```bash
pnpm test
pnpm build
open release/1.2.2/mac-universal/点一点.app
```

`pnpm build` 会先执行 `build/scripts/clean-build.js`，删除 `dist/`、`dist-electron/` 和当前版本的 `release/<version>/`，再进行类型检查、Vite 构建和 Electron 打包。

## 数据位置

生成媒体不存放在仓库。用户选择或新建的空文件夹本身就是项目根，项目 Wiki、状态、输入、资产和媒体都位于该目录：

```text
<用户选择的项目根>/
  project.json
  shared-state.json
  episodes/
  assets/
  inputs/
  wiki/
```

Electron `userData` 只保留 `media-projects.json` 项目位置注册表、API Key、数据库、模型缓存和全局声音库。退出或替换应用包不应删除用户项目根；排障时也不应通过清理 `userData` 解决构建产物问题，避免丢失注册表和应用级配置。

## 启动规则

- 启动新包前完全退出旧 Electron 进程。
- 进程检查必须按 `short-video-factory` 或短视频工厂应用的完整路径过滤，避免影响同时运行的其他项目。
- Node 25 的历史 `localStorage` 兼容问题及测试入口处理见 [[排障/开发环境localStorage兼容问题]]。

## macOS 签名

本机发布证书若在 `codesign` 阶段返回 `errSecInternalComponent`，可先生成仅供本地验证的未签名包：

```bash
CSC_IDENTITY_AUTO_DISCOVERY=false pnpm build
```

该命令不会修改项目配置。正式分发仍应修复钥匙串或证书环境后执行普通 `pnpm build`。

## GitHub 推送经验

本机全局 Git 配置使用 `http.sslbackend=openssl` 时，`git push` 和 `git ls-remote` 可能在 75 秒后连接 GitHub 443 超时，而普通 `curl` 访问正常。已验证的一次性绕行命令为：

```bash
git -c http.sslbackend=secure-transport push origin main
```

该命令不修改全局配置。2026-07-30 使用它成功推送提交 `57c48b6`。

构建动态分块问题见 [[排障/构建产物与运行进程版本不一致]]。
