# 本地构建与发布

## 环境

- Node.js：项目要求 `>=22.17.0`。
- pnpm：项目锁定 `10.12.4`。
- Electron：`22.3.27`。
- FFmpeg / ffprobe：使用项目已安装的 `ffmpeg-static` 和 `ffprobe-static`，构建版从 `app.asar.unpacked` 解析，不依赖用户系统 PATH。
- uv：Windows 构建时由 `build/scripts/before-pack.js` 下载固定版本 `0.12.3`，校验 sha256 后按架构放入 `resources/runtime-tools/uv/<arch>/uv.exe`；一键安装优先使用随包 uv，再回退到系统 uv 或在线安装。

## 常用命令

```bash
pnpm test
pnpm build
open release-translation/1.2.2/mac-universal/视频翻译工作台.app
```

`pnpm build` 会先执行 `build/scripts/clean-build.js`，删除 `dist/`、`dist-electron/` 和当前版本的 `release-translation/<version>/`，再进行类型检查、Vite 构建和 Electron 打包。

Windows 安装包必须在 Windows 电脑或 GitHub Actions 的 `windows-latest` Runner 构建。不要在 Mac 上交叉构建 Windows 包；`ffmpeg-static` / `ffprobe-static` 按构建机系统安装，交叉构建会带入错误平台的媒体工具。Windows 包不内置 FunASR 和人声分离大模型，模型仍由用户点击“一键安装”后下载到系统应用数据目录。

## Windows 首装一键安装经验

Windows 首装目标是让用户下载 APP 后只点击“一键安装”，不需要理解 PATH、FFmpeg、ffprobe、uv、Python 或模型目录。实现边界为“小工具随包走，大模型一键下载”：

- 随安装包提供 `ffmpeg.exe`、`ffprobe.exe` 和按架构隔离的 `uv.exe`。
- 不把约 2 GB 的 FunASR、PyTorch 和人声分离模型打进安装包。
- 一键安装优先使用随包 `uv` 创建 Python 3.10 环境，再安装 FunASR / Sherpa-ONNX / SoundFile 并下载模型。
- 用户项目文件仍在用户选择的项目根；运行环境和模型仍在系统应用数据目录 `jc-video-translation-desk/`。

2026-08-11 Windows 首装修复的关键点：

- `electron/runtime-tools.ts` 统一解析 `ffmpeg`、`ffprobe` 和随包 `uv` 路径，业务代码不得裸调用系统 `ffmpeg` 或 `ffprobe`。
- `ffprobe-static` 已加入依赖，上传视频校验不再依赖用户系统 PATH。
- `build/scripts/before-pack.js` 在 Windows 构建时下载 Astral uv `0.12.3`，校验 sha256，并放入 `resources/runtime-tools/uv/<arch>/uv.exe`。
- `beforePack` 会校验 `ffmpeg-static` 与 `ffprobe-static` 的真实文件存在；`uv.exe` 已存在时也要执行 `uv --version` 验证版本，旧路径 `runtime-tools/uv/uv.exe` 会迁移到架构路径并删除。
- FunASR 模型状态检查必须匹配 `runtime/funasr/runtime.py` 的真实目录合同：`<model-root>/models/iic--.../snapshots/master`。
- `build/scripts/post-install.js` 不得在未配置镜像时传入 `FFMPEG_BINARIES_URL=undefined`。

Windows 发包 smoke check 必须至少执行：

```powershell
release-translation/1.2.2/win-unpacked/resources/runtime-tools/uv/x64/uv.exe --version
release-translation/1.2.2/win-unpacked/resources/app.asar.unpacked/node_modules/ffmpeg-static/ffmpeg.exe -version
release-translation/1.2.2/win-unpacked/resources/app.asar.unpacked/node_modules/ffprobe-static/bin/win32/x64/ffprobe.exe -version
```

2026-08-11 已验证输出包括 `uv 0.12.3`、`ffmpeg version 6.0-essentials_build-www.gyan.dev` 和 `ffprobe version 4.0.2`。构建产物 `视频翻译工作台-1.2.2-win-x64-setup.exe` 约 200 MB。

后续仍应补强但不阻塞当前 Windows 包发布的事项：

- 锁定 Windows 一键安装使用的 `torch` / `torchaudio` 版本和 CPU wheel 源。
- 为 `vocals.fp16.onnx` 与 `accompaniment.fp16.onnx` 增加大小或 sha256 校验，避免损坏文件只因存在就被判定为已安装。
- 增加“复制诊断报告 / 打开日志目录”，把安装失败分层翻译为网络失败、Python 环境创建失败、模型校验失败或安全软件拦截。

## 安装包平台规则

- macOS 默认产物为 `视频翻译工作台-<version>-mac-universal-installer.dmg`。Universal 包同时包含 `arm64` 与 `x64`，Apple M 系列和 Intel Mac 使用同一个 DMG，不需要分别发布。
- Windows 安装包只能在 Windows 电脑或 GitHub Actions `windows-latest` Runner 生成。
- Linux 安装包在 GitHub Actions `ubuntu-latest` Runner 生成。
- GitHub Release 从 `release-translation/<version>/` 上传 `.dmg`、`.exe`、`.deb`、`.rpm` 和 `.AppImage`，不得继续读取旧 `release/<version>/`。

## 数据位置

生成媒体不存放在仓库。用户选择或新建的空文件夹本身就是项目根，项目 Wiki、状态、输入、资产和媒体都位于该目录：

```text
<用户选择的项目根>/
  project.json
  shared-state.json
  episodes/
  assets/
  inputs/
  wiki/
```

Electron `userData` 统一位于系统应用数据目录下的 `jc-video-translation-desk/`，只保留 `media-projects.json` 项目位置注册表、API Key、数据库、FunASR 模型与环境和全局声音库。退出或替换应用包不应删除用户项目根；排障时也不应通过清理 `userData` 解决构建产物问题，避免丢失注册表和应用级配置。

首次切换到独立 APP 时，只从 `视频翻译工作台`、`短视频工厂`、`short-video-factory`、`AI Short Video Factory` 旧目录复制新目录缺失的项目注册表、API Key、SQLite、声音库和本地 TTS 数据。已有新数据不覆盖，旧目录不删除，便于回退。

FunASR 安装器、识别进程和 SQLite 都以 Electron 当前 `userData` 为准，避免模型、环境和数据库分别落入不同产品目录。

## macOS 签名

本机发布证书若在 `codesign` 阶段返回 `errSecInternalComponent`，可先生成仅供本地验证的未签名包：

```bash
CSC_IDENTITY_AUTO_DISCOVERY=false pnpm build
```

该命令不会修改项目配置。正式分发仍应修复钥匙串或证书环境后执行普通 `pnpm build`。

## GitHub 推送经验

本机全局 Git 配置使用 `http.sslbackend=openssl` 时，`git push` 和 `git ls-remote` 可能在 75 秒后连接 GitHub 443 超时，而普通 `curl` 访问正常。已验证的一次性绕行命令为：

```bash
git -c http.sslbackend=secure-transport push origin main
```

该命令不修改全局配置。2026-07-30 使用它成功推送提交 `57c48b6`。

构建动态分块问题见 [[排障/构建产物与运行进程版本不一致]]。
