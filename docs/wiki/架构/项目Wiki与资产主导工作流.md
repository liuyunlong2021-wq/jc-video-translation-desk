# 项目 Wiki 与资产主导工作流

> 当前产品主链。项目是 Wiki、状态、媒体和任务的唯一所有权边界。

## 制作主链

```text
创建项目并确认文稿
  -> 角色、场景、道具 Skill 分别生成资产设计 JSON
  -> 可选搜索或上传参考图
  -> 生成资产图
  -> 导演分镜绑定稳定资产 ID
  -> 生成分镜图和分镜视频
  -> 逐镜分析、剪辑、配音、混音和字幕
  -> 最终成片
```

“产品”不再是独立资产类型。品牌商品、手机、眼镜等统一归入道具，资产集合固定为角色、场景、道具。

## 两类事实

- 结构化项目状态、稳定 ID 和媒体路径是执行事实来源。
- Markdown 是面向用户的可读投影，负责阅读、编辑、审阅和双链导航，不代替运行状态。
- `projectId`、项目 Wiki、资产版本、媒体任务和最终产物必须同属一个项目；切换项目不能串入其他项目的数据或锁。

## 项目位置与路径事实源

- 新项目根目录由用户选择或新建，所选空文件夹本身直接成为项目根，不再追加日期子目录；目录名是初始显示名，稳定 `projectId` 不因修改显示名或移动目录而改变。
- 应用级 `media-projects.json` 是 `projectId -> rootPath` 的唯一事实源；项目内 `project.json` 是该目录身份和结构版本的事实源，两者 ID 不一致时拒绝打开。
- Wiki、状态、输入、资产、任务和媒体全部位于项目根；项目文件只保存相对路径，不写用户机器的绝对目录。
- Wiki 读写、媒体协议、导出预览、任务恢复、FFmpeg 和声音库项目反链统一调用 `resolveProjectRoot(projectId)`。
- 用户移动目录后使用“打开已有项目目录”重新注册。开发期不扫描、不迁移、不兼容旧 `media-runs` 测试项目。

新建项目曾误把所选目录当成父目录并追加日期子目录，其根因和回归见 [[../排障/新建项目误建日期子目录]]。

## 资产合同

资产设计 JSON 是生图模型的正式合同，不使用额外的简化提示词替代它。JSON 至少完整包含项目画风、画面比例、资产类型和资产本身的设计要求。

```text
生成资产设计 JSON
  -> 可选搜索参考图或上传用户图片
  -> 将 JSON 与当前参考图集合共同提交图像模型
  -> 保存 AI 图为新的资产版本
```

每个版本的来源固定为搜索、上传或 AI 生成；来源不决定用途。`activeVersionId` 独立指定“当前使用图”，因此搜索图、上传图和 AI 图都可以不经再次付费生成而直接进入下游。未激活的版本仍可作为生成参考或历史版本；参考图只补充视觉约束，不改写设计 JSON。

## 增量与版本规则

- 必需资产只有在 `activeVersionId` 指向现存版本时才正式就绪，不再要求必须存在 AI 生成图。
- 批量生成只扫描需要 AI 图且尚未生成的资产，不重复生成已完成项。
- 后续分镜新增资产后，用户可以回到资产阶段补齐；已有结果不能阻塞新增项。
- 任意来源版本都可设为当前使用图；切换时只使引用该资产的下游媒体失效，不删除旧版本或其他资产结果。
- 删除不满意的未激活参考图后可以重新搜索；删除当前版本前必须先切换或让资产回到待确认状态。
- 资产图、分镜图和视频均应保留版本、支持预览、单项重试和精确下游失效。
- 中栏显示“已就绪”时，该资产的就绪状态必须成为下游判断依据，不能因切换视图退回参考图状态。
