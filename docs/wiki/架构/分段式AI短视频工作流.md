# 分段式 AI 短视频工作流

## 目标

第一版采用“单核心参考资产 + 单镜头分段”的媒体编排方式。每个视频片段只包含一个连续镜头，最终由本地 FFmpeg 拼接并覆盖为统一配音。该设计优先保证可测试、可重试、主体一致和声音一致，而不是一次调用生成整条片子。

## 用户与数据流

```text
用户诉求
  -> 文稿生成并确认
  -> 声音方案（人设、音色特征、风格、情感、节奏）
  -> 选择云端或本地 VoiceDesign，生成统一配音并读取真实时长
  -> 按真实时长生成分镜计划，用户在右栏逐镜检查和编辑提示词
  -> 每段生成一张分镜图
  -> 每张图生成一条单镜头视频
  -> FFmpeg 丢弃片段原声、拼接画面、加入统一配音
  -> 最终成片
```

付费步骤均由用户分段触发，所有结果进入中栏素材库。失败后只重试未成功的分段，不重新提交已经成功的付费任务。

## 固定能力合同

| 阶段 | 模型或能力 | 关键约束 |
|---|---|---|
| 文稿与 Skill 执行 | `gemini-3.6-flash` | Skill 输出必须是 JSON；解析失败时只修正重试一次 |
| 声音设计 | 云端 `rh-aiapp-voice-design` 或本地 `Qwen3-TTS-12Hz-1.7B-VoiceDesign` | 业务输入只有文稿与五项声音提示词，不传语言字段；本地模式不自动降级到云端 |
| 分镜图 | `gpt-image-2` | 无参考图走 `/v1/images/generations`；有参考图走 `/v1/images/edits` multipart |
| 分镜视频 | `veo-3.1-generate-preview` | 图生视频；仅 `9:16`、`16:9`；时长仅 4、6、8 秒 |
| 最终合成 | 本地 FFmpeg | 画面按配音时长裁切或补帧，最终只保留统一配音 |

API 固定为 `https://api.jiucaihezi.studio/v1`，界面不要求用户填写模型名。视频创建提交到 `/v1/videos`，异步任务轮询 `/v1/video/generations/<taskId>`。

## 本地配音

- 设置中可选“云端”或“本地”，默认使用云端，选择会随任务状态持久化。
- 本地模式仅支持 Apple Silicon macOS，需要独立的 MLX Audio Python 运行时和 `mlx-community/Qwen3-TTS-12Hz-1.7B-VoiceDesign-bf16` 模型缓存。
- 五项声音设计提示词直接作为本地模型的 `instruct`，生成结果写入当前任务目录并进入素材库，后续合成流程不区分云端或本地来源。
- APP 安装包不内置 Python 运行时和模型。环境缺失时明确报错，不自动调用云端，避免产生非预期费用。

## 时长规则

- 文稿阶段按约 200 个汉字/分钟做预估，仅用于目标控制。
- 配音生成后，程序根据真实音频时长和节奏档位计算参考镜头数，导演 Skill 再按叙事节拍决定最终镜头数。
- 每段 `playDuration` 是成片时间线长度；`generationDuration` 只能取覆盖该片段所需的最小时长 4、6 或 8 秒。
- 单段超过 8 秒时必须增加分段，不能请求模型生成非法时长。
- 镜头数量不再固定为公式结果；自动、慢、中、快节奏与程序估算值只提供参考，具体长镜、标准推进和蒙太奇拆镜由导演 Skill 决定，详见 [[架构/Veo3.1能力边界与镜头节奏]]。
- 程序把 `referenceShotCount` 传给导演 Skill；图片 Skill 原样继承导演实际输出的镜头数。任一层输出违反时长、全文覆盖或单镜头合同时，携带具体校验错误自动修正一次，再失败才终止。

## 单核心参考资产

- 用户可上传一张 PNG、JPEG 或 WebP，最大 20 MB。
- 参考图先复制到当前任务的 `inputs/`，后续接口只接收受控任务目录中的文件。
- 只有需要核心主体出现的分镜才传参考图；其他场景不强行绑定角色、场景和道具一致性。
- 第一版不使用多宫格、卷轴或单图多镜头，因为 Veo 3.1 当前按单一连续镜头合同执行。

## 任务状态与持久化

状态依次为 `draft`、`script-generated`、`script-approved`、`voice-plan-ready`、`voice-ready`、`shot-plan-ready`、`storyboards-ready`、`videos-ready`、`completed`。

任务素材位于 Electron `userData/media-runs/<runId>/`：

```text
inputs/
storyboards/
clips/
voice.mp3
final.mp4
state.json
run.json
```

状态保存使用临时文件后原子重命名；持久化只记录任务内相对路径。`run.json` 保存当前项目的媒体任务账本，但不保存 API Key。重新打开应用时恢复最近一次有效 `state.json`，旧任务只显示为可恢复状态；用户必须显式点击“继续查询”或“继续下载”，应用不会自动执行。

## 下游失效原则

- 改文稿：声音、分镜图、视频和成片全部失效。
- 改声音：分镜计划、图片、视频和成片失效，但已生成音频可按动作边界保留。
- 编辑声音提示词：当前配音和全部视觉链路失效，旧文件保留在磁盘。
- 编辑全局一致性或某镜分镜图提示词：对应图片、视频和成片失效。
- 编辑某镜视频提示词：对应视频和成片失效，已生成图片保留。
- 改风格或核心参考图：只让视觉链路失效，保留文稿和配音。
- 重生成图片：对应视频和最终成片失效。
- 重生成视频：只让最终成片失效。
