## 当前结论

- 新项目不再写入隐藏的 `userData/media-runs`：用户选择或新建的空文件夹本身直接成为项目根，文件夹名就是初始项目名，不再追加“新项目-日期”子目录。应用级 `media-projects.json` 保存稳定 `projectId -> rootPath`，项目内 `project.json` 保存目录身份。旧测试项目不迁移、不兼容。
- 启动时若 Pinia/localStorage 留有未注册旧项目 ID，必须先清空无效状态；新建、打开和自动保存均不得向该 ID 调用 `cloud-save-state`。
- 所有项目内 JSON、Markdown 和媒体引用使用项目相对路径；Wiki、任务、媒体协议、FFmpeg、导出和声音库反链统一通过 `resolveProjectRoot(projectId)` 定位。
- 资产版本的来源与用途已经分离：搜索、上传、AI 生成是三种来源；`activeVersionId` 是唯一当前使用图。任意来源版本都能直接采用，没有当前使用版本时不能进入正式下游。

- 项目总监在声音生成、资产和分镜之前确认内容类型 `narration-promo` 或 `drama`；声音制作路线默认 `seed-full-track`，用户明确选择后才改为 `post-dub`。
- 内容类型与声音路线都确认后才开放下游；两者分别写入项目总监和制作路线 Wiki。
- 创作项目确认路线时先写 `wiki/项目/项目总监.md` 和 `wiki/项目/制作路线.md` 双链页面，再暴露确认状态。
- `seed-full-track` 固定顺序为项目总监、视觉资产、全局配音工作台逐角色选择/绑定参考音、生成角色音色提示词、生成角色参考音、整段配音安排、全局声音提示词、可编辑豆包语音稿、Seed 完整声音轨、Faster-Whisper 真实声音时间轴，再进入画面分镜；视频原生声音照常生成，后期默认采用 Seed 轨。
- `post-dub` 保持现有先生成视频、再用 IndexTTS2/Qwen3-TTS 逐句后配的流程。
- VEO/Grok 的视频提示词不再硬编码“禁止生成人声”或“无背景音乐”；两者按原提示词正常生成画面和原生声音，最终采用哪条音轨由后期声音策略决定。
- Seed 路线的角色声音操作从资产页移到资产之后的全局配音工作台；角色声音身份仍以 `speakerId -> voiceProfileId` 写入 Wiki。`post-dub` 路线在 `editing-timeline.json` 就绪后，由用户点击“生成中文配音”才调用 IndexTTS2/Qwen3-TTS。
- 每条原始视频先由 Faster-Whisper 生成素材 SRT；`gemini-3.6-flash` 再读取原视频、确认剧本/文稿、完整分镜提示词和 SRT，直接输出角色身份、动作和准确剪辑点。
- 不使用 Sherpa 说话人聚类。Sherpa-ONNX 只参与按需执行的 Spleeter 人声分离链路。
- 全部视频素材完成后即可进入配音字幕工作台查看原视频、六列表格和逐行时间轴滑块；右栏只保留七个动作按钮，后端音频模式与输出语言由已执行动作自动推导。
- 顶部七阶段为：文稿、资产、分镜、分镜图、视频、配音字幕、成片。“烧录配音和字幕”就是生成成片。
- `rh-grok-image-video` 已真实验证九宫格分镜板、多图参考、人物/动物一致性和片内切镜；官方 `6-30` 秒合同保留，但不是全部时长逐档实测结论。
- 已确认 TDD-11：「点一点」在“文稿”阶段增加项目级“文字创作 / 视频反推”来源路线，不开发独立 App、窗口或第二套 Store/Wiki。
- 视频反推复用应用自身 Faster-Whisper、`gemini-3.6-flash`、项目/剧集边界和 Markdown 文稿编辑器；产物先进入文稿人工确认，确认后才与 Seed Audio / 逐句后配和现有下游合流。
- 项目输入模式由所有剧集继承；每集原片、Whisper/Gemini 证据、`final-timeline.json`、草稿和确认文稿必须按 `episodeId` 隔离。
- TDD-10 已接通原代码主链；新确认将 Skill 调用从“生成完整声音轨”内部拆为独立“生成豆包语音稿”，中栏编辑 `声音导演稿.md` 后再提交 Seed Audio。该节点尚待代码执行，详见 [[开发/Seed Audio声音优先路线]]。
