## 当前结论

旧的“压缩视频、全片多模态理解、切片、逐片扒片”字幕路线已经退出。现行字幕主链只处理声音和 SRT：FFmpeg 提取整轨音频，FunASR 生成固定时间戳和原始文字，用户按需使用中点抽帧与整集语义校准，最终以人工确认稿翻译。

真实样片已确认：FunASR 时间戳可直接采用；按真实字词时间戳拆分过长字幕后显示效果成功；中点抽帧读取原片画面字幕能显著修正嘈杂音乐、含混台词造成的文字错误。画面人物聚类在本次样片中明显比声音聚类更接近真实角色数量，因此角色工作流采用“画面优先、声音兜底、人工最终确认”。完整英文配音也已验证可以由 FunASR 整块识别，再将确认英文稿与英文词级时间按顺序对齐后剪句；自动测试覆盖 FunASR 把一句拆成多个识别 cue 的情况。

现行执行合同以 [视频翻译工作台“识别字幕”执行流程](../../视频翻译工作台-扒片按钮执行流程.md) 为准。TDD-13 与本页后文旧切片路线只保留历史追溯，不再作为字幕识别实现依据。

## 现行已跑通主链

```text
上传或更换识别视频
-> FFmpeg 提取 16 kHz 单声道 WAV
-> FunASR 整轨识别声音、时间戳、匿名说话人和情绪候选
-> 程序只按真实字词时间戳拆分过长字幕
-> 保留不可变 FunASR 原文，生成可手工编辑的人工确认稿
-> 按需对每条 cue 的时间中点抽一帧
-> 同一次画面模型调用给出字幕文字建议和 visual-person-N 聚类
-> 按需让大模型结合 FunASR、画面建议和整集上下文进行语义校准
-> 人工应用建议、撤销、恢复原文或直接手写
-> 以人工确认稿翻译，时间戳始终不变
-> 人工复核后进入配音工作台
```

## 2026-08-09 已验证的成功经验

- 时间轴与文字分权：FunASR 提供时间锚点，抽帧和语义模型只提供文字建议，不允许模型返回或改写时间戳、cue 数量、ID 和顺序。
- 原始证据与工作稿分权：`recognizedText` 永久保存 FunASR 原文；`frameSuggestion` 和 `calibrationSuggestion` 是可选辅助；`sourceText` 人工确认稿是翻译的唯一正文来源。
- 辅助功能不设门禁：只要人工确认稿非空，就能直接翻译；用户可以完全不用抽帧或语义校准，也可以只用其中一个。
- 一帧承担两项任务：每条 cue 只抽 `(startMs + endMs) / 2` 的一张中点帧，同一批图片同时读取画面字幕和聚类画面人物，没有新增第二轮抽帧或全片多模态分析。
- 画面人物与声音人物必须独立编号：`visual-person-N` 不能冒充 `speaker-N`，两者最终都只能绑定到产品自己的 `translationRoleId`。
- 角色选择采用画面优先：完成抽帧校准后，单人画面的候选、新建角色默认名和自动绑定使用“画面人物 N”；多人、无人或遮挡画面不猜，交给人工；未做画面校准时才回退声音候选。
- 单条和批量修改显式分开：角色下拉默认只改当前 cue；用户主动勾选“相同声音”或“相同画面人物”才批量应用，并显示影响条数。
- 用户界面只展示决策所需证据：一张实际中点帧、“声音人物 N”和“画面人物 N”；人物外观特征只作为模型内部聚类依据，不展示英文内部 ID 或“疑似人物”结论。
- 翻译使用整集上下文，不做孤立逐句直译。英语目标明确面向美国观众，要求当代美式影视口语、人物身份与情绪一致、对白适合原时间窗阅读和配音，同时禁止编造、遗漏、合并或拆分 cue。
- 角色变化不删除已有译文，只把译文标记为需要复核；人工确认稿变化才使旧译文失效。
- 抽帧单次最多处理 30 条 cue，并在提图和模型调用前拒绝超限任务，避免长视频内存和请求体风险。
- 真实样片结果：用户确认字幕拆分成功、时间戳满意、抽帧文字校准效果“出奇地好”；同一样片的画面人物聚类明显比声音聚类更接近实际三名角色。

## 整段配音对齐经验

成功方案：完整配音块只识别一次，不再预先切成固定 10 秒小片，也不再把音频交给多模态模型猜 `cueId`。FunASR 返回英文词级时间后，程序将确认英文台词和识别词流做字符级单调匹配：cue 顺序固定，首个匹配词确定开始，最后一个匹配词确定结束，再从原始高质量配音块用 FFmpeg 裁句。这样保留整段 Seed 的连续表演，同时避免逐句生成造成的断裂。

失败经验：旧的“固定小片 + 模型猜每片属于哪句”会在切片边界重复识别、漏掉尾部或把一句截成只有前几个音；不能作为整段配音对齐方案。把音频转成视频/图片再截帧也不会增加声音时间信息，不能解决英文发音与字幕的对应问题。

边界经验：极短的 `Mm.`、`Uh.` 等语气词可能没有可用识别词，程序保留前后真实词之间的完整声音区间；有识别词但文本匹配低于阈值时必须阻止进入成片并提示人工确认。当前仍需留意相邻 cue 的防截尾余量可能带来尾词重复，后续只能收紧相邻边界，不能回退到固定切片。

## 安装部署经验

FunASR 的 Python 环境和模型不提交仓库，也不包含在 DMG/安装包中。首次安装必须在源码目录执行 `pnpm setup:funasr`，该脚本会锁定 FunASR 提交、创建独立 Python 3.10 环境、安装依赖、下载模型并运行真实探针。Apple Silicon 已完成真实验证；Intel Mac 和 Windows 仍需在干净机器完成首装验收。README 已按 M 系列 Mac、Intel Mac 和 Windows 分成逐步的小白安装流程。

## 历史成功经验（旧切片路线，不再执行）

- 上传与处理分离：上传只归档原片；压缩、模型调用和切片只在用户点击“扒片”后发生。
- 原片与分析片分工明确：小文件直接分析，大文件生成较小分析副本；Gemini 全片分析和 FFmpeg 复核切片读取同一个分析视频，最终成片始终读取原片。
- 云端与本地阶段分开：Gemini、翻译模型和 Seed Audio 是可失败、可重试的云端任务；FFmpeg 切片、混音和烧录是本地任务，不能用云端错误描述本地阶段。
- 扒片保持简单：全片剧情与切点、FFmpeg 实际切片、Gemini 逐片台词、程序最终稿四阶段足够，不再叠加无效的多轮模型互审。
- 每阶段均有 Markdown 证据：`01-整体分析与切片方案.md`、`02-FFmpeg切片.md`、`03-Gemini逐片台词.md`、`04-最终稿.md` 形成可追溯链；JSON 只承担程序状态和执行合同。
- 字幕排版由程序决定：标点后强制形成新 cue，中日韩约 15 字、其他语言约 40 字，每行保留连续时间戳，不把换行交给模型自由发挥。
- 翻译角色库按项目跨集复用，但角色、声音、剧集产物和执行状态均留在 `wiki/翻译/` 与翻译媒体沙箱，不写回创作工作流。
- 声音身份只使用产品自己的 `translationRoleId` 和 `voiceProfileId`。正式配音请求直接携带当前参考音文件，并使用 `voiceProfileId` 完成参考音与 `@音频N` 的确定性映射。
- 英语配音稿采用“中文导演说明 + 英文正式对白”：用户能读懂并修改情绪、强度、语速和停顿，英文台词仍逐字保留。
- 大任务必须显示阶段进度、持续生成文档并支持失败后续跑；已完成的本地和云端产物不重复执行。
