# AI 媒体工作流可复用经验

## 1. 按模型真实能力设计工作流

模型分类比内容用途分类更稳定。Veo 3.1 当前适合“一张图 -> 一个连续镜头”，因此第一版不强迫它解析卷轴、多宫格或单图多镜头。未来换回真正支持多镜头参考图的模型时，再启用卷轴工作流。

## 2. 一致性先收敛到一个核心资产

角色、场景、道具全套资产会显著增加交互和状态复杂度。第一版只保证一个产品或主体参考图的一致性，已经能覆盖产品营销、科普、演示和多种视觉风格；只有业务明确需要连续角色或固定场景时，才扩展资产系统。

## 3. 先生成配音，再按真实时长分镜

按字数估时适合约束文稿，不适合最终时间线。具有情感和节奏的 TTS 会改变真实时长，所以分镜数量、每段播放时长和最终成片长度都应以生成后的音频元数据为准。

## 4. 模型时长和成片时长必须分开

`generationDuration` 是模型允许的 4、6、8 秒离散值；`playDuration` 是最终时间线实际使用的长度。选择覆盖播放长度的最小模型时长，再在 FFmpeg 阶段裁切或补末帧，能避免非法请求和不必要成本。

## 5. 声音统一应在合成层完成

提示词要求“无背景音乐”能减少干扰，但不能作为唯一保证。最终 FFmpeg 合成显式丢弃片段原声，只映射统一配音音轨，才能确保人物声线、音量和节奏一致。

## 6. 付费生成与结果下载要分离

生成接口成功、结果下载失败时，必须持久化任务 ID 或结果 URL。重试应继续轮询或下载，不能再次提交付费生成。成功分段也必须从批量重试集合中排除。

## 7. 媒体文件由应用托管

上传的参考图先复制进任务目录，生成结果也写入同一受控目录。IPC 只允许访问当前 `runId` 下的资产，并持久化相对路径，可同时解决恢复、迁移和任意文件访问风险。

## 8. 素材库是工作流的可观察面

音频、分镜图、视频和最终成片都应立即进入中栏素材库。紧凑缩略图、分类筛选、弹窗预览和单项重生成，比把所有媒体堆成大卡片更适合逐阶段测试和定位问题。
