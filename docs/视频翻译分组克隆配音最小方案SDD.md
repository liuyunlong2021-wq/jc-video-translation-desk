# 视频翻译“分组克隆配音”最小方案 SDD

> 状态：待确认，确认后实施  
> 原则：精准、简单、直接、有效；复用现有配音版本、批量并发、任务抽屉和成片流程。

## 1. 目标

在现有“全局配音”之外增加一条“分组克隆”路线：

```text
人工确认字幕 + 已确认角色参考音
-> 手动确定配音分组
-> 从全局配音提示词拆出每个分组的三段式提示词
-> 批量并发生成分组音频
-> 按原时间戳进入成片工作台
```

分组只决定哪些台词连续生成一段音频，不改变字幕本身。

## 2. 分组提示词唯一格式

每个分组只允许一个角色和一个参考音。提示词严格由三部分组成：

```text
这是一段时长为{整数秒}秒的配音表演艺术家在顶级录音棚内的配音片段。

{角色名}是{角色声音身份}，饰演者为@音频1。

{角色名}（{本句情绪/表演方向}）：“{正式译文}”
{角色名}（{本句情绪/表演方向}）：“{正式译文}”
```

提炼规则固定如下：

1. 第一段只写分组时长。时长取该组第一条字幕开始时间到最后一条字幕结束时间，四舍五入为整数秒，最小为 1 秒。
2. 第二段只写当前角色已确认的声音身份，并固定绑定为 `@音频1`。
3. 第三段按字幕顺序逐行写出台词；括号内使用全局配音提示词中对应句的情绪/表演方向，引号内使用人工确认的正式译文。
4. 正式译文必须逐字保留，不增加、删除、改写、合并或拆分。
5. 不添加全局表演要求、剧情总结、上下文说明、时间戳、音效、参数或其他提示语。

全局提示词到分组提示词不再次调用模型。程序先按现有规则校验全局提示词中的角色、台词数量、顺序和正式译文，再按行映射回对应 `cueId`，直接提取括号内的表演方向。全局提示词缺句、乱序或改写正式译文时停止生成并提示修正，不能猜测匹配。

示例：

```text
这是一段时长为10秒的配音表演艺术家在顶级录音棚内的配音片段。

风千雪是女性白富美千金大小姐，饰演者为@音频1。

风千雪（借着酒劲当众爆发，咬着对方名字，声音因愤怒发抖，破折号处被情绪噎住）：“Si, how dare you cheat on me and betray me!”
风千雪（话头被自己的怒气打断，急促吸气，语气里全是怨怼）：“If my dad hadn’t forced me to marry you,”
风千雪（冷笑一声反问，语气轻蔑，give a damn 刻意重读）：“you think I give a damn about you?”
```

## 3. 字幕分组规则

字幕工作台只增加两项操作：

```text
与下一条组成配音组
从配音组拆出
```

- 只允许相邻且角色相同的字幕组成一组。
- 未分组的单条字幕自动视为一个配音组。
- 分组后，字幕原文、译文、顺序、开始时间和结束时间全部不变。
- 分组音频从组内第一条字幕的开始时间放置，目标时长为整组时间范围。
- 配音分组在确认最终时间戳剧本时一并冻结；修改分组后，旧的分组提示词、分组音频和成片状态自动失效。

数据上只给字幕增加可选的 `dubbingGroupId`。连续字幕的 `dubbingGroupId` 相同即属于同一组；不再建立第二套分组数据结构。

## 4. 工作台 UI 与序号

分组克隆复用字幕工作台和成片工作台现有的“视频预览 + 时间轴表格 + 右侧操作区”，不复制一套新的工作台 UI。

三个工作台统一增加显示序号：

```text
字幕工作台：#07
分组克隆：组03 · 字幕07-09
成片工作台：#07
```

- 序号只用于界面查看和沟通，按当前时间顺序动态计算，不写入项目数据。
- `cueId` 仍是字幕跨工作台流转的唯一身份，时间戳仍是音画放置依据。
- 拆分、合并或调整字幕后可以重新编号，但不能因此改变 `cueId` 对应的数据。

分组克隆表格固定显示：

```text
组号 | 时间轴 | 角色 | 包含字幕 | 目标时长 | 生成状态 | 试听
```

点击一行后，右侧显示该组的三段式提示词和单组操作。

## 5. 配音工作台

配音工作台页签调整为：

```text
角色声音 | 全局配音 | 分组克隆
```

“分组克隆”页只显示：

- 分组列表：组号、角色、字幕数量、目标时长、生成状态。
- 当前组选中后显示三段式提示词，可人工修改。
- `批量生成全部分组`。
- 单组的试听和 `重新生成`。

不提供自动分组、时间轴编辑器或其他生成策略。

## 6. 批量并发与历史进度

点击 `批量生成全部分组` 后，每个分组作为一个独立任务进入现有批量并发流程：

```text
排队中 -> 生成中 -> 已完成
                  -> 生成失败
```

- 并发数量沿用现有批量生成配置，不新增队列框架。
- 一个分组失败不影响其他分组继续生成。
- 右上角现有“任务/历史记录”抽屉逐组显示进度、角色、组号和错误原因。
- 失败项提供 `重新生成`，只重新提交该分组。
- 已完成项可单独试听；重新生成成功后替换该组当前采用音频，历史任务仍保留。

## 7. 与成片工作台衔接

- 分组继续使用现有配音版本中的 `blocks[].cueIds`、音频路径和生成清单。
- 每个分组生成成功后，直接成为当前配音版本中的一个音频块。
- 全局配音继续使用现有的 FunASR 逐句对齐流程。
- 分组克隆不得把组音频重新逐句识别、切割或分别放置；成片时直接把完整组音频放到组内第一条字幕的开始时间。
- 字幕仍按每条原时间戳独立烧录，不随配音组改变。
- 生成音频超过目标时长时不得强制裁掉结尾；界面显示超时时长，并允许用户单独重新生成该组。
- “进入成片工作台”从“角色声音”页移除，放到“全局配音”和“分组克隆”共用的配音完成区域；当前采用路线完整后才可点击。

衔接依据固定为：

```text
cueId：保证字幕、提示词、配音组和成片使用同一句对白
scriptHash：保证使用同一份已冻结字幕和分组关系
组内第一条 startMs：决定完整组音频的放置位置
每条字幕 startMs/endMs：决定字幕独立显示时间
```

## 8. 明确不做

- 不增加“全局表演要求”。
- 不让模型重新分析或改写正式译文。
- 不做自动分组、智能分组或跨角色分组。
- 不做新的任务中心、队列系统或数据库。
- 不在本轮增加字幕时间轴编辑和多种时长处理策略。
- 不对分组音频做逐句切割、自动变速或强制裁剪。

## 9. 验收标准

1. 字幕工作台、分组克隆和成片工作台显示一致的字幕序号，序号变化不影响 `cueId`。
2. 多条相邻同角色字幕能组成一个配音组，字幕内容和时间戳保持不变。
3. 每组提示词由已校验的全局提示词按 `cueId` 顺序直接提取，严格符合三段式格式。
4. 全部分组可一次批量提交并并发生成。
5. 右上角任务抽屉能逐组显示排队、生成、成功和失败状态。
6. 任一失败或超时分组可单独重新生成，不影响已成功分组。
7. 分组音频在成片阶段保持完整，只从组内第一条字幕开始时间放置，不重新逐句切割。
8. 字幕仍按原时间戳逐条烧录，分组操作不改变字幕显示。
