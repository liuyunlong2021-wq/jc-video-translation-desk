# 视频翻译工作台“扒片”按钮执行流程

## 1. 入口与前置条件

用户在“字幕工作台”点击右栏的 `扒片` 按钮。

执行前必须满足：

- 已打开项目和剧集。
- 已上传识别视频，状态字段为 `sourceVideoPath`。
- 识别视频必须属于当前项目当前剧集的视频翻译目录。
- 识别视频必须包含可读取的音频流。
- 本机 FFmpeg、Spleeter 运行环境和 Faster-Whisper 模型可用。
- 已配置可访问 `https://api.jiucaihezi.studio/v1` 的 API Key。

按钮调用链：

```text
字幕工作台“扒片”
-> reverseTranslationVideo()
-> Electron preload / IPC
-> identifyVideoTranslationSpeakers()
-> 五阶段扒片
-> 返回字幕、角色候选和证据
-> 写入字幕工作台
```

## 2. 精确执行顺序

### 第 1 步：本机 FFmpeg 提取音频

| 项目 | 内容 |
| --- | --- |
| 执行位置 | 用户本机 |
| 软件 | FFmpeg；优先使用环境变量 `FFMPEG_PATH`，否则调用系统命令 `ffmpeg` |
| 输入 | 当前剧集的识别视频 `episodes/<episodeId>/video-translate/source.<ext>` |
| 动作 | 从识别视频提取完整音频，转换为 44.1kHz、双声道、16-bit PCM WAV |
| 输出 | `wiki/翻译/<episodeId>/识别/source.wav` |

实际参数核心部分：

```text
-vn -acodec pcm_s16le -ar 44100 -ac 2
```

这一步不调用云端模型。

### 第 2 步：本机 Spleeter 分离人声与背景声

| 项目 | 内容 |
| --- | --- |
| 执行位置 | 用户本机 |
| 软件 | `peiyin-pyvideotrans` Python 虚拟环境中的 Spleeter 分离模块 |
| 默认项目目录 | `/Users/by3/Documents/peiyin-pyvideotrans` |
| 默认 Python | `/Users/by3/Documents/peiyin-pyvideotrans/.venv/bin/python` |
| 实际模块 | `videotrans.process._audio_separate.vocal_bgm_spleeter` |
| 输入 | `source.wav` |
| 动作 | 将完整音频分离为人声 stem 和非人声 stem |
| 输出 | `vocal.wav`、`instrument.wav` |

固定输出路径：

```text
wiki/翻译/<episodeId>/识别/vocal.wav
wiki/翻译/<episodeId>/识别/instrument.wav
```

可通过以下环境变量替换默认运行环境：

```text
PEIYIN_PYVIDEOTRANS_ROOT
PEIYIN_PYVIDEOTRANS_PYTHON
```

这一步不调用云端模型。`instrument.wav` 在扒片阶段只作为已分离的背景声文件保存，不参与字幕文字裁决。

### 第 3 步：本机 Faster-Whisper 生成人声时间证据

| 项目 | 内容 |
| --- | --- |
| 执行位置 | 用户本机 CPU |
| 软件 | Faster-Whisper |
| 模型 | `large-v3-turbo` |
| 默认模型目录 | `/Users/by3/Documents/peiyin-pyvideotrans/models/models--mobiuslabsgmbh--faster-whisper-large-v3-turbo` |
| 输入 | Spleeter 输出的 `vocal.wav` |
| 动作 | 识别人声内容、语音区间和词级时间戳 |
| 输出 | Whisper JSON、SRT 和人声证据 Markdown |

主要识别参数：

```text
device=cpu
compute_type=int8
beam_size=5
best_of=5
condition_on_previous_text=false
vad_filter=true
word_timestamps=true
```

固定输出：

```text
wiki/翻译/<episodeId>/识别/source-whisper.json
wiki/翻译/<episodeId>/识别/source-whisper.srt
wiki/翻译/<episodeId>/00-人声识别与漏句证据.md
```

`source-whisper.json` 同时记录识别视频 SHA-256 指纹。再次点击 `扒片` 时，如果视频指纹相同且全部证据文件有效，直接复用，不重新运行 FFmpeg、Spleeter 和 Faster-Whisper。

Whisper 在本流程中的职责只有：

- 提供哪里存在人声的时间证据。
- 帮助发现短句和可能被音乐遮盖的对白。
- 在 Gemini 漏掉有声区间时提供候选文字。

Whisper 文字不是正式字幕，不会直接覆盖最终原文。

### 第 4 步：本机 FFmpeg 准备模型分析视频

| 项目 | 内容 |
| --- | --- |
| 执行位置 | 用户本机 |
| 软件 | FFmpeg |
| 输入 | 当前剧集识别视频 |
| 动作 | 根据文件大小决定直接使用原视频，或生成供 Gemini 分析的压缩视频 |
| 输出 | 原识别视频路径，或 `analysis.mp4` |

规则：

- 识别视频不超过 20 MiB：直接作为模型分析视频，不重新编码。
- 识别视频超过 20 MiB：生成 `episodes/<episodeId>/video-translate/analysis.mp4`。
- 压缩目标为 12 MiB，最终不得超过 20 MiB。
- 视频最长边宽度限制为 1280，保持原始宽高比。
- 视频使用 H.264，音频使用 64kbps 单声道 AAC。
- 最多根据实际文件大小重新计算码率并尝试三次。
- 不覆盖识别视频。

后续“全片分析”和“实际切片”必须使用同一个模型分析视频。

### 第 5 步：云端 Gemini 完整观看视频并规划切片

| 项目 | 内容 |
| --- | --- |
| 执行位置 | 韭菜盒子云端模型接口 |
| API | `https://api.jiucaihezi.studio/v1` |
| 模型 | `gemini-3.6-flash`，代码固定指定，不使用界面当前文本模型 |
| 输入 | 模型分析视频、Whisper 语音区间、已有翻译角色、项目上下文 Markdown |
| 动作 | 完整理解剧情、人物、关系、称谓、场景和节奏，并规划连续 FFmpeg 切片 |
| 输出 | `01-整体分析与切片方案.md` |

Gemini 此时只负责：

- 生成全片剧情理解。
- 选择自然的剧情、镜头或对白间隙作为切点。
- 输出每个切片的开始毫秒、结束毫秒和切点理由。

Gemini 此时不输出最终字幕。

程序对切片方案执行确定性校验：

- 第一片必须从 `0ms` 开始。
- 所有切片必须首尾严格相接。
- 最后一片必须结束于 FFmpeg 检测的真实视频时长。
- 每片不得超过 45 秒。
- 切片 ID 必须唯一。

结果无效时，程序把错误原因反馈给 Gemini，自动重试一次。仍无效则停止扒片。

### 第 6 步：本机 FFmpeg 按 Gemini 方案实际切片

| 项目 | 内容 |
| --- | --- |
| 执行位置 | 用户本机 |
| 软件 | FFmpeg |
| 输入 | 第 4 步确定的模型分析视频、第 5 步通过校验的切片方案 |
| 动作 | 按毫秒边界逐片重新编码，生成真实 MP4 文件 |
| 输出 | `review-slices/*.mp4` 和 `02-FFmpeg切片.md` |

切片编码规则：

```text
视频：H.264 / libx264 / preset fast / CRF 24
音频：AAC / 64kbps / 单声道
画面：最大宽度 1280，保持比例
```

输出目录：

```text
episodes/<episodeId>/video-translate/review-slices/
```

文件名包含切片序号和绝对时间边界：

```text
slice-001-<startMs>-<endMs>.mp4
```

`02-FFmpeg切片.md` 记录每个实际切片文件及其原片绝对开始、结束毫秒。

### 第 7 步：云端 Gemini 逐片提取台词和角色

| 项目 | 内容 |
| --- | --- |
| 执行位置 | 韭菜盒子云端模型接口 |
| 模型 | `gemini-3.6-flash` |
| 输入 | 当前 FFmpeg 切片、当前片 Whisper 区间、全片剧情文档、已有翻译角色 |
| 动作 | 综合声音、口型、画面字幕和剧情上下文，逐句提取真实有声台词 |
| 单片输出 | `03-片段NNN台词.md` |
| 汇总输出 | `03-Gemini逐片台词.md` |

每句必须返回：

```text
开始毫秒
结束毫秒
角色 ID
角色名
置信度
是否需要复核
校准原文
证据
画面文字
```

时间是当前切片内从 `0ms` 开始的相对时间。程序收到结果后加上切片的绝对开始时间，转换为原视频绝对时间。

Gemini 的正式字幕裁决证据为：

1. 实际声音。
2. 画面硬字幕或其他画面文字。
3. 人物口型。
4. 全片剧情与人物关系。
5. Whisper 人声区间，仅作辅助证据。

每片结果必须满足：

- 台词 ID 唯一。
- 开始和结束时间合法并位于当前切片内。
- 台词之间不重叠。
- `校准原文` 非空。

单片结果无效时自动重试一次。已经生成且重新校验有效的 `03-片段NNN台词.md` 会在再次点击 `扒片` 时直接复用，只请求缺失或无效的片段。

### 第 8 步：本机程序合并、分句和检查漏句

| 项目 | 内容 |
| --- | --- |
| 执行位置 | 视频翻译工作台本机 Electron 后端 |
| 软件 | 产品 TypeScript 确定性逻辑，不调用模型 |
| 输入 | Gemini 逐片台词、Whisper 语音区间 |
| 动作 | 合并绝对时间轴、按标点拆分长句、检查重叠、检测未覆盖人声区间 |
| 输出 | `04-最终稿.md` 和字幕工作台 cue 数据 |

处理规则：

- 按原片绝对开始时间排序。
- 不允许相邻台词时间重叠。
- 逗号、句号、问号、感叹号和分号作为强制分句点。
- 仍然过长的字幕继续按既有 `simple_wrap` 规则拆分。
- 拆分后的时间在原句时间窗内按字符权重连续分配，首尾不变、不留缝、不重叠。
- 正式字幕重新生成稳定 ID：`translation-cue-NNN`。

漏句检测规则：

1. 取每个 Whisper 人声区间。
2. 减去已经被 Gemini 正式字幕覆盖的时间范围。
3. 剩余连续区间达到 300ms 时，新增一条 `疑似漏句`。
4. Whisper 候选文字只写入 `recognizedText`。
5. 正式原文 `sourceText` 保持空白。
6. 用户必须试听并手工确认原文，之后才能翻译和进入配音流程。

最终输出：

```text
wiki/翻译/<episodeId>/04-最终稿.md
```

`04-最终稿.md` 由程序直接合并生成，不再调用 Gemini。

### 第 9 步：前端写入字幕工作台

后端返回最终台词数组后，前端写入当前剧集状态：

```text
cueId
startMs
endMs
recognizedText
sourceText
translationRoleId
proposedName
confidence
evidence
ocrText
needsReview
suspectedMissing
```

界面结果：

- 每句显示原片绝对时间。
- 显示角色候选、置信度和证据。
- `sourceText` 作为正式原字幕。
- `疑似漏句` 使用警告状态显示，正式原字幕为空。
- 译文保持空白，等待用户点击 `翻译所有字幕`。
- 自动选中第一条字幕并停留在字幕工作台。

## 3. 扒片过程的固定文档链

```text
00-人声识别与漏句证据.md
-> 01-整体分析与切片方案.md
-> 02-FFmpeg切片.md
-> 03-片段NNN台词.md
-> 03-Gemini逐片台词.md
-> 04-最终稿.md
```

| 文档 | 唯一责任方 | 内容 |
| --- | --- | --- |
| `00-人声识别与漏句证据.md` | 本机 FFmpeg + Spleeter + Faster-Whisper | 人声分离结果和语音时间证据 |
| `01-整体分析与切片方案.md` | 云端 Gemini 3.6 Flash | 全片剧情理解和连续切片方案 |
| `02-FFmpeg切片.md` | 本机 FFmpeg | 实际生成的切片文件和绝对边界 |
| `03-片段NNN台词.md` | 云端 Gemini 3.6 Flash | 单片台词、角色、时间和证据 |
| `03-Gemini逐片台词.md` | 本机程序汇总 Gemini 输出 | 所有逐片原始结果 |
| `04-最终稿.md` | 本机确定性程序 | 合并、分句、漏句标记后的正式扒片结果 |

## 4. 五阶段界面进度

用户点击 `扒片` 后，右栏依次显示：

```text
第 1/5 步：正在分离人声并生成 Whisper 漏句证据
第 2/5 步：Gemini 正在完整分析视频，最长等待 15 分钟
第 3/5 步：FFmpeg 正在按方案切片
第 4/5 步：Gemini 正在扒取片段 N/M
第 5/5 步：正在合并时间轴并检查疑似漏句
```

第 1、3、5 阶段在本机执行；第 2、4 阶段调用云端 Gemini。

## 5. 失败、停止与继续执行

- Spleeter 或 Faster-Whisper 失败：在产生 Gemini 费用前停止。
- Gemini 全片切片方案无效：自动重试一次。
- Gemini 单片台词无效：该片自动重试一次。
- 点击停止：本机任务停止等待；已经发到云端的请求可能仍在执行并产生费用。
- 再次点击 `扒片`：校验并复用有效的本机证据、全片切片方案和逐片台词文件，从第一个缺失或无效阶段继续。
- 更换识别视频：视频指纹改变，原扒片证据和下游翻译、配音、成片状态全部失效。
- 上传或更换无字幕成片母版：不影响扒片结果，因为扒片始终只读取识别视频。

## 6. 职责边界

| 能力 | 责任方 |
| --- | --- |
| 提取音频 | 本机 FFmpeg |
| 分离人声与背景声 | 本机 Spleeter |
| 提供语音区间和漏句候选 | 本机 Faster-Whisper large-v3-turbo |
| 理解全片剧情和规划切点 | 云端 Gemini 3.6 Flash |
| 实际生成视频切片 | 本机 FFmpeg |
| 逐片判断台词、角色、口型和画面字幕 | 云端 Gemini 3.6 Flash |
| 校验时间、合并、分句和检测疑似漏句 | 本机产品代码 |
| 确认疑似漏句和错误字幕 | 用户 |
| 翻译目标语言字幕 | 后续 `翻译所有字幕` 按钮，不属于 `扒片` 按钮 |
| 生成参考音和连续对白配音 | 后续配音工作台，不属于 `扒片` 按钮 |
