# 视频翻译工作台“识别字幕”执行流程

> 状态：代码已按本文实施，待真实项目视频完成端到端验收（2026-08-09）。
>
> 范围：只定义视频翻译的原声转写、字幕润色、角色绑定和翻译交付。配音、混音和成片工作台另行定义。

## 1. 目标

字幕工作台把原片音频转成带时间戳的原始字幕，保留 FunASR 原始结果，允许人工修正时间，再经可选画面抽帧校准、影视对白语义重建和人工确认后交给翻译和配音工作台。

```text
上传识别视频
-> FFmpeg 提取 16 kHz 单声道 WAV
-> FunASR 整轨识别
-> 按字词时间戳拆分过长字幕
-> 生成带时间戳、匿名说话人和可用情绪候选的 JSON/SRT
-> 人工检查原文和时间戳
-> 按需点击“抽帧校准”生成画面文字建议
-> 按需点击“大模型语义校准”融合原文、画面建议和剧情上下文
-> 人工应用、撤销或恢复 FunASR 原文
-> 人工将 speaker-N 绑定为正式角色
-> 整集翻译并人工复核
-> 进入配音工作台时冻结最终时间戳剧本
```

本流程不读取视频画面，不调用多模态模型，不压缩分析视频，不生成物理切片，不做分组扒片、重叠去重或二次语义合并。字幕拆分只调整 cue 边界，不切音频或视频。

## 2. 固定选型

### 2.1 识别内核

第一版固定使用 FunASR：

```text
SenseVoiceSmall：原文识别、粗粒度情绪和声音事件
FSMN-VAD：真实发声区间
CT-Punc：中文和英文标点恢复与句级时间戳
CAM++：匿名说话人聚类
```

首版支持 SenseVoiceSmall 能力范围内的中文、英文、日文、韩文和粤语。不在首版同时接入 Paraformer、Fun-ASR-MLT-Nano、Palmier Pro 或第二套 ASR。扩展语言前必须先用真实样片验证对应模型。

CAM++ 只输出 `speaker-0`、`speaker-1` 等声纹聚类，不猜测角色姓名或正式角色 ID。SenseVoiceSmall 的情绪只是音频候选标签，不视为真实表演定论。

### 2.2 不使用 Palmier Pro

Palmier Pro 的词级时间映射可作为实现参考，但其字幕管线与 Swift、macOS 26、Apple Speech 和自身时间轴紧密绑定。本产品是 Electron/TypeScript 应用，不引入 Palmier Pro 代码或运行时。

## 3. 入口和前置条件

原右栏 `扒片` 按钮改名为 `识别字幕`。

必须满足：

- 已打开项目和剧集。
- 已上传当前剧集的识别视频。
- 视频包含可读音频流。
- FFmpeg 可用。
- FunASR 运行时和固定模型可用。
- 运行语义校准和翻译时，用户选择的文本模型 API Key 可用。

调用链：

```text
字幕工作台“识别字幕”
-> Electron IPC
-> FFmpeg 提取 WAV
-> FunASR 整轨识别
-> 本机生成原始 JSON/SRT
-> 写入字幕工作台

字幕工作台“抽帧校准”（可选）
-> 按现有 cue 时间范围取 `(startMs + endMs) / 2`，用 FFmpeg 抽取一张中点帧
-> 同一张帧同时生成画面字幕建议和视觉人物建议，不重复抽帧
-> 保存中点帧供人工查看，不改变时间戳

字幕工作台“大模型语义校准”（可选）
-> 所选文本模型分析整集 FunASR 原文和可选画面字幕建议
-> 展示校准建议
-> 人工应用、撤销或恢复原文
-> 翻译前按当前工作稿和当前人工时间戳生成润色 SRT
```

## 4. 音频处理

### 4.1 FFmpeg 提取

FFmpeg 只从用户原片提取标准 WAV：

```bash
ffmpeg -i source.mp4 -vn -ac 1 -ar 16000 -c:a pcm_s16le source.wav
```

输出：

```text
episodes/<episodeId>/video-translate/source.wav
```

规则：

- 不覆盖用户上传的原片。
- 按原片文件指纹缓存 WAV；原片未变时直接复用。
- 不生成 `analysis.mp4`。
- 不运行静音切片、物理切片或视频压缩。
- 不默认做人声分离，避免分离模型损坏对白和发声边界。
- 原片无可读音频时停止，不调用 FunASR 和文本模型。

人声分离不属于首版自动链路。只有真实样片证明背景声导致识别质量不可接受时，才能另增人工触发的“增强人声后重试”。

## 5. FunASR 转写

### 5.1 整轨识别

FunASR 一次读取完整 `source.wav`。FSMN-VAD 在模型管线内确定发声区间，不由本机预先切音频。

每条原始记录至少包含：

```ts
interface RawSubtitleCue {
  cueId: string
  startMs: number
  endMs: number
  recognizedText: string
  speakerCluster?: string
  emotion?: string
}
```

规则：

- `cueId` 由本机生成，FunASR 不生成正式 ID。
- `startMs/endMs` 直接来自 FunASR `sentence_info`。
- 程序不按标点、字数或时长重新拆句。
- 程序不按字数重新分配时间。
- 允许不同 `speakerCluster` 的真实抢话时间重叠。
- 无人声时生成合法空 JSON/SRT，不伪造对白。

### 5.2 原始产物

写入：

```text
wiki/翻译/<episodeId>/原始转写.json
wiki/翻译/<episodeId>/原始转写.srt
```

JSON 是机器真值，保存 `cueId`、匿名说话人和情绪。SRT 是人工审查和字幕交换文件。两者必须使用相同的 `startMs/endMs`。

原始产物一旦成功写入，后续润色、角色绑定和翻译都不回写它。

## 6. 大模型语义校准

### 6.1 润色输入

原始转写成功后先展示 FunASR 原文，不自动调用文本模型。用户可以先点击“抽帧校准”获得每条 cue 的可选 `frameSuggestion`，再点击“大模型语义校准”。语义校准一次性提交整集全部 cue，并可同时提交：

```text
项目剧本、Wiki 和已确认专有名词（剧情资料证据）
抽帧校准建议（画面证据，可为空）
FunASR 原文（听觉证据）
speakerCluster / emotion（上下文辅助）
```

模型身份固定为：

```text
影视对白语义重建与校准导演
```

它不是普通错别字校对员，也不是编剧。模型必须先理解整集故事、当前场景、人物关系、问答因果和情绪推进，再在每个固定 cue 时间区间内重建最可能的原对白。证据优先级为：已确认剧情资料和专名 > 画面中清晰可读的字幕 > 全文语义推理 > FunASR 原始文字；画面字幕模糊、遮挡或明显不是对白时不得盲目照抄。

只允许在声音、画面字幕、剧情资料和上下文共同支持的范围内补回漏字、修正同音字和重建残句，不得编造原剧情没有证据支持的新事实。

### 6.2 固定输出合同

时间戳不出现在模型的可写输出中。模型只返回：

```ts
interface PolishedSubtitleText {
  cueId: string
  correctedText: string
}
```

模型必须：

- 保留全部 `cueId` 及原顺序。
- 不增加、删除、合并或拆分 cue。
- 不翻译、概括或编造对白；允许在证据支持范围内重建被噪声吞掉的文字。
- 不输出角色 ID、时间戳或新的情绪结论。
- 不输出解释、推理过程、前言或总结。

本机校验：

- 输入和输出 `cueId` 数量、集合和顺序必须完全一致。
- 不接受未知 ID、重复 ID、空文本或非法格式。
- 无效时把错误反馈给同一模型重试一次；再次失败则停止，保留原始转写。
- 校准后的 `startMs/endMs`、`speakerCluster` 和 `emotion` 永远保留当前本机工作稿值，不接受模型值。

模型结果先作为建议保存在工作台，不覆盖 `recognizedText` 或当前人工确认稿。用户可以应用建议、撤销本次应用，或继续手工修改人工确认稿。点击翻译时，当前人工确认稿和当前人工时间戳写入：

```text
wiki/翻译/<episodeId>/润色字幕.srt
```

`recognizedText` 永久保留 FunASR 原文，`frameSuggestion` 保存可选画面建议，`sourceText` 保存最终人工确认稿，方便对照和恢复。

### 6.3 抽帧人物建议

声音与画面使用两套独立机器编号：

```text
speaker-N        FunASR 声音聚类
visual-person-N  抽帧画面人物聚类
translationRoleId 人工确认的正式角色
```

每条 cue 仍只抽现有的一张中点帧。模型必须从头到尾比较本次全部帧：首次出现的清晰人物建立 `visual-person-1`，同一人物再次出现时复用原编号。整集结果先返回唯一人物目录，再逐条返回画面字幕建议和 `visiblePersonIds`。人物特征只作为模型内部聚类依据，不在用户界面展示。

抽帧完成后，为人物目录自动创建“画面人物 1、画面人物 2……”临时角色。单人画面的 cue 自动绑定该画面人物；画面无人、多人或人物被遮挡时不自动绑定，交给人工选择。用户把“画面人物 1”改名为真实角色后，所有已绑定该角色的字幕同步显示真实姓名。声音聚类只作为辅助证据，不自动覆盖画面人物或人工确认角色。

抽帧校准使用用户当前选择的文本模型发送图片，不在产品层限制模型。模型服务不支持图片时直接显示服务端错误。长字幕会按每批 20 条 cue 拆分为“抽帧校准”项目任务；成功批次结果落盘复用，失败后重新执行会跳过已成功批次。

## 7. 字幕工作台

### 7.1 页面职责

字幕工作台只负责：

- 上传、替换和预览识别视频。
- 分别执行音频识别和大模型语义校准。
- 对照原始识别文字和润色文字。
- 人工将匿名说话人绑定为正式角色。
- 对照中点抽帧、声音聚类和视觉人物建议确认正式角色。
- 人工修正原文和复核情绪候选。
- 翻译并人工检查目标语言对白。
- 冻结最终时间戳剧本。

“翻译所有字幕”只要求人工确认稿完整且当前没有正在翻译，不因已有译文而禁用。用户每次点击都重新调用模型；成功后用新结果替换当前译文，并使旧的冻结剧本和配音下游失效；失败时保留点击前的译文和下游状态。

点击“进入配音工作台”表示人工确认当前时间戳、正式角色、人工确认稿和目标语言译文。产品冻结完整的 `最终时间戳剧本.md/json`，生成 `finalScriptId` 和 `scriptHash`，后续配音版本必须与两者一致。完整标准剧本保留人工确认稿用于追溯和重新翻译，但配音 Skill 只接收目标语言表演稿：剧本 ID、哈希、目标语言、时间戳、正式角色、表演方向和目标语言译文；不得把源语言人工确认稿传给配音 Skill。

FunASR 返回句级结果后，本机先按原始字词时间戳处理字幕：长静音直接拆分；单条超过 5 秒或 22 个可见字符时，优先在标点、短停顿或最接近限制的位置拆分。拆分点必须落在真实字词边界，禁止平均分配时间。

语义校准不修改时间戳或 cue 数量。人工可以对照视频修改、新增、拆分、合并或删除字幕；人工拆分时，用户把播放头停在所选字幕内部，并把工作稿文字光标放在需要断句的位置，程序以播放头作为新旧 cue 的时间边界。原始 JSON/SRT 始终保留机器识别结果，当前工作稿记录人工编辑结果。

### 7.2 中栏列表

播放器始终读取原识别视频。点击一条字幕后，从该条开始时间播放，到结束时间暂停。

表格只显示：

```text
时间戳 | 匿名说话人 | 正式角色 | 情绪候选 | FunASR 原文 | 人工确认稿 | 目标语言字幕
```

每行对应唯一 `cueId`。

界面不显示内部英文 ID、疑似说话人或人物外观特征，只显示“声音人物 N”和“画面人物 N”。每行只显示抽帧校准实际使用的中点截图；点击整集播放器或字幕行继续核对原视频。

角色下拉框默认只修改当前字幕。表头分别提供“相同声音”和“相同画面人物”复选框：未勾选时逐条修改；勾选后，修改角色会批量应用到相同声音聚类或共同出现的单一画面人物。批量模式必须显示影响条数，并且只有用户主动选择角色时才执行。

### 7.3 右栏按钮

```text
上传识别视频 / 更换识别视频
识别字幕
大模型语义校准
翻译所有字幕
进入配音工作台
```

不再提供由旧切片扒片流程产生的单片模型重试和上下文复核。人工字幕编辑仍保留。

人工字幕编辑区提供：

```text
在当前位置新增对白
在当前位置拆分所选对白
与下一条对白合并
设为所选字幕开始 / 结束
删除所选对白
```

## 8. 说话人与角色

FunASR 的聚类标签只在当前识别草稿内有效：

```text
speaker-0 -> 人工绑定 role-<UUID>
speaker-1 -> 人工绑定 role-<UUID>
```

规则：

- 一次绑定默认应用到当前草稿中全部同聚类 cue。
- 聚类可能错合并或错拆分，允许用户对单条 cue 覆盖角色。
- 程序和文本模型都不根据声音自动创建正式角色。
- 新建和修改角色名使用应用内输入对话框，不调用浏览器或 Electron 的系统 `prompt()`。
- 角色名去除首尾空格后不能为空；取消对话框不产生修改。
- 修改角色不改变 `cueId/startMs/endMs`。

## 9. 翻译

点击 `翻译所有字幕` 时，一次性提交整集人工复核后的：

```text
cueId
translationRoleId
roleName
emotion
sourceText
```

文本模型必须：

- 保留全部 `cueId` 及原顺序。
- 不增加、删除、合并或拆分字幕。
- 不修改角色、情绪和时间。
- 只返回 `cueId + translatedText`。
- 结合整集对白、说话人和上下文翻译，不逐句孤立调用。

本机使用与润色相同的 ID 完整性校验，然后将译文回填到原 cue。翻译不修改 `startMs/endMs`。

## 10. 最终时间戳剧本

### 10.1 触发和校验

用户点击 `进入配音工作台` 时，程序校验：

- 每条 cue 有唯一 `cueId`。
- `0 <= startMs < endMs <= 视频时长`。
- 当前 cue 的 `startMs/endMs` 与原始转写 JSON 完全相同。
- 每条 cue 有非空 `sourceText` 和 `translatedText`。
- 每条 cue 有人工确认的 `translationRoleId`。
- 每个 `translationRoleId` 能解析到非空角色名。

情绪是可选辅助信息，不作为进入下一工作台的强制门槛。校验失败时不切换工作台，并定位第一条错误。

### 10.2 正式产物

原子写入：

```text
wiki/翻译/<episodeId>/最终时间戳剧本.json
wiki/翻译/<episodeId>/最终时间戳剧本.md
```

每条对白包含：

```text
cueId
translationRoleId
roleName
startMs / endMs
emotion（可选）
sourceText
translatedText
```

后续配音只使用 `translatedText` 发音；`sourceText` 只用于剧情理解和追溯。配音、混音和字幕烧录都不得反向修改已冻结时间戳。

### 10.3 剧本哈希

`scriptHash` 只计算：

```text
sourceFingerprint
sourceLanguage
targetLanguage
按时间排序的 cueId
translationRoleId
roleName
startMs / endMs
emotion
sourceText
translatedText
```

声音档案、参考音、生成时间和显示排序号不参与哈希。最终剧本改变后，旧配音和成片自动过期。

## 11. 文档链

```text
source.wav
-> 原始转写.json / 原始转写.srt
-> 润色字幕.srt
-> 人工绑定角色并复核
-> 最终时间戳剧本.json / 最终时间戳剧本.md
```

| 产物               | 内容                                           |
| ------------------ | ---------------------------------------------- |
| `source.wav`       | FFmpeg 从原片提取的 16 kHz 单声道音频          |
| `原始转写.json`    | FunASR 时间戳、原文、匿名说话人和情绪候选      |
| `原始转写.srt`     | 与原始 JSON 使用同一时间戳的人工可读字幕       |
| `润色字幕.srt`     | 只替换文字、不改时间戳的润色字幕               |
| `最终时间戳剧本.*` | 人工确认的角色、双语对白、可选情绪和冻结时间戳 |

不再创建：

```text
01-压缩、人声分离与切片.md
02-片段NNN扒片.md
03-合并稿.md
speech-intervals.json
review-slices/
analysis.mp4
analysis-vocals.wav
```

## 12. 状态和失败处理

| 操作                 | 结果                                            |
| -------------------- | ----------------------------------------------- |
| 同一原片指纹重新识别 | 直接复用有效 WAV 和原始转写                     |
| 强制重跑 FunASR      | 生成新草稿和新 `cueId`，旧角色绑定和下游过期    |
| 语义校准失败两次     | 停止并保留原始转写和当前工作稿，不应用部分结果  |
| 人工修改原文或角色   | 翻译、最终剧本、配音和成片过期；原 `cueId` 保留 |
| 人工修改译文         | 最终剧本、配音和成片过期；原 `cueId` 保留       |
| 更换识别视频         | WAV、原始转写、润色、角色绑定和全部下游过期     |
| 最终剧本写入失败     | 不进入配音工作台，不替换旧版本                  |

原始转写和最终剧本使用原子写入。任一中间步骤失败时，不以部分文件覆盖上一个有效版本。

## 13. 明确不做

字幕识别链路不做：

- 视频压缩和模型分析版视频。
- 多模态视频理解、口型识别或画面 OCR。
- FFmpeg 静音检测、对白候选区间和物理切片。
- 10 秒切片、500 ms 重叠、跨片补句和重叠去重。
- 逐片、逐句或分组调用大模型。
- 使用大模型改写、重排或推测时间戳。
- 自动猜测角色真名和正式角色 ID。
- 把粗粒度情绪候选包装成精确表演定论。
- 独立剧情梗概、动作时间轴或第二份对白脚本。
- 在本阶段执行角色参考音、配音、混音、字幕烧录和成片导出。

## 14. 验收标准

1. 点击 `识别字幕` 后只执行 FFmpeg 提取、FunASR 整轨识别和原始 JSON/SRT 写入，不调用文本模型。
2. 点击 `大模型语义校准` 后才提交整集原文，并可应用、撤销或恢复 FunASR 原文。
3. 整条链路不上传视频或视频切片，不调用多模态模型。
4. 原始 JSON 和原始 SRT 的每条时间一致。
5. 语义校准前后 cue 数量、`cueId`、顺序、`speakerCluster` 和 `emotion` 完全一致，只允许文字建议改变。
6. 模型无法通过 ID 完整性校验时不应用校准结果。
7. CAM++ 只产生匿名聚类，正式角色必须人工输入或选择，并可按聚类批量绑定。
8. 超过 5 秒或 22 个可见字符的字幕按真实字词边界自动拆分，人工可在播放头和文字光标位置继续拆分。
9. 新建角色和角色改名均使用可输入、可确认、可取消的应用内对话框。
10. 翻译使用已确认工作稿和人工可修正的当前时间戳。
11. 点击 `进入配音工作台` 后原子写入最终 JSON/Markdown，不增加额外确认按钮。
12. 代码和索引不再创建或链接旧切片扒片产物。
