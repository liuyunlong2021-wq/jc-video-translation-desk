## 1. 一句话目标

把现有音色文件整理为可检索、可试听、可复用、可追溯的角色声音资产库：原始音频保持不动，建立稳定 `voiceProfileId`、多标签元数据、版权状态和 Wiki 双链；项目中的角色只绑定经过审核的声音档案，不直接绑定文件名或临时路径。

## 3. 已确认产品决策

1. 原始目录 `/Users/by3/Documents/800+音色` 只读，不批量改名、移动、删除或覆盖。

## 4. 音色资产分层

### 4.1 原始层

原始层是外部目录中的实际文件，只读保存：

```text
/Users/by3/Documents/800+音色/<source-relative-path>
```

索引必须记录相对路径和源文件 SHA-256，不把机器绝对路径写入项目 Wiki。原始文件不能因为标准化失败、重复判断或版权待审而删除。

### 4.2 档案层

档案层是音色库的业务实体。一个档案可以关联一个或多个原始片段，但必须有一个明确的主参考音频。

最小合同：

```ts
interface VoiceProfile {
  voiceProfileId: string
  displayName: string
  sourceGroup: string
  sourceRelativePath: string
  sourceSha256: string
  referenceRelativePath?: string
  format: 'wav' | 'mp3' | 'other'
  durationMs: number
  sampleRate?: number
  channels?: number
  tags: string[]
  roleTags: string[]
  emotionTags: string[]
  language?: string
  dialect?: string
  quality: 'pending' | 'approved' | 'rejected'
  cloneReady: boolean
  rights: 'commercial-cleared' | 'local-only' | 'unknown' | 'rejected'
  notes?: string
}
```

`voiceProfileId` 由 `voice-` 加稳定哈希组成。第一版使用源文件 SHA-256；相同文件只生成一个档案。近似重复只报告候选，不自动合并。

### 4.3 标准化层

只有用户审核通过并准备接入模型的参考音频才生成标准化副本：

- 单声道 WAV；
- 16kHz 或目标模型明确要求的采样率；
- 去除首尾明显静音和异常空白；
- 保留原始文件，不覆盖原文件；
- 标准化失败时保留原始档案并标记 `cloneReady: false`。

标准化副本放入应用级受控媒体目录，例如：

```text
<Electron userData>/voice-library/reference/<voiceProfileId>.wav
```

不得把同一份标准化音频复制到每个项目。项目只保存引用和必要的可移植快照。

## 5. 分类与检索规则

分类采用多标签，不采用互斥文件夹。标签分为五组：

| 标签组 | 示例 |
| --- | --- |
| 基础音色 | 低沉、明亮、磁性、沙哑、清冷、柔和 |
| 人物年龄 | 儿童、少年、青年、中年、老年 |
| 性别与声部 | 男声、女声、中性、高音、中音、低音 |
| 表演和角色 | 旁白、广告、师姐、反派、老人、喜剧、影视、方言 |
| 情绪与节奏 | 平静、开心、悲伤、愤怒、惊讶、快速、慢速、克制 |

文件名只用于生成初始候选标签；AI 或脚本生成的标签必须标记为 `auto`，人工确认后才进入 `approvedTags`。不能因为文件名出现“男”或“女”就把性别当成事实。

检索至少支持：

- `roleTags`：按角色用途筛选；
- `tags`：按音色和表演风格筛选；
- `emotionTags`：按情绪参考筛选；
- `cloneReady`：只看可克隆音色；
- `rights`：默认只展示 `commercial-cleared`，本地测试可显式展开其他状态；
- `sourceGroup`：追溯资源来源。

## 6. Wiki 结构与双链

### 6.1 应用级音色库

音色库本身使用一个独立的可读索引，不复制到每个项目：

```text
<应用级音色库> /
├── 音色索引.md
├── 分类/
│   ├── 男性青年.md
│   ├── 女性青年.md
│   ├── 老年.md
│   ├── 旁白与广告.md
│   └── 角色化.md
├── 音色/
│   └── <voiceProfileId>.md  # 只为已审核或已使用档案创建
└── catalog.json             # 执行事实来源
```

`catalog.json` 用于应用检索和精确 ID 解析；`音色索引.md` 和分类 Markdown 是面向用户的阅读和搜索投影。第一版不为全部待审核文件创建独立 Markdown 页面。

### 6.2 项目 Wiki

项目只创建实际使用到的角色声音档案：

```text
wiki/
└── 声音/
    ├── 配音设计.md
    ├── 角色/
    │   └── <speakerId>.md
    └── 配音任务/
        └── <taskId>.md
```

角色声音页面至少记录：

```md
---
entityType: character-voice
speakerId: character-001
voiceProfileId: voice-abc123
status: approved
---

# 林夏的角色声音

声音档案：[[声音库/音色/voice-abc123]]
角色页面：[[资产/角色/character-001]]
当前配音任务：[[声音/配音任务/episode-001]]
```

正向链路：

```text
角色 Wiki -> 角色声音 Wiki -> 音色档案 -> 参考音频
```

反向链路：

```text
音色档案 -> 使用它的角色、剧本、配音任务和成片
```

反向链路由应用根据 `voiceProfileId` 和 `speakerId` 计算或更新，不允许依靠人工维护重复列表。

## 7. 资源整理流程

```text
只读扫描原始目录
  -> 记录文件、格式、时长、采样率、SHA-256
  -> 按来源组和文件名生成待审核标签
  -> 识别完全重复文件并生成报告
  -> 标记克隆候选、情绪候选和测试-only资源
  -> 人工确认标签与版权状态
  -> 为已审核档案生成标准化参考音频
  -> 生成音色库 catalog.json 与 Markdown 索引
  -> 项目按 voiceProfileId 建立角色双链
```

任何一步失败都不得删除原始文件。整理脚本必须支持重复执行：同一个 `sourceSha256` 不重复创建档案，不覆盖人工修改的标签和版权状态。

## 8. 角色声音使用规则

1. 角色先绑定 `speakerId`，再绑定 `voiceProfileId`；不能只保存显示名称。
2. 同一个项目和同一角色的后续集数优先复用已确认的 `voiceProfileId`。
3. 角色没有合适的已审核音色时，才允许进入 Qwen VoiceDesign 创建新声音。
4. 选中的音色只作为参考输入，不把原始音频内容写入提示词。
5. IndexTTS2 负责音色参考和情绪控制时，情绪来自台词结构化字段、情绪文字或单独情绪样音；不自动把不同角色的情绪音频当作同一角色音色。
6. Qwen Base 和 IndexTTS2 的模型差异只能记录在配音任务中，不改变角色档案 ID。
7. 更换 `voiceProfileId` 必须使该角色下游配音、字幕时间轴和成片标记为待更新，但不删除旧音频。

## 9. 版权与安全边界

- `commercial-cleared`：有明确授权证据，才允许进入产品默认候选；
- `local-only`：只能在本机测试，默认不展示给其他用户；
- `unknown`：来源或授权不明，禁止作为产品默认音色；
- `rejected`：明确禁止使用，不进入检索结果。

目录内“公共领域整理”文字只记录为来源备注，不能自动改变 `rights`。真实人物、影视角色、动漫角色和带明显模仿指向的音频默认至少为 `unknown`。

音频目录路径、用户绝对路径和本地配置不写入可分享的项目 Wiki；Wiki 使用 `sourceGroup`、相对资源名和 `voiceProfileId`。

## 10. 实施阶段

### P0：只读盘点

- 扫描 2,262 个音频文件；
- 输出数量、格式、时长、采样率、声道和 SHA-256；
- 识别完全重复文件；
- 输出来源组、疑似标签和版权待核验清单；

完成标准：扫描结果可重复，文件数量无丢失，所有来源路径可回溯。

### P1：建立音色目录

- 创建 `catalog.json`；
- 生成音色索引和分类 Markdown；
- 为 `克隆参考音色`、`智声整理音色` 和已人工确认的音色建立档案；
- 仅对审核通过的主参考音生成标准化副本；
- 保留版权状态和人工修订记录。

完成标准：可按角色用途、音色标签、情绪、质量和版权状态检索，并能试听候选。

### P2：接入项目 Wiki

- 角色声音页面绑定 `speakerId` 和 `voiceProfileId`；
- 生成音色档案到角色和配音任务的正向链；
- 生成音色档案到项目使用关系的反向链；
- 项目切换后仍能恢复当前绑定，不触发付费任务。

完成标准：打开任一项目 Wiki，可以从角色跳到声音档案，再回到配音任务和成片。

### P3：接入配音模型

P3 另立实现 SDD，待 Qwen Base 与 IndexTTS2 完成同条件测评后确定默认模型。当前 SDD 不规定具体 API、模型参数或批量配音 UI。

## 11. 验收测试

### 数据完整性

1. 原始音频数量和源文件 SHA-256 与 P0 扫描报告一致；
2. 完全重复文件被报告但不误删；
3. 所有档案的来源相对路径可解析；
4. 重复执行扫描不会重复创建档案；
5. 人工标签和版权状态不会被再次扫描覆盖。

### Wiki 与双链

1. `音色索引.md` 能按分类定位到已审核音色；
2. 角色页面能正向链接到声音档案；
3. 声音档案能反向定位使用它的角色和配音任务；
4. 断开的媒体链接和不存在的 `voiceProfileId` 会被报告；
5. 项目 Wiki 不包含机器绝对路径。

### 使用边界

1. 默认检索结果排除 `unknown`、`local-only` 和 `rejected`；
2. 本地测试模式可以显式展开非商用档案；
3. 更换声音档案后，旧音频和成片仍可恢复；
4. 音色整理和索引生成不会触发任何付费 TTS、克隆或模型任务。
