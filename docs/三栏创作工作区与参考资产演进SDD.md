# 三栏创作工作区与参考资产演进 SDD

> 日期：2026-07-30
> 状态：已实施，待云端全链路验收
> 目标版本：2.3
> 依赖：`docs/短视频工厂AI原生创作改造SDD.md`、`docs/镜头节奏控制SDD.md`、`docs/创作参数与品牌视觉升级SDD.md`
> 取代范围：`docs/短视频工厂AI原生创作改造SDD.md` 第 5.1、5.4、5.5 节的界面职责
> 项目与资产演进：本文第 4.1、4.4、8、10、12 节中的单项目选择、单核心参考与 Future 多资产方案，由 `docs/资产图工作区与Markdown双链创作图谱升级SDD.md` 取代

## 1. 一句话目标

把现有三栏从“左侧堆文稿、中间堆素材、右侧堆全部控制”重构为稳定的“创作输入、作品工作区、上下文检查器”；当前支持单核心参考图，未来扩展到产品、角色、场景、道具和风格参考时，不增加新列、不复制工作流、不推翻分镜与媒体链路。

## 2. 问题定义

当前界面的主要问题不是控件尺寸，而是信息职责错位：

1. 中栏拥有最大的可视面积，却在分镜审阅阶段主要显示待生成素材占位项；
2. 分镜文档被放在最窄的右栏，逐镜文稿、图片提示词和视频提示词同时展开，难以扫描；
3. 声音方案与分镜方案永久上下堆叠，无论用户当前在处理什么，都争夺右栏高度；
4. 文稿、配音文稿和分镜对应台词存在被理解为多个版本的风险；
5. `jc-script-storyboard` 已输出导演、代表作、参考场景、节奏档案和镜头数量理由，但当前 Store 与解析器没有完整保存和展示这些导演决策；
6. 当前核心参考图以单独控件存在，缺少未来扩展为角色、场景和道具资产的稳定位置。

根因是“阶段控件”与“作品产物”混在一起。新设计必须先固定区域职责，再安排具体控件。

## 3. 产品原则

### 3.1 三栏职责长期稳定

| 区域 | 长期职责 | 不承担的职责 |
| --- | --- | --- |
| 左栏：创作输入 | 用户诉求、比例、目标时长、视觉风格、镜头节奏、核心参考上传 | 不长期展示正式作品文档，不堆生成结果 |
| 中栏：作品工作区 | 文稿、导演分镜、素材、成片的查看与主编辑 | 不展示全局设置表单，不堆所有阶段按钮 |
| 右栏：上下文检查器 | 当前工作区、当前镜头或当前素材的属性、提示词与下一步操作 | 不永久同时展示声音、分镜、素材三套面板 |

不得增加第四列。未来角色、场景和道具属于参考资产，不各自占用新列。

### 3.2 单一事实来源

- 项目只有一份权威文稿 `approvedScript`；
- “确认”是文稿状态，不是另一份文稿；
- 声音设计使用 `approvedScript + voicePrompt`，不得创建“配音文稿”副本；
- 分镜中的 `script` 只是权威文稿的连续片段，不是可独立改写的新稿；
- 配音、分镜图、视频和成片是文稿的派生产物。

### 3.3 渐进披露

用户先看创作决定，再看执行提示词：

```text
导演与参考作品
  -> 全片叙事节奏
  -> 镜头列表
  -> 当前镜头导演设计
  -> 首帧提示词 / 视频提示词
```

不得默认同时展开全部镜头的两个长提示词。技术提示词必须保留可编辑能力，但只在用户选择具体镜头后显示。

## 4. 信息架构

### 4.1 中栏一级工作区

中栏只保留四个一级视图：

```text
文稿 | 分镜 | 素材 | 成片
```

| 视图 | 核心内容 |
| --- | --- |
| 文稿 | 唯一正式文稿、草稿/已确认状态、字数、目标时长、统一配音播放器 |
| 分镜 | 导演总览、节奏带、紧凑镜头列表、当前镜头选择 |
| 素材 | 参考资产、统一配音、分镜图和视频片段 |
| 成片 | 最终播放器、时长、比例、文件操作和合成状态 |

“素材”内部使用二级筛选：

```text
全部 | 参考资产 | 音频 | 分镜图 | 视频
```

最终成片不再与普通生成素材同级混在筛选列表中；它拥有独立一级视图，但仍可在“全部”中显示一个结果入口。

### 4.2 右栏上下文

右栏内容由当前选择决定：

| 当前上下文 | 右栏内容 |
| --- | --- |
| 文稿草稿 | 文稿状态、生成/重新生成、确认文稿 |
| 文稿已确认 | 声音设计五项、云端/本地引擎、生成声音方案、生成配音 |
| 分镜总览 | 导演身份、参考作品与场景、镜头数量理由、重新转分镜、生成分镜图 |
| 选中镜头 | 导演设计、参考资产绑定、首帧提示词、视频提示词、单镜失效状态 |
| 选中素材 | 预览、来源镜头、生成状态、错误、重试或打开文件 |
| 成片 | 合成条件、结果信息、重新合成、打开文件 |

同一时刻只显示一个上下文。阶段主操作固定在右栏底部，不随长文本滚出可视区域。

### 4.3 自动导航

阶段成功后，中栏自动切换到最需要用户检查的视图：

```text
生成文稿     -> 文稿
确认文稿     -> 文稿，右栏切换声音方案
生成配音     -> 文稿顶部出现播放器，素材/音频新增结果
转分镜       -> 分镜
生成分镜图   -> 素材/分镜图
生成视频     -> 素材/视频
合成完成     -> 成片
```

自动切换只发生在用户主动完成阶段操作后，不在恢复历史任务时抢夺用户当前视图。

### 4.4 阶段进度与按钮

分段确认流程继续保留，用户仍然逐步点击按钮生成每项产物。所有阶段按钮都放在右栏底部同一个固定操作区，不随文档滚动，也不在中栏内容中重复出现。

右栏顶部显示紧凑阶段进度：

```text
文稿 -> 配音 -> 分镜 -> 图片 -> 视频 -> 成片
```

- 已完成阶段显示完成状态并可点击返回对应工作区；
- 当前阶段高亮；
- 尚未满足条件的未来阶段只显示状态，不可提交任务；
- 阶段进度用于导航和说明，不替代底部主按钮。

右栏底部使用稳定的“次要操作 + 当前主操作”结构：

```text
[次要操作]                         [当前绿色主按钮]
```

同一时刻只允许一个绿色主按钮。按钮根据任务状态依次变化：

| 当前状态 | 中栏默认视图 | 右栏次要操作 | 右栏主按钮 | 点击结果 |
| --- | --- | --- | --- | --- |
| 尚无文稿 | 文稿 | 无 | 生成文稿 | 根据左栏诉求与参数生成文稿草稿 |
| 文稿草稿 | 文稿 | 重新生成 | 确认文稿 | 冻结唯一文稿，进入声音设计 |
| 文稿已确认 | 文稿 | 修改文稿 | 生成声音方案 | 生成并显示五项声音提示词 |
| 声音方案已生成 | 文稿 | 重新设计声音 | 生成配音 | 提交 TTS，音频进入素材库 |
| 配音已生成 | 文稿 | 重新生成配音 | 转分镜 | 读取真实时长并生成导演分镜文档 |
| 分镜已生成 | 分镜 | 重新转分镜 | 生成分镜图 | 按导演最终镜头数提交图片任务 |
| 分镜图已完成 | 素材/分镜图 | 重试失败项 | 生成视频 | 每张分镜图提交一条单镜头视频 |
| 视频已完成 | 素材/视频 | 重试失败项 | 合成视频 | 本地拼接视频并覆盖统一配音 |
| 成片已完成 | 成片 | 重新合成 | 打开成片 | 打开当前最终文件，不产生云端费用 |

规则：

1. 主按钮始终显示准确动作名称，不使用含糊的“继续”；
2. 图片和视频按钮显示本次待提交数量，例如“生成 14 张分镜图”“生成 14 条视频”；
3. 云端媒体按钮在点击后才产生付费任务，页面切换和查看文档不得自动提交；
4. 待提交图片或视频超过 20 个时，沿用现有数量确认；用户取消后不创建任何任务；
5. 任务运行中，主按钮变为带进度的“正在生成”，并提供独立的停止操作；
6. 部分失败时，主按钮优先显示“重试 2 个失败项”，成功项不重复付费；
7. 次要操作不得使用主绿色填充，避免与当前下一步竞争；
8. 修改上游内容后，按钮立即回到最早失效阶段，不允许跳过失效产物继续合成；
9. 恢复历史任务时，根据持久化产物计算当前主按钮，不依赖上次停留页面猜测；
10. 键盘焦点、禁用原因和运行状态必须可访问，不能只通过颜色表达。

## 5. 文稿工作区

### 5.1 唯一文稿

文稿视图展示 `approvedScript` 的生成、编辑和确认状态：

- 确认前：可编辑，状态为“草稿”；
- 确认后：默认只读，状态为“已确认”；
- 用户主动选择修改后才重新进入编辑状态；
- 修改已确认文稿必须按现有失效规则清空配音及全部视觉下游；
- 不创建 `voiceScript`、`ttsScript` 或其他正文副本。

### 5.2 配音关联

声音方案只保存：

```ts
interface VoiceDesignDraft {
  text: string // 必须等于 approvedScript
  voicePrompt: string
}
```

右栏声音检查器只显示“使用已确认文稿”的引用状态和五项声音提示词，不再重复渲染第二个可编辑正文框。音频生成后：

- 文稿视图顶部显示紧凑播放器和真实时长；
- 音频文件进入“素材 / 音频”；
- 点击文稿引用可返回文稿视图；
- 任何模型返回的 `text !== approvedScript` 继续作为合同错误拒绝。

## 6. 分镜工作区

### 6.1 导演总览

分镜顶部固定展示：

- `creativeIdentity`：世界知名导演或动画主创 + 具体代表作 + 具体参考场景；
- `sceneReference`：为什么该场景适合本片；
- `resolvedPace`、真实配音时长、参考镜头数、最终镜头数；
- `shotCountRationale`：长镜、标准推进和蒙太奇如何影响最终数量；
- `visualAnchor`：全片视觉一致性。

首屏只显示一行导演身份和核心数字。“参考场景”“镜头数量理由”“全局一致性”使用可展开区域，不以多个大文本框常驻。

### 6.2 节奏带

在导演总览下方显示一条按 `playDuration` 比例绘制的节奏带：

- 每个色块代表一个镜头，宽度对应成片播放时长；
- 角色使用可区分的语义样式：`hook`、`development`、`payoff`；
- 处理方式使用图标或纹理区分：`hold`、`progression`、`montage`；
- 点击色块选中对应镜头并滚动到镜头列表位置；
- 色彩必须有文字或图标冗余，不能只靠颜色表达含义。

节奏带是审阅工具，不是第一版时间线编辑器；不支持拖拽改时长、磁吸、轨道和关键帧。

### 6.3 紧凑镜头列表

每镜默认只显示：

```text
镜号 | playDuration | script | shotRole | editTreatment | shotSize | cameraMovement
```

列表行高度稳定，长文稿最多显示两行并截断。选中镜头后，完整信息进入右栏检查器，不在列表中展开多个嵌套文本框。

### 6.4 镜头检查器

选中镜头后，右栏使用三个标签：

```text
导演设计 | 首帧提示词 | 视频提示词
```

“导演设计”展示 `storyBeat`、`startState`、`actionProgression`、`endState`、景别、机位、运动和参考资产绑定；两个提示词标签保留当前可编辑合同。

修改首帧提示词只使该镜分镜图、视频和成片失效；修改视频提示词只使该镜视频和成片失效。修改导演结构字段不自动重写提示词，第一版只读展示，重新规划通过“重新转分镜”完成。

## 7. 分镜文档数据合同

当前解析器不得再丢弃导演层字段：

```ts
interface StoryboardDocument {
  actualDuration: number
  creativeIdentity: string
  sceneReference: string
  rhythmArchive: string
  distributionIntent: string
  resolvedPace: 'slow' | 'medium' | 'fast'
  referenceShotCount?: number
  finalShotCount: number
  shotCountRationale: string
  visualAnchor: string
  shots: StoryboardShot[]
}

interface StoryboardShot {
  index: number
  storyBeat: string
  shotRole: 'hook' | 'development' | 'payoff'
  editTreatment: 'hold' | 'progression' | 'montage'
  playDuration: number
  generationDuration: 4 | 6 | 8
  script: string
  shotSize: string
  cameraAngle: string
  cameraMovement: string
  startState: string
  actionProgression: string
  endState: string
  referenceAssetIds: string[]
  storyboardImagePrompt: string
  videoPrompt: string
}
```

- `finalShotCount` 必须等于 `shots.length`；
- `shots[].script` 顺序拼接后必须覆盖唯一文稿；
- `referenceShotCount` 只用于解释节奏，不参与数组长度校验；
- `playDuration`、`generationDuration` 和单一连续镜头合同继续沿用现有验证；
- 图片 Skill 只能补充 `storyboardImagePrompt`，不得删除导演字段或改变镜头数量。

## 8. 参考资产演进

### 8.1 当前单核心参考映射

当前能力仍只允许 `0..1` 张核心参考图。界面和模型行为保持不变，但在新文档模型中映射为：

```ts
interface ReferenceAsset {
  id: string
  role: 'core'
  label: string
  relativePath: string
  mimeType: 'image/png' | 'image/jpeg' | 'image/webp'
  source: 'upload'
}
```

迁移规则：

```text
coreReferenceVisible === true  -> referenceAssetIds = [coreReference.id]
coreReferenceVisible === false -> referenceAssetIds = []
```

第一阶段不改变媒体接口，不把一个参考图重复保存成多个资产，也不开放多选上传。

### 8.2 未来多参考资产

未来扩展时只扩展 `role`，不改变三栏和分镜主流程：

```ts
type ReferenceAssetRole =
  | 'product'
  | 'character'
  | 'scene'
  | 'prop'
  | 'style'
```

“素材 / 参考资产”按角色分组展示。每个镜头通过 `referenceAssetIds` 绑定实际需要的资产；未绑定的资产不得发送给该镜头的图片或视频任务。

示例：

```text
镜头 06
角色：年轻内容创作者
场景：夜晚工作室
道具：电脑、核心产品
风格：手工粘土定格
```

如果该镜只需要产品和风格，就只绑定这两项。不得把全项目所有角色、场景和道具无差别发送给每个镜头。

### 8.3 未来资产所有权

- Electron 主进程继续拥有真实文件路径、导入、复制、删除和媒体提交；
- Skill 只能使用受控资产 ID 和公开元数据，不得生成本机路径；
- 角色、场景和道具生成结果先进入参考资产库，再由导演分镜绑定；
- 替换某个参考资产只使绑定它的镜头图像、视频和成片失效；
- 未绑定该资产的镜头和已确认文稿、配音保持不变。

本节是后续合同，不属于本 SDD 第一阶段实施范围。

## 9. 上下文 AI 局部修改

### 9.1 产品定位

所有由模型生成且用户需要审阅的对象，统一支持“选中对象后用自然语言修改”：

```text
选中对象 -> AI修改 -> 输入一句要求 -> 查看提案 -> 应用
```

这不是全局聊天助手。当前选中对象就是修改范围，模型不得自行扩大范围。产品价值是“哪里不满意就只改哪里，已经满意和已经付费的部分继续保留”。

### 9.2 最小操作 UI

右栏检查器标题区固定提供一个带图标的 `AI修改` 按钮。只有当前对象支持修改时显示；按钮始终可见，不能只在悬停时出现。

点击后不打开新页面或大型模态框，而是在当前检查器顶部展开一行内联输入区：

```text
[描述你想怎么改                                      ] [发送]
```

- 输入焦点自动进入文本框；
- `Cmd/Ctrl + Enter` 发送，`Esc` 取消；
- 当前对象、锁定条件和前后文由系统自动附带，用户不需要选择 Skill、模型或修改范围；
- 输入区记住本次未发送内容，切换对象时询问是否放弃，不把指令串到另一个对象；
- 第一版不增加全局聊天侧栏、聊天历史列表和多轮 Agent 会话。

发送后，右栏原位显示修改提案：

- 文本和结构化对象：只突出发生变化的句子或字段；
- 图片：显示原图与新版本缩略预览；
- 视频：显示原视频与重做版本预览；
- 底部只提供 `取消` 与 `应用修改`；
- 在应用前显示准确影响，例如“将使第 13 镜图片、视频和成片失效”；
- 用户应用前不覆盖当前对象、不改变工作流阶段、不清理旧文件。

### 9.3 修改能力与边界

| 当前对象 | 用户示例 | AI 实际动作 | 默认锁定项 |
| --- | --- | --- | --- |
| 文稿 | “开头更直接，控制在 30 秒” | 重写选中段落或全文并返回完整候选文稿 | 已验证事实、目标时长、产品名称 |
| 声音方案 | “不要播音腔，更年轻自然” | 只重写五项 `voicePrompt` | 唯一文稿、五项顺序 |
| 单个分镜 | “第 13 镜改成俯拍桌面，慢慢推进” | 只重写该镜导演字段、首帧简报和视频提示词 | 镜号、文稿片段、播放时长、镜头总数、全局风格 |
| 分镜图 | “产品放大，人物移到左侧” | 使用当前图片和绑定参考资产生成一个图片变体 | 比例、核心主体、镜头职责 |
| 单条视频 | “动作慢一点，不要转身” | 修改该镜视频提示词并从首帧重新生成视频 | 首帧、播放时长、单镜头合同 |

当前视频模型不承诺直接编辑既有视频。用户界面应使用“AI重做本镜”而不是“精确编辑视频”，并保留旧视频直到新版本被采用。

以下请求超出单对象修改范围：

- 把一个镜头拆成多个镜头；
- 合并镜头或改变镜头总数；
- 修改某镜对应文稿或重新分配播放时长；
- 改变全片导演、视觉风格或核心参考资产；
- 要求修改其他未选中的镜头。

遇到这些请求时，模型不得偷偷执行。界面应建议进入“重新转分镜”或对应上游工作区，并在用户确认后按全局失效规则处理。

### 9.4 模型上下文合同

单对象修改只发送完成该任务所需的最小上下文：

```ts
interface RevisionRequest<T> {
  targetType: 'script' | 'voice-plan' | 'shot' | 'image' | 'video'
  targetId: string
  instruction: string
  current: T
  locks: Record<string, unknown>
  context: Record<string, unknown>
}

interface RevisionProposal<T> {
  targetType: RevisionRequest<T>['targetType']
  targetId: string
  revised: T
  changedFields: string[]
  impact: string[]
}
```

具体上下文：

- 文稿：用户诉求、已验证事实、目标时长、当前文稿和用户选区；
- 声音方案：唯一文稿、当前五项提示词和用户要求；
- 单镜分镜：全局导演、参考作品、视觉锚点、第 `N-1 / N / N+1` 镜、当前资产绑定和用户要求；
- 图片：当前图片、该镜首帧提示词和已绑定参考资产；
- 视频：当前首帧、该镜视频提示词、播放时长和用户要求。

单镜修订返回值必须通过与首次分镜相同的合同验证：镜号、文稿、时长和总镜头数不变；仍为无切镜的单一连续镜头；前后连续性可解释。图片和视频修改继续使用 Electron 管理的受控资产，不向文本模型暴露本机路径。

### 9.5 应用、版本与精确失效

点击“应用修改”后才替换当前版本，并按依赖关系失效：

| 应用的修改 | 保留 | 失效或需要重做 |
| --- | --- | --- |
| 文稿 | 诉求、参数、参考资产 | 配音、分镜、图片、视频、成片 |
| 声音方案 | 文稿、参考资产 | 配音及依赖真实配音时长的全部下游 |
| 单镜分镜 | 其他镜头和配音 | 该镜图片、该镜视频、成片 |
| 单张图片 | 其他图片和视频 | 该镜视频、成片 |
| 单条视频 | 其他视频 | 成片 |

- 文本和结构化修改至少支持一次撤销；
- 图片和视频新版本成功前保留旧文件，用户采用新版本后旧文件进入该素材的历史版本，不立即物理删除；
- 重新生成失败时继续使用旧版本，不让成功素材变成不可用；
- 部分修改只重做失败或受影响项，禁止重新提交其他已成功的付费任务；
- 图片、视频修改属于付费媒体任务，发送前必须显示准确对象和数量；文本提案不得伪装成媒体已修改成功。

### 9.6 与阶段主按钮的关系

`AI修改` 是当前对象工具，不取代右栏底部的阶段主按钮：

- 提案生成与取消不改变当前阶段；
- 应用后若产生下游失效，阶段主按钮自动回到最早需要重做的位置；
- 例如应用第 13 镜修改后，主按钮变为“重新生成第 13 镜分镜图”；
- 应用声音方案修改后，主按钮变为“生成配音”；
- 媒体变体生成按钮显示“生成 1 张图片”或“重做 1 条视频”，不复用全批量按钮制造歧义。

## 10. 状态与选择

Store 新增纯界面状态，不写入媒体业务状态机：

```ts
type WorkspaceView = 'script' | 'storyboard' | 'media' | 'final'
type MediaFilter = 'all' | 'references' | 'audio' | 'storyboards' | 'videos'

interface WorkspaceSelection {
  view: WorkspaceView
  mediaFilter: MediaFilter
  selectedShotIndex?: number
  selectedAssetId?: string
}
```

- `selectedShotIndex` 和 `selectedAssetId` 不能同时生效；
- 删除或失效对象后清理对应选择；
- 当前工作区可持久化，自动导航只覆盖当前会话的明确阶段成功事件；
- 业务阶段继续使用现有 `draft -> ... -> completed` 状态，不另建第二套工作流状态机。

## 11. 响应式与可访问性

- 桌面宽屏保持三栏；左、右栏使用稳定宽度，中栏获得剩余空间；
- 窗口较窄时右栏作为可开合检查器，不把中栏压缩到不可阅读；
- 不允许出现第四列、横向溢出或页面级滚动失效；
- 中栏和右栏各自只有一个主要纵向滚动容器；
- 镜头列表、节奏带和素材项支持键盘选择；
- 图标按钮提供工具提示和可访问名称；
- 所有文本框、按钮和标签在中文与英文下不得溢出。

## 12. 实施阶段

### Phase 1：作品工作区

1. 建立 `文稿 / 分镜 / 素材 / 成片` 四个中栏视图；
2. 把正式文稿从左栏移入文稿视图，左栏保留输入与参数；
3. 删除重复配音正文，只引用唯一文稿；
4. 保存完整导演分镜字段；
5. 实现导演总览、节奏带和紧凑镜头列表；
6. 把右栏改为上下文检查器；
7. 实现固定的阶段进度和右栏底部主操作栏，迁移全部现有阶段按钮；
8. 保持单核心参考图、现有媒体 API 和分段付费确认不变。

### Phase 2：上下文 AI 修改与恢复

1. 完成镜头、素材选择与右栏联动；
2. 实现文稿、声音方案和单镜分镜的上下文 `AI修改`、提案预览、应用与一次撤销；
3. 实现自动导航、历史任务恢复、精确失效和失效后的选择清理；
4. 验证窄窗口、长文稿、20 镜以上和中英文布局。

### Phase 3：媒体局部重做

1. 实现单张分镜图的自然语言编辑与版本选择；
2. 实现单条视频提示词修改和“AI重做本镜”；
3. 明确付费确认、失败回退、旧版本保留和局部重试；
4. 打包并人工走通文稿、配音、分镜、图片、视频和成片全流程。

### Future：多参考资产

在单核心参考工作流稳定后另立 SDD，实施：

- 多资产导入与分组；
- 产品、角色、场景、道具和风格资产；
- 每镜资产绑定；
- 角色/场景/道具生成 Skill 的单轮应用合同；
- 受影响镜头级失效与重生成。

不得在 Phase 1、Phase 2 中提前实现上述 Future 功能。

## 13. 验收标准

1. 界面仍为三栏，没有新增第四列；三栏职责分别为输入、作品、检查器。
2. 中栏只有 `文稿 / 分镜 / 素材 / 成片` 四个一级视图，媒体类型进入素材二级筛选。
3. 右栏底部始终只有一个绿色主按钮，并按文稿、配音、分镜、图片、视频、成片顺序推进；原有阶段能力没有丢失。
4. 图片和视频主按钮显示待提交数量，部分失败只重试失败项，查看页面不会自动产生费用。
5. 全项目只有一份权威文稿；声音方案不显示第二个可编辑正文。
6. 转分镜后自动进入分镜视图，首屏可看见具体导演、代表作、参考场景、真实时长、参考镜头数和最终镜头数。
7. 节奏带宽度与各镜 `playDuration` 成比例，并可选择对应镜头。
8. 镜头列表默认不展开长提示词；选中镜头后右栏才显示导演设计、首帧提示词和视频提示词。
9. 当前单核心参考图能迁移成 `referenceAssetIds`，图片和视频生成行为与现有版本一致。
10. 修改单镜提示词只使该镜必要下游失效；修改已确认文稿继续使整个配音和视觉链路失效。
11. 旧任务的文稿、声音方案、媒体路径和已生成素材不丢失；缺少新导演字段的旧任务能以兼容视图打开。
12. 44 项现有测试继续通过，并增加工作区导航、按钮状态、导演字段持久化、自由镜头数、参考资产映射和响应式滚动测试。
13. 类型检查、生产构建和 Universal macOS 未签名包通过；人工完成一次全链路测试。
14. 文稿、声音方案和单镜分镜都能通过同一个 `AI修改` 入口生成提案，应用前可取消且不影响现有产物。
15. 单镜修改不能改变文稿、时长、镜头总数和其他镜头；应用后只使该镜必要下游失效。
16. 单图编辑和单视频重做在付费前显示准确数量，新版本失败或未采用时旧版本继续可用。
17. 常规 AI 修改不打开新页面或全局聊天栏，用户从选中对象到发送修改要求最多需要一次额外点击。

## 14. 明确不做

- 不增加第四列；
- 不创建配音文稿副本；
- 不在第一阶段实现复杂时间线、轨道、关键帧或拖拽调时；
- 不在第一阶段实现多角色、场景和道具生成；
- 不把全部参考资产发送给所有镜头；
- 不增加脱离当前选择的全局聊天助手；
- 不允许单对象修改静默改变其他对象、文稿时长或镜头数量；
- 不把视频重新生成宣传为对既有视频的精确编辑；
- 不改变固定模型、API、付费确认、托管媒体目录和 FFmpeg 合成合同；
- 不为新界面创建第二套媒体 Store 或第二套任务状态机。
