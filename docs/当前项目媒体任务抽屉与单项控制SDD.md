# 当前项目媒体任务抽屉与单项控制 SDD

> 日期：2026-08-01
> 状态：已实施，待用户真实付费任务验收
> 范围：资产图、分镜图、视频的项目内任务历史、单项停止、继续与重试
> 原则：不改变现有三栏布局，不建立跨项目任务中心，不复制第二套媒体执行系统

## 1. 结论

在现有三栏工作区顶部项目工具栏增加一个小型“任务”图标和未完成数量徽标。点击后从右侧打开窄抽屉，只显示当前项目的媒体任务。

```text
项目选择器                         [任务 3]
                                      |
                                      v
                         +---------------------------+
                         | 当前项目任务              |
                         | 资产图 · 编剧小人         |
                         | 下载失败   [继续下载][放弃]|
                         | 分镜图 · 镜头 03          |
                         | 生成中 02:31 [停止等待]    |
                         | 视频 · 镜头 01            |
                         | 已完成                    |
                         +---------------------------+
```

- 任务严格跟随项目：项目 A 只显示 A 的任务，切换到项目 B 后立即显示 B 的任务；
- 卡片负责当前资产或镜头的就地状态与操作，任务抽屉负责当前项目总览；
- 批量生成拆成独立单项任务，一项失败或停止不影响其他项，也不能锁死整个项目；
- 媒体任务执行期间仍可新建项目、切换项目、查看和编辑文稿；
- 只锁定正在执行任务的目标资产或镜头自己的重复生成操作；
- 资产图、分镜图、视频复用同一任务合同和同一抽屉，不为三类媒体各做一套历史。

## 2. 当前问题与根因

当前后端已经把待完成任务保存在每个项目自己的 `run.json`，并能在已有结果 URL 时继续下载而不重复提交生成。问题不在于缺少项目归属，而在于控制粒度过大：

1. 前端 `busyAction` 是整个工作区的单一全局锁，一个媒体请求未结束时会阻止项目内其他操作；
2. 后端 `withRunAbort()` 和 `cancelRun()` 以整个 `runId` 管理控制器与待办，无法只停止某一个资产或镜头；
3. 成功任务会从 `pending` 删除，失败、停止、已完成没有统一的可见历史；
4. “取消”没有区分本地 HTTP 等待、结果下载和云端付费任务，容易让用户误以为费用已经撤销；
5. 批量操作缺少单项状态和单项恢复入口，一个小环节异常会表现成整个项目不能继续。

因此本轮不是增加一个更大的任务中心，而是把现有项目待办升级为项目内任务账本，并把锁和中止从项目级缩小到任务级。

## 3. 产品原则

### 3.1 项目是唯一边界

- 任务在提交时冻结 `runId`、任务类型、目标 ID 和输出路径；
- 异步完成、继续下载或恢复查询时始终使用提交时的 `runId`，不得重新读取当前选中的项目；
- `run.json` 天然位于项目运行目录，不重复保存 `projectId`；
- 切换项目只切换抽屉的数据源，不停止原项目已经提交的云端任务；
- App 不自动替用户恢复旧任务。用户回到对应项目后，通过任务卡显式“继续查询”或“继续下载”。

### 3.2 产物与操作分工

- 中间栏继续显示资产图、分镜图和视频成果；
- 右栏继续承载当前阶段的生成与修改操作；
- 顶部任务抽屉只显示任务状态、耗时、错误和恢复操作，不重复展示大图、提示词或 Markdown 正文；
- 当前目标卡片与任务抽屉读取同一任务记录，不维护两份状态。

### 3.3 付费动作必须明确

- `继续查询`、`继续下载`不得再次提交付费生成；
- 只有`重新生成`明确创建新的付费任务；
- 用户停止本地等待时，必须提示云端任务可能仍在运行并扣费；
- 只有上游真实提供取消接口且返回取消成功，按钮才能叫“取消云端任务”。本轮没有该能力，不提供此按钮。

## 4. UI 合同

### 4.1 顶部入口

在项目选择器所在工具栏增加一个图标按钮：

- 使用现有图标库的任务/历史图标，不新增图标依赖；
- 徽标只统计当前项目 `queued`、`generating`、`downloading` 三种未完成任务；
- 没有未完成任务时不显示数字；
- 点击打开右侧窄抽屉，再次点击或按 `Esc` 关闭；
- 抽屉覆盖在现有工作区之上，不挤压或重排三栏；
- 新建项目和项目选择器的现有位置、尺寸与交互保持不变。

### 4.2 当前项目任务抽屉

抽屉按 `updatedAt` 倒序显示当前项目任务。每项只包含：

```text
[类型] 目标名称
状态 · 已用时间或完成时间
简短错误（失败时）
[与当前状态匹配的操作]
```

类型文案固定为“资产图”“分镜图”“视频”。目标名称来自现有资产标签或镜头编号；找不到标签时回退到持久化的 `targetLabel`，不能显示空白卡。

抽屉空态只显示“当前项目还没有媒体任务”，不增加教程或引导卡。

### 4.3 卡片就地状态

中间栏的资产或镜头卡片显示同一任务的紧凑状态：

```text
生成中 02:31        [停止等待]
下载中              [停止下载]
等待继续查询        [继续查询] [放弃]
等待继续下载        [继续下载] [放弃]
生成失败            [重新生成]
下载失败            [继续下载] [放弃]
已完成
```

- 卡片和抽屉的按钮调用同一 action；
- 正在生成某个目标时，只禁用该目标的重复生成按钮；
- 批量按钮仍可启动其他尚无活动任务的目标；
- 已成功项不因再次点击批量生成而重复提交；
- 不在卡片新增“历史”按钮，历史只从顶部任务入口查看。

## 5. 统一任务状态机

P0 固定六个持久化状态：

```text
queued
generating
downloading
success
failed
stopped
```

其中 `stopped` 必须结合 `resumeFrom` 判断后续动作：

```text
queued -> generating -> downloading -> success
             |              |
             v              v
           failed         failed
             |              |
             v              v
        重新生成        继续下载

generating  --停止等待--> stopped(resumeFrom: generating)
downloading --停止下载--> stopped(resumeFrom: downloading)
stopped(generating) --继续查询--> generating
stopped(downloading) --继续下载--> downloading
```

状态定义：

| 状态 | 含义 |
| --- | --- |
| `queued` | 本地已创建任务，尚未提交或正等待批量并发槽位 |
| `generating` | 已开始提交或等待云端结果；有 `taskId/pollRoute` 时可恢复查询 |
| `downloading` | 已取得 `resultUrl`，正在写入项目文件 |
| `success` | 输出文件已经成功落入提交时冻结的项目路径 |
| `failed` | 当前阶段明确失败；是否可继续由保留的任务字段决定 |
| `stopped` | 用户终止本地等待或下载，不代表云端已取消 |

不得新增模糊的 `processing`、`pending`、`cancelled` 同义状态。

## 6. 操作语义

### 6.1 停止等待

- 只中止该任务当前本地同步 HTTP 请求或轮询；
- 不清空同项目其他任务，不删除 `run.json` 记录；
- 如果已经获得 `taskId/pollRoute`，保存它并进入 `stopped(resumeFrom: generating)`；
- 如果上游是同步长请求且尚未返回任务 ID，仍进入 `stopped`，并明确提示“已停止本地等待，云端可能仍在执行；目前无法恢复查询”；
- 不声称取消、退款或停止计费。

### 6.2 停止下载

- 只中止该任务的本地下载；
- 保留 `resultUrl`、`outputPath` 和已落盘临时文件处理所需信息；
- 进入 `stopped(resumeFrom: downloading)`，以后允许继续下载；
- 不重复提交生成。

### 6.3 继续查询

- 仅在存在 `pollRoute` 或可查询的 `taskId` 时显示；
- 复用原任务 ID 查询结果；
- 查询成功后进入下载，查询明确失败后进入 `failed`；
- 临时网络错误保留恢复信息，不转成新的付费任务。

### 6.4 继续下载

- 仅在存在 `resultUrl` 时显示；
- 复用原结果 URL 下载到原 `outputPath`；
- 下载失败仍保留 URL，允许再次继续；
- 不调用图片或视频生成接口。

### 6.5 重新生成

- 这是唯一会再次提交付费生成的恢复操作；
- 只对当前失败或无法恢复的单项生效；
- 创建新的任务记录，旧记录保留在当前项目历史中；
- UI 在提交前使用明确文案“重新生成”，不能把它伪装成“重试下载”。

### 6.6 放弃

- 将该条待办标记为不再处理并从活动列表移除；P0 直接删除该条未完成任务记录；
- 不删除已经成功落盘的资产图、分镜图、视频或其他项目文件；
- 不请求云端退款，也不影响同一批次其他项；
- 对 `success` 历史不提供“放弃”。

## 7. `run.json` 数据合同

继续使用每个项目现有的 `run.json`，不新增 SQLite、全局 JSON 或跨项目索引。现有 `pending` 升级为可保留终态的 `tasks`：

```ts
type MediaTaskStatus =
  | 'queued'
  | 'generating'
  | 'downloading'
  | 'success'
  | 'failed'
  | 'stopped'

interface ProjectMediaTask {
  id: string
  batchId?: string
  kind: 'asset' | 'storyboard' | 'video'
  targetId: string
  targetLabel: string
  status: MediaTaskStatus
  resumeFrom?: 'generating' | 'downloading'
  taskId?: string
  pollRoute?: string
  resultUrl?: string
  outputPath: string
  error?: string
  createdAt: string
  startedAt?: string
  updatedAt: string
  finishedAt?: string
}
```

约束：

- 不保存 `projectId`，因为文件所在 `runId` 已经是项目边界；
- `targetId` 对资产使用资产 ID，对分镜图和视频使用稳定镜头 ID；不得只依赖会因排序变化的数组下标；
- `outputPath` 继续使用项目运行目录内相对路径；
- 不把提示词、参考图二进制或 API Key 复制进任务记录；这些继续由现有项目状态和受控文件承担；
- 每次状态变化通过现有临时文件加原子重命名写回，避免并发单项任务互相覆盖；
- 旧 `pending` 记录首次读取时映射为 `tasks`：有 `resultUrl` 的记录映射为 `stopped/downloading`，有 `pollRoute` 的记录映射为 `stopped/generating`；无法恢复的旧记录映射为 `failed`；
- 迁移只读当前项目自己的 `run.json`，不扫描其他项目目录；
- 本轮不做分页、搜索、筛选或历史清理设置。项目任务量实际造成性能问题后，再增加简单上限或归档。

## 8. 单项执行与批量规则

### 8.1 单项控制器

运行时控制器从 `Map<runId, Set<AbortController>>` 收窄为按任务 ID 定位：

```text
runId + taskId -> AbortController
```

- 停止只命中一个任务；
- 项目切换不销毁仍在运行任务的控制器；
- 抽屉关闭不影响执行；
- App 退出由系统终止本地请求，持久化任务保留为可恢复状态；
- 不再提供会清空整个项目全部待办的 `cancelRun()` 给普通单项按钮。

### 8.2 批量生成

- 点击“生成所有资产图”“生成所有分镜图”或批量视频时，先为每个目标建立独立任务；
- 每项独立提交、持久化、下载和结束；
- 某项失败、停止或被放弃，不中止同批其他项；
- 已有 `success` 或活动任务的目标跳过，不重复提交；
- 并发数量沿用现有批量执行策略，本 SDD 不新增队列框架或可配置并发设置；
- `batchId` 只用于显示同一批次关系和测试，不承担状态锁。

### 8.3 页面可操作性

媒体执行期间允许：

- 新建项目、切换项目；
- 查看和编辑当前项目文稿；
- 打开 Markdown、预览已有图片和视频；
- 对其他没有活动任务的资产或镜头发起操作。

只有会破坏当前目标输入或输出的操作需要在该目标任务运行时禁用。禁止继续使用一个 `busyAction` 锁住整个页面。

## 9. 三类媒体的复用方式

| 类型 | `targetId` | 成功结果 | 单项重试入口 |
| --- | --- | --- | --- |
| 资产图 | 资产稳定 ID | 对应资产 AI 版本 | 资产卡或任务抽屉 |
| 分镜图 | 镜头稳定 ID | 对应镜头图片路径 | 镜头卡或任务抽屉 |
| 视频 | 镜头稳定 ID | 对应镜头视频路径 | 镜头卡或任务抽屉 |

三类任务只在“提交参数”和“结果回写目标”上不同，状态机、停止、继续、持久化和抽屉 UI 完全复用。

声音生成当前是单项且位于独立步骤，本轮不纳入任务抽屉；验证三类视觉媒体稳定后再决定是否接入，不为它预留额外抽象。

## 10. 启动与项目切换行为

1. App 启动只恢复最近项目的文稿和项目状态，不自动执行旧媒体待办；
2. 进入项目时读取该项目 `run.json`，渲染任务徽标、抽屉和卡片状态；
3. 对上次异常退出时留下的 `generating/downloading`，显示为可恢复的停止态，而不是伪装成当前仍在运行；
4. 用户显式点击“继续查询”或“继续下载”后才重新建立运行时控制器；
5. 切换项目不把 A 的状态、错误或运行锁带到 B；
6. A 的任务若在后台完成，结果仍写回 A 提交时冻结的路径；用户回到 A 后看到最新状态；
7. 新建项目始终可用，不受其他项目媒体任务影响。

本文取代 `docs/wiki/架构/分段式AI短视频工作流.md` 中“重新打开应用时继续待下载任务”的旧行为。新规则是：重启后保留并展示可恢复任务，但必须由用户显式继续。

## 11. 错误显示

- 错误属于任务，不写入会影响整个页面的全局 `error`；
- 卡片显示一句可行动的错误，抽屉可显示完整但仍经过清理的错误文本；
- 下载错误与生成错误必须区分，因为前者可以复用结果 URL，后者才可能需要重新付费；
- 上游明确失败后立即停止等待并进入 `failed`；临时网络错误保留恢复字段；
- 没有 `taskId/pollRoute/resultUrl` 的同步请求被停止后，明确显示“无法恢复查询，可稍后确认云端状态或重新生成”，不能提供无效的“继续下载”。

## 12. 明确不做

- 不做跨项目任务中心；
- 不做新的页面、底部历史区或大型悬浮窗；
- 不改变现有三栏宽度和布局；
- 不引入数据库、消息总线、后台守护进程或新依赖；
- 不复制主 APP 的完整 `mediaTaskStore`；
- 不做跨设备任务同步；
- 不提供不存在的云端取消或退款能力；
- 不让 App 启动后自动恢复付费任务或下载；
- 不把成功媒体复制到任务历史，历史只保存项目文件路径引用；
- 不在本轮接入声音任务、FFmpeg 合成任务或 Pinterest 搜索任务。

## 13. 实施顺序

### P0-1：任务合同与单项控制

1. 扩展 `PendingCloudTask` 为统一项目媒体任务合同；
2. 将控制器和中止入口改为 `runId + taskId`；
3. 保留成功、失败和停止状态，不再在完成或失败时无条件删除记录；
4. 增加旧 `pending` 的最小兼容读取；
5. 先接通资产图单项生成、停止、继续下载和重新生成。

验证：一个资产图下载卡住时，可以停止该项、切换项目、编辑文稿，并能用原 URL 继续下载且生成接口提交次数不增加。

### P0-2：批量隔离与 UI

1. 批量资产图改为每项独立状态；
2. 顶部增加当前项目任务图标、徽标和右侧窄抽屉；
3. 资产卡与抽屉接入同一 action；
4. 删除媒体任务对页面级 `busyAction` 的依赖。

验证：五个资产中一项失败、另一项停止，其余三项仍能完成；新建项目和项目切换始终可点击。

### P1：分镜图与视频复用

1. 分镜图使用同一任务合同和抽屉；
2. 视频使用同一任务合同和抽屉；
3. 覆盖项目 A 运行中切换 B、完成结果仍写回 A 的回归；
4. 更新 Wiki 中被本 SDD 取代的自动恢复说明。

验证：三类视觉媒体不产生第二套状态机、抽屉或持久化文件。

## 14. 验收标准

1. 顶部任务徽标只统计当前项目的未完成任务，切换项目后立即变化；
2. 抽屉只显示当前项目任务，不出现其他项目记录；
3. 媒体任务执行期间，新建项目、切换项目、文稿查看和编辑仍可操作；
4. 同一批五个资产图中一项失败，不阻断其他四项；
5. 停止某一任务只中止该项，不清空同项目其他待办；
6. “停止等待”明确提示云端可能仍执行和扣费，不显示“已取消”；
7. 已有结果 URL 的下载失败任务点击“继续下载”后不再次调用生成接口；
8. “重新生成”只创建当前目标的新付费任务，旧历史仍可追溯；
9. 放弃未完成任务不删除任何已经落盘的项目媒体文件；
10. App 重启后不自动执行旧任务，进入项目能看到并显式恢复；
11. 在项目 A 提交任务后切换到 B，A 的结果只写回 A；
12. 资产图、分镜图、视频共用一个任务类型、一个状态机、一个抽屉和一组操作语义；
13. 旧 `run.json.pending` 可读取并迁移，不导致项目卡死或重复付费；
14. 自动化测试至少覆盖单项停止、批量失败隔离、继续下载不重复提交、项目切换写回归属和重启不自动恢复；
15. 类型检查、现有媒体合同测试和 `git diff --check` 通过。
