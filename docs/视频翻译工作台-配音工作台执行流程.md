# 视频翻译工作台“配音工作台”执行流程

> 状态：配音工作台主体与成片承接已接入 FunASR 整块英文词级对齐；相邻 cue 尾词重复的边界余量仍待后续小幅收紧（2026-08-10）。
>
> 范围：只定义视频翻译第二阶段“配音工作台”。字幕工作台和成片工作台另行定义。

## 1. 目标

配音工作台只做一件事：根据人工确认的最终时间戳剧本和角色参考音，生成完整的目标语言表演音频。

```text
最终时间戳剧本
-> 确认每个角色的声音和参考音
-> jc-luyinpeng 生成最终录音棚配音提示词
-> Seed Audio 生成全局配音
-> 人工试听
-> 进入成片工作台
```

不再增加：

- 配音项目总监。
- 配音项目总监节奏稿。
- 独立分段声音设计。
- 第二份剧情梗概或对白脚本。
- Whisper 识别和对白时间对齐。
- 原片人声分离、混音或烧录。

最终时间戳剧本已经包含角色、表演方向、目标语言对白和预期时间。`jc-luyinpeng` 直接承担声音导演职责，不再由其他模型重复分析。

## 2. 唯一主体输入

配音工作台只接受字幕工作台生成的：

```text
wiki/翻译/<episodeId>/最终时间戳剧本.md
```

进入时必须验证：

- `status` 为 `confirmed`。
- `finalScriptId` 存在。
- `scriptHash` 与文件当前内容重新计算后的结果一致。
- 每条对白有唯一 `cueId`。
- 每条对白有 `translationRoleId`、角色名、表演方向和译文。
- 每个 `translationRoleId` 都能解析到角色记录。

字段职责：

```text
原文：只用于理解剧情和翻译追溯，不参与发音
译文：目标语言唯一正式发音文本
表演：该句动作、情绪、语速、停顿和说话方式
时间戳：原片中该句对白的预期位置，不写入 Seed Audio 提示词
```

配音工作台不得读取未审核的逐片扒片文件来恢复、增加或改写台词。

## 3. 页面结构

继续使用两个页签：

```text
角色配音
全局配音
```

### 3.1 角色配音

角色列表只显示最终时间戳剧本中实际发言的角色。每个角色显示：

```text
角色名
translationRoleId
screenshotId（存在时）
角色声音身份提示词
当前参考音播放器
voiceProfileId
确认状态
```

按钮：

```text
生成角色提示词
上传参考音 / 按提示词生成参考音 / 选择已有参考音
确认角色声音
```

### 3.2 全局配音

全局页只保留：

```text
生成全局配音提示词
可编辑的最终提示词（超过 3 个角色时按块显示）
生成全局配音
全局配音播放器
历史生成版本（选择当前采用版本）
进入成片工作台
```

`生成全局配音` 替换原来的 `重新生成并对齐连续对白`。不再显示“配音项目总监”“生成分段声音设计”或“连续对白实验”。

## 4. 角色声音

### 4.1 角色声音提示词

`生成角色提示词` 只为当前角色生成稳定的声音身份：

```text
年龄感
性别感
身份或职业
目标语言口音
音高
声线
音色质感
吐字
气息特征
```

输入使用该角色在最终时间戳剧本中的全部台词、角色名和截图。瞬时的愤怒、哭泣、醉酒等不写进稳定声音身份，它们已经保存在每句对白的表演方向中。

角色声音身份用于：

1. 生成角色参考音。
2. 写入 `jc-luyinpeng` 输出中的角色定义行。

### 4.2 唯一声音 ID

角色参考音只使用一个正式 ID：

```text
voiceProfileId
```

`voiceProfileId` 解析到当前采用的参考音文件。不要再创建内容重复的 `referenceAudioId`。

无论参考音来自上传、AI 生成还是已有声音库，确认后都统一得到 `voiceProfileId`。

### 4.3 确认角色声音

用户试听参考音并点击：

```text
确认角色声音
```

程序保存：

```text
translationRoleId
roleName
voiceProfileId
voiceIdentityText
confirmedAt
```

确认规则：

- `translationRoleId` 必须来自最终时间戳剧本。
- `voiceProfileId` 必须能解析到有效参考音文件。
- `voiceIdentityText` 非空。
- 同一个 `translationRoleId` 只能有一个当前采用的 `voiceProfileId`。
- 更换声音身份文字或参考音后，该角色自动变回未确认。
- `roleName` 只保存确认时的显示快照，声音绑定始终以 `translationRoleId` 为准；角色改名后显示当前最终剧本中的名称。

所有实际发言角色都确认后，才开放 `生成全局配音提示词`。

## 5. 最小分块规则

Seed Audio 每次最多接收 3 个角色参考音。分块只解决这个物理限制，不负责导演创作。

- 整集只有 1 至 3 个角色：全片作为一个配音块。
- 整集超过 3 个角色：本机按 `cueId` 时间顺序扫描；当前块持续加入对白，下一句引入第 4 个不同角色时，在该句之前结束当前块并从该句建立新块。
- 不调用模型决定分块。
- 不改写、遗漏、重复或调整对白顺序。
- 不因为原片时间戳长短切块。
- 同一句对白不能跨块。
- 同一角色可以出现在多个配音块中，始终复用同一个 `voiceProfileId`。

每块使用：

```text
voice-block-001
voice-block-002
...
```

块编号只在当前 `scriptHash` 的配音安排内有效。每块保留有序 `cueIds`，以及按第一次发言顺序排列的 `translationRoleId + voiceProfileId + referenceIndex`。生成音频后必须使用 `voiceVersionId + voiceBlockId` 定位具体块音频，不能单独使用 `voiceBlockId`。

## 6. jc-luyinpeng

### 6.1 唯一任务

`skills/jc-luyinpeng/SKILL.md` 是配音工作台唯一的声音导演 Skill。

它直接读取：

```text
finalScriptMarkdown：完整最终时间戳剧本 Markdown 全文
currentCueIds：当前配音块 cueIds
references：本块角色的 translationRoleId、roleName、voiceProfileId、voiceIdentityText、referenceIndex
correction：校验失败原因（仅修正输出时可选）
```

目标语言已经包含在最终时间戳剧本中，不重复传入。最终时间戳剧本是主体输入；角色声音身份和参考音映射只是辅助输入。不再传入重复的 `segments`、`storyContext`、`emotion`、剧情梗概、对白脚本、配音项目总监稿、分段声音设计稿或额外任务说明。

Skill 使用完整剧本理解上下文，但只输出当前配音块 `cueIds` 对应的译文；其他块的台词不能出现在本块提示词中。

### 6.2 参考音顺序

本块角色按第一次发言顺序映射：

```text
第一位角色 -> @音频1
第二位角色 -> @音频2
第三位角色 -> @音频3
```

角色定义、参考音数组、版本清单和 API 请求必须使用同一顺序。每块必须持久化以下有序数组；`translationRoleId` 用于程序校验，不写入最终 Seed Audio 提示词。

```json
[
  {
    "translationRoleId": "role-...",
    "voiceProfileId": "voice-...",
    "referenceIndex": 1
  }
]
```

### 6.3 唯一输出格式

Skill 只输出可直接提交给 Seed Audio 的提示词正文：

```text
这是一段三个专业的配音表演艺术家在顶级录音棚内的配音片段。

风千雪是20至25岁女性豪门千金，美式英语发音自然，中高音调，声线清亮干脆，带有轻微气声共鸣与微尖的明亮音色质感，饰演者为@音频1。
白露是20至25岁女性，美式英语发音自然，中高音调，声线丝滑流畅，吐字清晰，带有轻微气声与潜藏的冷感质感，饰演者为@音频2。
服务生是25至35岁男服务生，中低音调，声音温和，吐字清晰，共鸣流畅，气息控制干净，语气礼貌专业，饰演者为@音频3。

风千雪（因被放鸽子极度气愤，音量抬高，充满受辱的尖锐与委屈）：“How dare that Si guy stand me up!”
白露（立刻顺着话头拱火，语气充满讨好与煽动）：“Exactly, Cousin.”
服务生（中速温和介入，礼貌客气，带标准的服务业职业感）：“Hello, how can I help you ladies tonight?”
```

输出规则：

- 开头根据角色数量使用“一个”“两个”或“三个”。
- 每个角色只定义一次，并严格绑定对应的 `@音频N`。
- 当前配音块每个 `cueId` 的译文出现且只出现一次，顺序不变；不输出其他块的台词。
- 每句使用最终时间戳剧本中的表演方向，并允许 Skill 为演员补足必要的声音表演细节。
- 同一角色的情绪和身体状态承接上一句，换人时承接对方的动作和潜台词。
- 只把译文放进引号，绝不把原文作为发音台词。
- 不输出时间戳、`cueId`、角色 ID、标题、解释、音乐、环境声或音效说明。
- 不写“连续配音”等额外限定；开头只使用上述录音棚句式。

## 7. 生成全局配音提示词

点击 `生成全局配音提示词` 时：

1. 验证当前 `finalScriptId` 和 `scriptHash`。
2. 验证所有实际发言角色已确认声音。
3. 按最小分块规则生成配音块。
4. 每块调用一次 `jc-luyinpeng`。
5. 把输出解析为有序对白行，逐行校验数量、对应位置的角色名、完整译文和 `@音频N` 映射。
6. 保存提示词并显示在全局配音页供用户检查或编辑。

只有一个配音块时显示一份提示词。存在多个配音块时按块分别显示和编辑；文档中的块标题只用于产品管理，提交 Seed Audio 时只发送该块的提示词正文。

提示词校验失败时，把具体错误交给同一个 Skill 修正一次。仍然失败则停止，不调用 Seed Audio。

用户手工修改提示词后必须再次执行相同校验。校验按对白行位置比较，不按全文搜索译文，因此重复出现的相同短句仍能正确对应各自 `cueId`。只要每行正式译文和角色顺序不变，就允许调整角色声音描述和表演说明。

## 8. 生成全局配音

只有以下条件全部满足时，才能点击 `生成全局配音`：

- 当前最终时间戳剧本有效。
- 所有实际发言角色声音已确认。
- 每个配音块都有通过校验的最终提示词。
- 每个角色的 `voiceProfileId` 能解析到参考音文件。

执行：

1. 每次点击都创建新的 `voiceVersionId`，再按块把最终提示词和一至三个参考音提交给 Seed Audio。
2. 每块成功后立即写入当前生成目录；只有全部块、试听和 manifest 完成后才进入可选版本列表。
3. 任一块失败时当前版本不进入可用列表；再次点击会创建新的 `voiceVersionId`，避免把半成品误当成完整版本。
4. 全部完成后生成版本清单和连续试听文件，并把新版本设为 `activeVoiceVersionId`。

连续试听文件只用于人工试听，不承担原片时间对齐。配音工作台不使用时间戳裁切生成音频，也不要求 Seed Audio 严格复刻原片句长。

## 9. 人工试听和进入成片工作台

用户试听当前全局配音版本，可以从历史生成版本中切换当前采用版本。满意后点击：

```text
进入成片工作台
```

门禁：

- 所有配音块生成成功。
- 连续试听文件可播放。
- `activeVoiceVersionId` 指向一个完整成功版本。
- 当前采用版本绑定当前 `finalScriptId`、`scriptHash` 和角色声音映射。
- 当前版本的每个块音频均存在、可读取，文件 SHA-256 与版本清单一致。

进入成片工作台时只传递当前采用版本：

```text
finalScriptId
scriptHash
activeVoiceVersionId
voiceVersionId
按顺序排列的 voiceBlockId
每块有序 cueIds
每块原始音频路径和音频 SHA-256
每块有序 translationRoleId + voiceProfileId + referenceIndex
连续试听文件路径
```

历史版本继续保留，但成片工作台不能自行选择“最新版本”，只能消费 `activeVoiceVersionId` 指向的版本。

进入成片工作台后才执行：

```text
分离并移除原片人声
-> FunASR 整块识别配音的真实发音时间
-> 按顺序约束和文本相似度绑定 cueId
-> FFmpeg 按真实发音切句并贴回原时间戳
-> 与原片背景声合成目标语言音轨
-> 烧录字幕并生成翻译成片
```

## 10. ID 和版本

配音工作台只使用：

```text
finalScriptId：最终时间戳剧本版本
scriptHash：最终时间戳剧本完整校验
cueId：对白稳定 ID
translationRoleId：角色稳定 ID
voiceProfileId：角色当前采用声音的唯一 ID
voiceBlockId：当前 scriptHash 内的配音块 ID
voiceVersionId：一次完整全局配音结果 ID
activeVoiceVersionId：当前人工选中并交给成片工作台的 voiceVersionId
```

不再创建 `referenceAudioId`、配音项目总监 ID 或分段声音设计 ID。

`voiceVersionId` 在每次点击 `生成全局配音` 时由本机生成。相同剧本、参考音和提示词也允许生成多个不同表演版本，任何新结果都不能覆盖历史版本。半成品版本不写入可用版本索引，再次点击从新版本开始。

版本清单保存该次使用的 `scriptHash`、角色声音映射和最终提示词快照，用于验证和复现，不再增加 `promptId`、`promptHash` 或其他版本 ID。

## 11. 失效规则

| 修改内容                  | 保留                         | 失效                                         |
| ------------------------- | ---------------------------- | -------------------------------------------- |
| 最终剧本发生变化          | 已确认且仍存在角色的声音绑定 | 全局提示词、全局配音、成片                   |
| 目标语言发生变化          | 声音库中的历史参考音         | 所有角色声音确认、全局提示词、全局配音、成片 |
| 新增发言角色              | 其他角色声音确认             | 新角色待确认；全局提示词、全局配音、成片     |
| 删除发言角色              | 该角色声音档案仍留在声音库   | 当前角色列表、全局提示词、全局配音、成片     |
| 修改角色声音身份或参考音  | 其他角色声音确认             | 当前角色确认、全局提示词、全局配音、成片     |
| 只修改全局提示词表演说明  | 角色声音确认                 | 全局配音、成片                               |
| 单块 Seed Audio 失败      | 其他成功块                   | 当前失败块                                   |
| 切换 activeVoiceVersionId | 所有历史配音版本             | 配音对白时间戳、混音和成片                   |

失效只改变当前采用关系，不删除声音库参考音和历史成功音频。

## 12. 文档和产物

```text
wiki/翻译/<episodeId>/最终时间戳剧本.md
wiki/翻译/声音/<translationRoleId>-角色声音.md
wiki/翻译/<episodeId>/声音/全局配音提示词.md
wiki/翻译/<episodeId>/声音/全局配音版本/<voiceVersionId>/manifest.json
wiki/翻译/<episodeId>/声音/全局配音版本/<voiceVersionId>/voice-block-NNN.wav
wiki/翻译/<episodeId>/声音/全局配音版本/<voiceVersionId>/连续试听.wav
```

`全局配音提示词.md` 只有一个配音块时直接保存正文；多个配音块时以 `voiceBlockId` 分节保存，每节正文仍必须符合 `jc-luyinpeng` 唯一输出格式。

`manifest.json` 不复制最终时间戳剧本正文，只保存：

```text
voiceVersionId
finalScriptId
scriptHash
createdAt
Seed Audio 模型和生成任务信息
每块 voiceBlockId
每块有序 cueIds
每块最终提示词
每块有序 translationRoleId + voiceProfileId + referenceIndex
每块原始音频相对路径、SHA-256 和时长
连续试听文件相对路径、SHA-256 和时长
```

## 13. 验收标准

1. 配音工作台只消费最终时间戳剧本和已确认角色参考音。
2. 不生成配音项目总监、节奏稿或独立分段声音设计。
3. `voiceProfileId` 是唯一声音 ID，不存在重复的 `referenceAudioId`。
4. 所有发言角色未点击 `确认角色声音` 时，不能生成全局配音提示词或音频。
5. `jc-luyinpeng` 直接使用完整最终时间戳剧本，输出严格匹配录音棚标准格式。
6. Seed Audio 只朗读译文，不朗读原文、表演说明、时间戳或 ID。
7. 一至三个角色只生成一个配音块；超过三个角色才进行最小连续分块。
8. 配音工作台只生成人工试听通过的原始全局配音，不做时间识别、切句、混音或成片。
9. 点击 `进入成片工作台` 后，才开始实际发音时间识别和后期处理。
10. 每次生成都有新的 `voiceVersionId`，成片只消费人工选中的 `activeVoiceVersionId`。
11. 每个配音块持久化有序参考音映射，任何阶段都不会交换角色与 `@音频N`。
