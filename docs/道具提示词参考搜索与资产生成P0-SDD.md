## 1. 结论

资产阶段固定为三个页面级显式动作，不在资产卡片上增加上传、确认或重复操作按钮：

```text
[生成资产提示词] -> [搜索下载参考图（可跳过）] -> [生成资产图]
```

- 提示词是必需主设计，参考图只是可选增强；
- 没有参考图也允许直接生成资产图；
- 三个按钮每类只出现一次，作用于当前资产阶段，不在每张卡片重复一组；
- 用户点击角色、场景或道具后，该资产成为当前选中项；
- 右栏始终保留一个修改意见文本框和“确认修改”，只修改当前选中资产的设计与生图提示词，不搜索、不下载、不生图；
- 修改结果只在中间栏对应资产 Markdown 中显示，右栏不重复展示输出；
- 资产图生成成功即成为该资产当前版本，不再增加“确认资产”按钮。

这里的“生成资产图”是直接调用用户选择的图像模型，不是调用 `jc-gpt-image` 或其他通用生图 Skill。资产链路只保留“资产提示词 Skill + 搜索参考 Skill + 图像模型”三类职责。

```text
jc-character-prompt ──────────> 角色设计 + 生图提示词 + 一条有效搜索查询
jc-scene-prompt ──────────────> 场景设计 + 生图提示词 + 一条有效搜索查询
jc-prop-prompt ───────────────> 道具设计 + 生图提示词 + 一条有效搜索查询
jc-asset-reference-search ────> 可选参考图 + 本地受控路径 + 来源元数据
生图提示词 + 可选参考图 ─────> 用户选择的图像模型 ─────> 资产图
```

## 2. 当前问题

1. 三类资产尚未统一执行各自完整 Skill 合同，道具运行时还曾只保留一段简短 `prompt`，没有读取 `references/prop-format.md`。
2. 专业 Skill 原有的完整设计字段可能在 App 简化合同中丢失。
3. 用户上传图只以布尔值告知文本模型，模型没有形成可追溯的完整道具设计。
4. 搜索下载目前藏在 Electron 实现中，没有独立 `jc-asset-reference-search` Skill 合同，职责边界不可见、不可复用。
5. 历史通用生图 Skill 与资产提示词 Skill 职责重叠；现在提示词已经由道具、场景、角色各自的专业 Skill 产出，不应再经过第二层通用提示词 Skill。

## 3. 固定用户流程

### 3.1 生成资产提示词

输入：确认文稿、项目风格、比例和已有资产。

同一个“生成资产提示词”按钮并行执行三类专业 Skill：

- 角色：`jc-character-prompt`；
- 场景：`jc-scene-prompt`；
- 道具：`jc-prop-prompt`。

`jc-prop-prompt` 必须输出每个重要道具：

```json
{
  "assets": [{
    "role": "prop",
    "label": "学生时代餐桌",
    "description": "叙事用途",
    "required": true,
    "design": {},
    "generationPrompt": "可直接提交给生图模型的完整中文提示词",
    "searchQuery": "student school desk"
  }]
}
```

- `design` 必须满足 `references/prop-format.md` 的完整 JSON 字段；
- `generationPrompt` 必须完整表达 `design`，不是几十字摘要；
- `searchQuery` 只输出一条查询，但必须包含 3-5 个有辨识度的英文词，来自资产完整设计，而不是一个泛化对象词；
- 角色组合身份/原型、关键外貌和 `character reference`；场景组合地点/功能、关键氛围或结构和 `environment design`；道具组合类型、关键结构/材质/用途和 `prop design`；
- 角色和场景同样保存各自 Skill 的完整设计与最终生图提示词，不允许统一压缩成通用短提示词；
- App 保存完整结构化结果，并在对应资产 Markdown 中显示。

### 3.2 搜索并下载参考图

- “搜索参考”明确执行 `jc-asset-reference-search`；
- Skill 负责搜索词使用、候选判断和结果合同，Electron 受控工具负责联网、下载和写入项目目录；模型不得伪装成已经下载文件；
- 页面只提供一个“搜索下载参考图”按钮，按当前三类资产提示词中的简短 `searchQuery` 处理尚无参考图的资产；
- 按 `searchQuery` 联网搜索，自动采用相关性最高且可直接下载的一张图片；
- 只使用 Pinterest 搜索，按结果顺序尝试 `i.pinimg.com` 原图，并记录对应 Pin 页面；Pinterest 不可访问时明确失败，不回退其他图库；
- 下载到当前项目受控目录，记录搜索词、原图 URL 和来源页面 URL；
- 新搜索结果成为当前参考版本，旧参考和 AI 版本继续保留；
- 搜索失败只显示错误，不阻断“生成资产图”；
- 搜索只补齐当前没有任何上传或联网参考版本的资产，已有参考的资产保持不变；用户可删除不满意的参考版本，删空后再次搜索只补该资产；
- P0 UI 不增加“上传参考”按钮；历史上传版本可继续读取，但不占用本阶段三个主操作位。

### 3.3 生成资产图

- App 直接调用当前固定的 `gpt-image-2` 图像模型，不调用 `jc-gpt-image` Skill；后续增加图像模型选择器时再扩展此合同；
- 没有参考版本：使用 `generationPrompt` 走文生图；
- 有上传或联网参考：使用同一提示词与当前参考图走参考图生图；
- 提示词负责项目风格和完整设计，参考图负责可借鉴的结构与细节；
- 不要求参考图本身符合项目风格；
- 页面只提供一个“生成资产图”按钮，生成当前尚未生成的角色、场景和道具资产；单项失败可重试，不重复生成已成功项；
- 生成结果保存为独立 AI 版本并自动成为当前版本，不再要求额外确认。

## 4. UI 合同

资产工作区右栏只提供三个页面级主按钮，中栏只显示资产卡片和 Markdown 结果：

```text
[生成资产提示词] [搜索下载参考图] [生成资产图]
```

- 缩略图显示当前选中版本并支持放大预览；
- 版本选择标明“联网参考 / 上传原图 / AI 版本”；
- 当前选中上传或联网参考时提供删除按钮；该动作只移除参考版本记录，不删除 AI 资产版本，文件本体暂不物理销毁；
- 角色、场景、道具卡片本身不放“上传”“搜索”“生成”“确认”按钮；
- 点击资产卡片即选中对应提示词，不触发生成或搜索；
- 右栏上方是修改意见文本框与“确认修改”，底部是三个资产操作按钮；确认修改只执行当前选中资产对应的专业 Skill，结果回写中栏 Markdown；
- 右栏不展示声音五项、资产 JSON、提示词正文、版本详情或历史结果；
- 不提供“确认资产”按钮，生成成功的资产图自动进入后续分镜可绑定集合；
- 不增加自动联网开关，不增加搜索设置页，不增加多候选选择器。

三个按钮顺序固定、状态清晰：没有提示词时只有“生成资产提示词”可用；提示词完成后可搜索参考，也可跳过搜索直接生成资产图。

## 5. 数据合同

`ReferenceAsset` 对角色、场景、道具统一保存：

- `design`：对应专业 Skill 的完整设计；
- `searchQuery`：唯一一条、由 3-5 个有辨识度的英文词组成的 Pinterest 查询；
- `generationPrompt` 继续落入现有 `prompt`，保持生图调用兼容。

`AssetVersion.source` 增加 `search`：

- `upload`：用户上传参考；
- `search`：联网下载参考；
- `generated`：AI 资产图。

联网参考版本增加可选来源元数据：`sourceUrl`、`sourcePageUrl`、`searchQuery`。

## 6. Skill 执行合同

- “生成资产提示词”分别执行 `jc-character-prompt`、`jc-scene-prompt`、`jc-prop-prompt`；
- 执行器加载每个 Skill 直接引用的格式文件；道具必须加载 `references/prop-format.md`，不得只读主文件；
- 三个专业 Skill 都只输出各自完整 `design`、`generationPrompt` 和一条 3-5 个核心英文词的 `searchQuery`，不得联网、下载或写入参考图；
- “搜索参考”只执行 `skills/jc-asset-reference-search/SKILL.md`；
- `jc-asset-reference-search` 只消费 `assetId` 与 `searchQuery`，通过 Electron 提供的受控联网和下载工具返回一张参考图的项目相对路径及来源元数据，不得修改资产设计或生图提示词；
- “生成资产图”不执行 Skill，直接把 `generationPrompt` 与可选当前参考图提交给当前固定的 `gpt-image-2` 图像模型；
- `jc-gpt-image` 不再参与道具、场景、角色资产链路；其仍有价值的风格规范归入项目风格库后，资产链路中的历史职责结束；
- App 验证 `design`、`generationPrompt` 和 `searchQuery`，缺字段即失败，不静默降级成短提示词；
- AI 修改根据当前选中资产调用对应专业 Skill，输入当前完整 `design`、当前 `generationPrompt` 与用户意见，输出同一合同。

最终目标形态固定为四个专业 Skill，不再增加第五个通用生图 Skill：

```text
jc-prop-prompt
jc-scene-prompt
jc-character-prompt
jc-asset-reference-search
```

前三个分别负责各自资产的设计与最终生图提示词；第四个供三类资产复用，只负责搜索并下载参考图。图像模型是执行端，不属于上述 Skill 编排。

## 8. 验收标准

1. 确认文稿后，一个“生成资产提示词”按钮生成角色、场景和道具三类完整提示词，并分别调用正确的专业 Skill。
2. 三类资产 Markdown 显示完整设计与生图提示词，结构化结果同时保留在项目状态中。
3. 页面主操作严格只有“生成资产提示词 / 搜索下载参考图 / 生成资产图”三个按钮，资产卡片不再出现上传或确认按钮。
4. “搜索下载参考图”明确通过 `jc-asset-reference-search`，每项只按一个短词组下载一张图并保留来源元数据。
5. 不搜索参考也能直接生成三类资产图。
6. 有上传或联网参考时，生图请求使用当前参考图；没有时走文生图。
7. 搜索失败不改变提示词、不删除已有版本、不阻断直接生图。
8. “生成资产图”直接调用当前图像模型，不调用通用生图 Skill，成功结果自动成为当前版本。
9. 选择任一角色、场景或道具后，右栏文本框只修改该项提示词；输出只在中间栏显示。
10. 三类资产使用同一 UI 和执行节奏，不再保留道具特例。
