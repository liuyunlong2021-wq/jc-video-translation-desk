# TDD-19：剧本角色提取与画面人物绑定

> 状态：待执行  
> 原则：有剧本增强，无剧本不受影响；复用现有字幕角色和配音工作台，不新建工作台。

## 1. 产品结论

在字幕工作台左栏增加一个入口：

```text
提取角色
```

用户可直接粘贴剧本/故事文本，或上传 TXT、MD、SRT、DOCX、PDF 文档后，模型提取项目角色列表。用户可以修改角色名称、别名和身份描述；字幕工作台后续识别出“画面人物 1/2/3”时，系统尝试绑定到剧本角色。

绑定成功后继续使用现有 `translationRoleId`，配音工作台、角色参考音、分组克隆和成片流程全部复用现有逻辑。

没有剧本时：

```text
画面人物识别
-> 画面人物 1/2/3
-> 用户手动修改或绑定
```

现有流程完全不变。

## 2. 唯一用户流程

### 2.1 有剧本

```text
字幕工作台左栏点击“提取角色”
-> 粘贴剧本/故事文本或选择剧本/故事文档
-> 模型提取角色
-> 左栏显示角色列表
-> 用户修改角色名称、别名和身份
-> 获取字幕并自动识别画面人物
-> 系统自动匹配可确定的角色
-> 不确定项由用户手动选择
-> 进入现有配音工作台
```

### 2.2 无剧本

```text
获取字幕
-> 自动识别画面人物
-> 继续使用现有“画面人物 1/2/3”
-> 用户可以手动修改角色名
-> 进入现有配音工作台
```

不因为没有剧本而阻止字幕翻译或配音。

## 3. 字幕工作台 UI

左栏目标语言选择器下方增加：

```text
[提取角色]
```

点击后打开小弹窗，提供两种入口：

```text
粘贴剧本/故事文本
上传文档提取（TXT / MD / SRT / DOCX / PDF）
```

PDF 首版只抽取可复制文字；扫描版 PDF 不做 OCR，提示用户直接粘贴文本。

提取成功后，现有“翻译角色”列表继续显示。每个角色增加一行状态：

```text
林默
已绑定剧本角色
```

或：

```text
画面人物 2
待绑定剧本角色
```

点击角色编辑时，可以：

```text
角色名
别名
身份/职业描述
绑定剧本角色
```

不增加独立“角色工作台”、项目角色页、批量绑定按钮或第二套确认流程。

## 4. 最小数据合同

### 4.1 项目级剧本角色

新增项目共享字段：

```ts
type ScriptCharacter = {
  scriptCharacterId: string
  displayName: string
  aliases: string[]
  description: string
  evidence: string
  sourcePath: string
  order: number
  status: 'draft' | 'confirmed'
}
```

角色列表保存在项目共享状态中，后续集数继续复用。

### 4.2 现有翻译角色增加绑定

```ts
interface TranslationRole {
  translationRoleId: string
  displayName: string
  visualPersonId?: string
  scriptCharacterId?: string
  aliases: string[]
  description?: string
  ...
}
```

`translationRoleId` 不变。绑定只改变角色来源和展示信息，不重建字幕 cue，不重建配音组。

## 5. 自动匹配规则

### 5.1 可以自动绑定

满足以下任一条件且只有一个候选时自动绑定：

1. 字幕或剧本文字出现角色正式名称；
2. 字幕或剧本文字命中唯一别名；
3. 画面人物与台词上下文形成唯一角色证据；
4. 模型返回唯一候选且程序校验角色 ID 有效。

### 5.2 必须人工选择

以下情况不自动绑定：

- 同名角色存在多个候选；
- 只有模糊外观，没有字幕或剧本证据；
- 模型返回多个候选；
- 剧本角色与画面人物数量无法对应；
- 角色身份无法从文档或字幕得到可靠证据。

此时保留现有“画面人物 1/2/3”，显示“待绑定”，不阻止后续操作。

## 6. 排序规则

- 剧本角色：按上传文档中的首次出现顺序；
- 当前集画面人物：按本集首次出现顺序；
- 新上传文档发现的新角色：追加到项目角色列表末尾；
- 不按台词数量、角色重要性或集数重新排序；
- 角色绑定不改变现有 `cueId` 和 `translationRoleId`。

第一集可以直接上传第一集剧本；如果用户拥有整部剧本，优先上传整部剧本建立项目角色库。

## 7. 配音工作台衔接

不新增配音按钮和页面。

现有角色声音提示词生成逻辑直接读取：

```text
角色名
别名
身份/职业描述
整集字幕上下文
```

有剧本时，身份描述作为可靠辅助信息进入现有角色提示词；没有剧本时继续使用画面和字幕推断。

如果用户修改角色绑定、角色名或身份描述，沿用现有失效规则：

```text
角色声音提示词失效
角色参考音确认失效
分组配音版本失效
```

不删除声音库中的历史参考音。

## 8. 文件与模型边界

- 粘贴文本直接进入提取模型，不要求用户先保存成文件；
- 上传文档先保存为当前项目相对路径；
- 上传文档支持 TXT、MD、SRT、DOCX、PDF；PDF 只保证可复制文本抽取；
- 模型只返回结构化角色 JSON，不直接写入角色状态；
- 程序校验角色 ID、名称、别名和顺序后再保存；
- 文档提取失败可重试，不影响现有字幕识别；
- 不把 API Key、完整原始文档或模型请求写入 Wiki；
- 角色证据和来源路径写入项目 Wiki，便于后续复查。

## 9. 明确不做

- 不新建配音工作台；
- 不改变当前字幕识别、OCR、ASR 和翻译链路；
- 不要求用户必须上传剧本；
- 不自动猜测无法证明的角色身份；
- 不做复杂人物关系图；
- 不做跨项目角色库；
- 不做按戏份排序或角色重要性评分；
- 不增加“全部确认角色”按钮；
- 不把“关联配音分组”移动到这里。

## 10. 实施顺序

### 第一阶段：字幕工作台

1. 增加文档上传和角色提取 IPC；
2. 增加项目级 `ScriptCharacter` 持久化；
3. 左栏显示、编辑和删除剧本角色；
4. 增加画面人物到剧本角色的自动匹配和手动选择；
5. 无剧本回归现有流程。

### 第二阶段：配音衔接

1. 让现有角色提示词读取 `description` 和 `aliases`；
2. 验证已有角色参考音和分组克隆无需改 UI；
3. 只补充角色绑定变化后的失效测试。

两阶段不同时重做配音页面，避免把稳定链路和新角色来源绑定在一起修改。

## 11. 测试清单

1. 有效剧本文档能提取角色、别名、描述和首次出现顺序；
2. 空名称、重复角色、未知字段和非法 JSON 被拒绝；
3. 重复上传同一文档不会重复创建角色；
4. 新角色只追加，不改变已有角色顺序；
5. 唯一名称或别名能自动绑定画面人物；
6. 多候选和低证据场景保持未绑定；
7. 手动绑定后 `translationRoleId` 和 `cueId` 不变化；
8. 无剧本时现有画面人物识别和手动改名测试全部通过；
9. 角色身份修改会使现有声音提示词和配音版本失效；
10. 角色参考音、确认、分组克隆和成片门禁继续通过；
11. `pnpm test`；
12. `pnpm exec vue-tsc --noEmit`；
13. `git diff --check`。
